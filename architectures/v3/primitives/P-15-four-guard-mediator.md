# P-15 — Four-guard mediator

Per-primitive Phase-3.5 buildability sketch. ## Contract restatement

The four-guard mediator is the **single substrate surface** through which spec-and-intent inputs pass before a builder agent sees them. It composes four deterministic-where-possible guards into one uniform gate: (1) **GtWR vocabulary lint** — INCOSE R7/R8/R9/R26/R35 catching vague terms, escape clauses, superlatives, temporal vagueness, absolutes; (2) **Contradiction-detector** — multi-judge ensemble flagging Larbi-style ([F37](../failure-modes-v3.md#f37--silent-contradictory-prompt-collapse)) inconsistency; (3) **Requirement-count budgeter** — deterministic counter enforcing the Yang/Llama ≤10–20 simultaneously-specified-requirement ceiling per work-unit class ([F36](../failure-modes-v3.md#f36--instruction-following-ceiling)); (4) **Perimeter typing** — CaMeL-class capability-typed boundary over every tool-call edge a spec-derived plan implies ([F33](../failure-modes-v3.md#f33--adversarial-prompt-defeat-of-llm-based-security-analysis) / [F44](../failure-modes-v3.md#f44--lethal-trifecta-production-scissors-default)). Contract is **composition**: one fail-closed gate, four typed sub-verdicts, one auditable envelope to P-05. The substrate refuses any fifth guard at this surface (Schillace's "just one more patch" anti-pattern per [F52](../failure-modes-v3.md#f52)).

## Construction path per sub-guard

### Guard 1 — GtWR vocabulary lint (engine integration)

P-16 specifies the rule library; the mediator's job is to host the engine and dispatch the rule set. Construction reuses P-12's deterministic-linter framework (ESLint-style `Linter` over a `tree-sitter`-parsed spec AST). **Integration sentence:** the mediator instantiates a P-12 `Linter` with the P-16 rule pack loaded at startup, calls `Linter.verify(specText, ruleSet)` on every incoming intent block, and translates each emitted `{rule-id, severity, location, message}` violation into the mediator's typed verdict envelope under `guard=gtwr-lint`. Threshold gating (configurable per work-unit class) lives in the mediator, not the engine — the engine is pure detection, the mediator is decision.

### Guard 2 — Contradiction-detector (multi-model judge ensemble)

The registry pre-tags this sub-guard as the load-bearing reason P-15 is `designed-system`: [F37 / Larbi MCC ≤ 0.55](../failure-modes-v3.md#f37--silent-contradictory-prompt-collapse) is a hard ceiling on LLM-as-judge contradiction detection. The mitigation is **ensemble agreement across provider families**, not a stronger single judge. **Construction:** LiteLLM (proxy router for cross-provider dispatch) hosts a 3-of-N ensemble in which each judge call is routed to a *different model family* (e.g., one Anthropic, one OpenAI, one Google / open-weight). **Integration sentence:** the mediator constructs the contradiction-detection call as a LiteLLM `acompletion` fanout against a model-family-diverse pool (provider rotation enforced by config; same-family responses rejected at routing time), uses a fixed CoT-prompt asking each judge for `{contradiction: bool, evidence: span[]}` per requirement pair, and emits a `guard=contradiction` PASS only when ≥3 of N (default N=5) family-distinct judges concur on contradiction-free; otherwise FAIL with the spans attached. The ensemble is the same shape as P-14 (judge router) configured for the contradiction-detection role — composition, not a new primitive.

### Guard 3 — Requirement-count budgeter (deterministic)

A pure-counting pass over the parsed spec AST: count distinct "shall"-statements (EARS-form requirements) plus distinct acceptance criteria, compare against a per-work-unit-class threshold (default 10; configurable up to ~20 per Yang's empirical envelope). **Construction:** same P-12 engine as guard 1, with a tree-sitter visitor that increments a counter on each `RequirementStatement` node. **Integration sentence:** the mediator runs a P-12 rule named `req-count-budget` that walks the parsed spec, sums recognised requirement-bearing nodes per scope, compares against the class-specific budget (looked up from the cycle manifest), and emits a `guard=req-count` FAIL with mandatory `chunk-into: N` advice when over budget. Determinism is total — no LLM call — so this guard's verdict is reproducible bit-for-bit on the same spec.

### Guard 4 — Perimeter typing (CaMeL-class)

Overlaps with P-25 (the standalone CaMeL-typed-perimeter primitive); the mediator-side integration is to *invoke* the perimeter typer on spec-derived plan fragments, not to re-implement it. **Construction:** wrap the CaMeL reference interpreter (Anthropic's [CaMeL paper](../../../research/followup/08-security-primitives.md) NORMAL/STRICT modes) or an equivalent typed-interpreter shim. **Integration sentence:** for every tool-call edge the spec implies (parsed out of EARS triggers + acceptance scenarios), the mediator calls `CaMeL.typeCheck(edge, currentCapabilityProfile)` and treats any capability mismatch as a `guard=perimeter-typing` FAIL with the offending edge and the missing capability named; in mediator terms this is a static-typing pre-check that the runtime perimeter (P-25 proper) will re-enforce dynamically. The mediator side is the **declaration-time check**; P-25 is the **call-time check**. Both are required for defence-in-depth against [F12 / F33 / F44 cascade](../failure-modes-v3.md#f12--lethal-trifecta--prompt-injection).

## Cross-guard composition

The mediator presents the four sub-verdicts as a **single fail-closed gate decision** with an attached typed envelope `{gtwr: {pass, violations}, contradiction: {pass, spans, ensemble-vote}, req-count: {pass, count, budget}, perimeter: {pass, edges, missing-caps}}`. The gate composition rule is **AND across guards** by default — any sub-guard FAIL fails the gate — with two refinements: (a) the GtWR lint has a per-severity threshold (e.g., R9 vague-term hits below threshold N degrade to warning, not FAIL — configurable), and (b) the contradiction-detector emits a *three-valued* sub-verdict (PASS / FAIL / UNDETERMINED when ensemble agreement is below quorum), and the mediator's composition treats UNDETERMINED as FAIL by default but allows the cycle manifest to escalate UNDETERMINED to a Patrol-tier review event (per [GF-S §1.S5](../tracks/greenfield-substrate-first.md#15s5--watchdog-tiers-daemon--triage--patrol-substrateresident-required-for-lightsout)) rather than hard-failing. The composed envelope writes to P-05 trajectory before the gate decision is returned to the caller — even a PASS is auditable.

On **partial failures** (e.g., guards 1 / 3 / 4 pass, guard 2 returns UNDETERMINED), the mediator returns the typed envelope with the partial-pass detail rather than a single bit; the upstream cycle driver can choose to escalate to Patrol or to re-author. The four-guards-full-stop discipline ([F52](../failure-modes-v3.md#f52)) lives at the *mediator-design* level — no fifth guard is admitted at this surface — but the cycle driver above the mediator may chain additional methodology-layer checks.

## Research-grade-uncertainty flag

**`partial — guard 2 only`.** The contradiction-detector's reliability under N=3 / N=5 family-diverse ensembles is **open**. Larbi's MCC ≤ 0.55 ceiling is named for *single-judge* detection; whether 3-of-N family-diverse agreement raises effective MCC into a defensible band is an *empirical* question the corpus does not answer. The standing risk: ensembles drawn from shared pre-training distributions exhibit [F27 / F48 (tacit collusion via shared context)](../failure-modes-v3.md#f48--tacit-collusion-via-shared-context), so even cross-family agreement may not be independent. Mitigation hooks (paraphrase divergence per P-21; opposing-side router per P-33) exist but are not load-bearing inside the mediator. Guards 1, 3, 4 are not research-grade — they are commodity or designed-system integrations with named prior art.

## Buildability verdict

**`designed-system`.** Three of the four sub-guards (GtWR lint, req-count budgeter, perimeter typing) are designed-system integrations over commodity engines (P-12 framework, CaMeL reference impl, LiteLLM router) with named prior art and uncontroversial construction. Guard 2 (contradiction-detector ensemble) carries a research-grade-uncertainty sub-flag noted above, but the *mediator's composition* of it — fail-closed-by-default with optional UNDETERMINED-to-Patrol escalation — is a designed-system integration, not a research-grade primitive in its own right. The whole-mediator verdict is `designed-system`; the explicit caveat on guard 2's empirical reliability is recorded as a standing open question this sketch surfaces for Phase-4 / Phase-8 lean-eval pressure-testing.
