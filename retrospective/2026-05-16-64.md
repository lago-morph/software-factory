## Part 1 — what happened

### Phase 1 — Preliminary indexing pass for ~71 manual sources (PR #61)

The user dropped 71 new sources into `research/manual/` (61 `.mhtml`, 9 `.txt`, 1 `.pdf`) and asked for a **preliminary index pass** — explicitly NOT a drain, and explicitly leaving `PLAN.md` untouched. The deliverable was a single `new-index.md` cataloging every source with title, reconstructed URL, summary, image-usefulness verdict, prior-processing check, and an incorporate/new-report/skip recommendation. Sources without informative images were to be converted to `.txt`; previously-processed sources were to be deleted. The user articulated seven thematic motivations for the batch (after I caught a double-5 numbering bug in their original prose) and asked me to capture them so the next agent could plan ingestion.

Planned approach: write an MHTML extractor, pre-build a metadata manifest, group sources into ~21 batches by topical cluster, dispatch parallel subagents with a shared on-disk brief. Each subagent would handle 2–5 files, do image triage by extracting and viewing the top-3-by-size embedded images, and return a structured markdown stream that I'd concatenate into the final index.

What actually happened: the plan worked, but with caveats. **Sixteen of twenty-one subagents returned synchronously** (presumably hitting an in-flight subagent cap); the remaining five went into background dispatch and trickled in over ~5 minutes. Several subagents flagged previously-processed files but did not actually `rm` them — I had to do a manual cleanup pass for three duplicates (Klaassen × 2, Shapiro × 1). One subagent's textual `Action taken` field said "kept as txt (passthrough)" for files that started as `.mhtml` — the filesystem actions were correct (the conversion happened) but the prose was misleading. The stop-hook fired mid-session demanding I commit; I made a WIP commit + push, then continued waiting for the last agent.

The end result was a 864-line `new-index.md` with: a 7-theme framing block, a roll-up table, 13 proposed new reports, 8 existing-report primary-source upgrades (notably three Cloudflare-blocked OpenAI URLs now drainable), 24 deletions of already-drained duplicates, and 15 source clusters with per-file blocks. After the user requested a test-merge of main to bring in PLAN.md v0.13, I verified the branch had no commits touching PLAN.md (clean merge guaranteed), merged, and shipped PR #61. It was merged the same hour.

### Phase 2 — Skill self-ownership of the script (PR #64)

The user observed that the MHTML extractor (`scripts/mhtml_extract.py`) should live inside the `research-pipeline` skill rather than at the repo root, since it's purpose-built for one skill's workflow. I:

1. Moved `scripts/mhtml_extract.py` → `.claude/skills/research-pipeline/scripts/mhtml_extract.py` and removed the empty top-level `scripts/` directory.
2. Added a filesystem-table row in `SKILL.md` documenting the script's four commands (`info` / `text` / `save-image` / `to-txt`).
3. Extended the Phase 0 `find` inventory to include `*.mhtml` (previously would have silently skipped the format the user actually uses for Save Page As).
4. Added an **MHTML caveat** in Phase 7 alongside the existing PDF caveat, with the image-triage rule of thumb that was empirically validated during Phase 1.
5. Fixed the stale path reference in `research/manual/new-index.md`.

PR #64 merged shortly after.

## Part 4 — proposed ADRs

Architectural decisions made or implied during this session that the user may want to record formally. **Titles only — no specs.** Use the `adr` skill if you want to author any of them.

- **Scripts that support one skill live under `.claude/skills/<skill>/scripts/`** — convention established by PR #64's move; previously ambiguous whether top-level `scripts/` or skill-local was canonical. Worth nailing down before more scripts proliferate.
- **`research/manual/` accepts an optional preliminary index-pass before a drain** — workflow contract distinguishing index-pass (this session, PR #61) from Phase 0 drain (`research-pipeline`). Surfaces when to invoke which.
- **Cohort subagent dispatch uses a shared on-disk brief file** — pattern validated in PR #61 (21 subagents Read `research/manual/.subagent-brief.md`); saves significant prompt tokens vs. duplicating instructions inline. Could be recorded as a `parallel-subagent-fanout` convention.
- **Stop-hook compliance via WIP commits is acceptable mid-task** — a forced commit doesn't have to be the final commit; intermediate WIP commits with clear "WIP" subject lines are an acceptable way to satisfy the hook without abandoning the task. Worth recording so future agents don't feel pressured to abandon work.
