# ADR 0058: U-C P-19 variant — distance-tuple feature source

- **Status**: Accepted
- **Date**: 2026-05-25
- **Deciders**: Wave 5.3c2 subagent

## Context

[ADR 0028](0028-p-19-eligibility-regime-classifier.md) records the **common P-19 framework** — decision-table engine (Drools or OPA Rego) + LLM-judge fallback via [P-14](0016-p-14-judge-router.md) + OPA hard-floor post-check — shared across four contested variants (GF-S work-unit-class, BF-L per-region, U-A interval-kind, U-C distance-gated). It explicitly defers per-variant feature-source and output-regime decisions to four Wave-5.3 ADRs; this ADR is the U-C one. Sibling deliverable [ADR 0057](0057-p-32-distance-estimator.md) records U-C's P-32 distance estimator, which produces the DistanceTuple this classifier reads.

The [Phase-4.2 overlap.md verdict on P-19](../../architectures/v3/primitives/overlap.md#p-19-eligibility--regime-classifier--four-contested-variants) is verbatim: **"SAME primitive (P-19 classifier framework), DISTINCT feature sources + distinct output regime sets. All four share the construction recipe (Drools/OPA Rego decision tables + LLM-judge fallback via P-14 + OPA hard-floor post-check per [P-19 sketch](../../architectures/v3/primitives/P-19-eligibility-regime-classifier.md)). The differences are at the *feature engineering* layer and the *output enum* layer, not the *decision-engine* layer."** The overlap.md table row for U-C specifies the feature source as **"P-32 DistanceTuple (graph_distance, pace_layer_crossings, intent_field_touches) + contradiction_flag hard-floor"** and the output as **"`lights-out / cross-model-judging / human-required`."**

[U-C's substrate-requirements summary §3 P-19 contract](../../architectures/v3/substrate-requirements/u-c.md) is explicit that U-C calls this primitive a *dispatcher* rather than a *classifier* because P-32 has already done the feature engineering; the dispatcher's job is threshold logic on the composite `w_g · graph_distance + w_p · pace_layer_crossings + w_i · intent_field_touches` plus a single hard floor — `contradiction_flag = true ⇒ human-required` regardless of composite (the F37 silent-contradictory-prompt catch). Distinct from GF-S/S9 (work-unit-class features inferred from intent-block diff), BF-L (code-region features from [P-26](0047-p-26-codebase-model.md)), and U-A (envelope-kind features at interval open) — those classify by what a cycle declares or what code-region it touches; U-C classifies by *how far the cycle's target sits from a frozen anchor*.

Decision-engine, fallback, and hard-floor disciplines are inherited unchanged from [ADR 0028](0028-p-19-eligibility-regime-classifier.md); this ADR specifies what plugs into them.

## Decision

**Build U-C's P-19 instantiation as a distance-tuple feature-reader that consumes the [ADR 0057](0057-p-32-distance-estimator.md) P-32 DistanceTuple plus the [ADR 0014 P-07 telemetry](0014-p-07-telemetry-ingestor.md) `contradiction_flag`, and emits a `{lights-out, cross-model-judging, human-required}` regime label into the [ADR 0028](0028-p-19-eligibility-regime-classifier.md) decision engine.**

Three components:

1. **DistanceTuple feature reader.** At dispatch time the dispatcher reads `(graph_distance, pace_layer_crossings, intent_field_touches)` from the [ADR 0057](0057-p-32-distance-estimator.md) P-32 estimator's output envelope on the cycle's target work-unit, plus the `contradiction_flag` lifted from [ADR 0014 P-07 telemetry](0014-p-07-telemetry-ingestor.md) for the same cycle. No additional feature engineering: P-32 has already produced the structural / pace-layer / semantic-touch decomposition, and P-07 has already emitted the contradiction signal. The feature vector is `{graph_distance, pace_layer_crossings, intent_field_touches, contradiction_flag}` — strictly four named features, schema-checked at every call.

2. **Decision-table classification.** The feature vector is evaluated by the ADR 0028 decision-table engine (OPA Rego preferred so the thresholds live next to U-C's anchor `mutation-protocol` policy bundles) computing `composite = w_g · graph_distance + w_p · pace_layer_crossings + w_i · intent_field_touches` against versioned thresholds `τ_low` and `τ_high`, emitting regime ∈ {`lights-out` (near-anchor: `composite ≤ τ_low`), `cross-model-judging` (mid-distance: `τ_low < composite ≤ τ_high`), `human-required` (far-anchor or anchor-edit: `composite > τ_high`)}. The weight tuple `(w_g, w_p, w_i)` and the threshold pair `(τ_low, τ_high)` are exposed as versioned substrate parameters per [u-c.md §2 calibration partial-RG](../../architectures/v3/substrate-requirements/u-c.md) so Phase-8 sweeps remain tractable.

3. **Contradiction-flag hard floor (OPA post-check).** Per ADR 0028's F57 hard-floor discipline: `contradiction_flag = true ⇒ regime = human-required, full stop`, regardless of composite — this is the F37 silent-contradictory-prompt catch and supersedes any rule-engine or LLM-judge output. Additional inherited floors: cold-start cycle count `< N ⇒ augmentation-required` per F25; any `kind = anchor-edit` target ⇒ `human-required` per [u-c.md §3 anchor mutation queue](../../architectures/v3/substrate-requirements/u-c.md); LLM-judge fallback on the `unknown` bucket is bound by the same floors.

The output regime is written to the cycle's [P-05](0012-p-05-trajectory-capture.md) trajectory event alongside the DistanceTuple itself (per [u-c.md §1 distance-keyed P-05 variant](../../architectures/v3/substrate-requirements/u-c.md)) so Patrol can monitor regime-distribution drift and DistanceTuple-distribution drift jointly — closing the F47 Goodhart concern on the `intent_field_touches` leg with a P-06 residual detector rather than at the dispatcher.

## Alternatives considered

**B. Work-unit-class feature source (GF-S's variant).** *Why rejected:* per the [overlap.md table](../../architectures/v3/primitives/overlap.md#p-19-eligibility--regime-classifier--four-contested-variants), work-unit-class is GF-S/S9's distinct shape — features derived from intent-block-fields-touched, declared stakes, and scenario-set saturation. U-C's load-bearing claim is that **anchor-distance is the substrate's first-class scalar** ([u-c.md §6](../../architectures/v3/substrate-requirements/u-c.md)); routing on work-unit-class would erase that thesis and demote P-32 from a substrate primitive to incidental telemetry. Work-unit-class features also presuppose intent-block typing that U-C does not stand up as a substrate primitive — U-C's anchor catalog carries `kind ∈ {intent-invariant, architecture-rule, standards-rule, live-test, runtime-trace}`, not GF-S's work-unit taxonomy.

**C. Per-region feature source (BF-L's variant).** *Why rejected:* per the [overlap.md table](../../architectures/v3/primitives/overlap.md#p-19-eligibility--regime-classifier--four-contested-variants), per-region is BF-L's distinct shape, grounded in [P-26 Codebase Model](0047-p-26-codebase-model.md) code-region indexing. U-C only depends on the *structural view portion* of P-26 (P-22 + P-23) for `graph_distance` computation per [u-c.md §4 X_UNM_B articulation](../../architectures/v3/substrate-requirements/u-c.md); it does not stand up the conventional / invariant views per-region classification needs. Importing per-region would also collapse U-C's distance-axis into BF-L's region-axis, forfeiting the distance-from-anchor regime stratification that motivates U-C's existence as a separate candidate.

## Consequences

**Easier:** U-C's dispatcher discipline lands on the same DistanceTuple every other U-C substrate primitive reads, so cross-primitive consistency is a typing property of the tuple rather than a coordination promise. The `contradiction_flag` hard floor is substrate-enforced via P-07 telemetry, not a methodology promise. F57 drift is monitorable at the composite-distribution layer: Patrol can diff regime distributions per anchor-kind slice. Phase-8 calibration sweeps on `(w_g, w_p, w_i, τ_low, τ_high)` are tractable because the parameters are versioned configuration per [u-c.md §2](../../architectures/v3/substrate-requirements/u-c.md).

**Harder:** The dispatcher is now tightly coupled to ADR 0057 (P-32) and ADR 0014 (P-07) — the DistanceTuple schema and contradiction-flag emission contract are both load-bearing for dispatcher behaviour, and a P-32 calibration change ripples into regime-distribution shifts that Patrol must distinguish from genuine F57 drift. The `intent_field_touches` leg's F33/F51 vulnerability ([u-c.md §2 Goodhart-resistance partial-RG](../../architectures/v3/substrate-requirements/u-c.md)) propagates into the dispatcher's regime output; the P-06 residual detector spec (Phase-5 ADR seed (ii) per [u-c.md §5](../../architectures/v3/substrate-requirements/u-c.md)) is required to close F47. Operator-legibility of the DistanceTuple at dispatch ([unified-C §7 OQ #5](../../architectures/v3/tracks/unified-C.md)) — the biggest single open question — falls on the dispatcher's UI surface, not on P-32.
