# P-19 — Eligibility / regime classifier

**Dispatch tier.** per-primitive (designed-system).
**Claimed by.** [GF-S/S9](../tracks/greenfield-substrate-first.md#1s9--eligibility-classifier-regime-naming-substrate-primitive), [BF-L per-region regime classifier](../tracks/brownfield-legacy-ingestion-first.md), [U-C distance-gated dispatcher (related variant)](../tracks/unified-C.md).

## Contract restatement

The eligibility / regime classifier is a substrate primitive that takes a typed input descriptor for a unit of intended work (work-unit metadata in GF-S; a code region tagged by the Codebase Model in BF-L; a distance-to-anchor tuple in U-C) plus the current substrate context (configured thresholds, recent watchdog signal, current bar-set parameters) and emits a **regime label** drawn from a small, deployment-declared label set — canonically `automation-eligible` / `augmentation-required` / `escalate` in GF-S, or a regime per the candidate's vocabulary — together with a **confidence / rationale envelope** and the **decision handles** the cycle dispatcher needs (which gate set to apply, which capability profile to open the sandbox under, which judge-diversity policy to require). The substrate **enforces** the regime: an `augmentation-required` unit cannot bypass the human-review gate; an `automation-eligible` unit cannot synchronously summon a human (escalation is via Patrol). The classifier's parameters are stored as versioned configuration, every classification is a typed event written to the trajectory store, and the classifier's own output distribution is watchdog-monitored for drift (F47 / F57).

## Construction path

**Primary path: feature-engineered classifier on named inputs, expressed as a Drools / OPA Rego decision table over typed features, with optional scikit-learn random-forest scoring per feature group.** The substrate's feature extractor produces a fixed-schema feature vector per input (named features only — no embedding bag); the Drools rule engine (or OPA's Rego when policy-as-data hosting is desired so the parameters live next to the other policy mediators in P-29) evaluates declarative thresholds against the features and emits the regime label deterministically. **Integration sentence.** Drools' decision tables let the substrate store the regime cut-points as a versioned spreadsheet (e.g., `coverage ≥ 0.85 AND churn_30d < τ_churn AND caremark_tag = none → automation-eligible`) which Patrol can diff across versions to log drift as F57-typed events — this is the mechanical realisation of GF-S/S9's "substrate-stores-the-classifier's-parameters-as-versioned-configuration" requirement. Where soft scoring is wanted on a feature group, a scikit-learn `RandomForestClassifier` with `feature_names_in_` checked at every call and Platt-calibrated probabilities (`CalibratedClassifierCV`) provides the score, which the Rego layer then thresholds — keeping the cut-points themselves declarative and auditable.

**Alternative path: LLM judge (Claude / GPT) called via P-14 (judge router) with a JSON-Schema-typed regime envelope, gated by OPA on top for a deterministic post-check.** The judge call uses `same-model-different-role` or `cross-family` per the deployment's judge-diversity policy, returns `{regime, rationale, confidence, named_drivers[]}` against a Pydantic schema, and OPA enforces deterministic invariants the judge cannot violate (e.g., "if `caremark_tag != none` then regime ≠ automation-eligible", "if cold-start cycle count < N then default to augmentation-required per F25"). **Integration sentence.** The LLM judge handles the *naturalistic* parts of regime fit (idiomatic-debt classification in brownfield, intent-block-touch ambiguity in greenfield) where rule-engineering is brittle, while the OPA wrapper guarantees the hard floors hold regardless of judge output — pairing the F25 (design starvation) cold-start protection and F57 (design-authority erosion) policy floors as substrate invariants rather than judge promises.

**Hybrid is plausible and probably correct:** rules / random forest for the high-confidence cases; LLM judge as the fallback for the rule-engine's `unknown` bucket; OPA post-check binding both.

## Per-candidate notes (no same-vs-distinct verdicts)

- **GF-S / S9.** Input is **work-unit class features** (intent-block-fields-touched, declared stakes, scenario-set saturation per work-unit-class, recent cross-family judge agreement on the class). Output regime set: `automation-eligible` / `augmentation-required` / `escalate`. Day-0 default is `augmentation-required` for *all* work units (substrate refuses to lights-out a cold-start factory) per the F25 design-starvation mitigation in [§5.S9 cold-start bootstrap](../tracks/greenfield-substrate-first.md). Classifier output drives sandbox capability profile (S1) and gate-set selection. ([greenfield-substrate-first §1.S9](../tracks/greenfield-substrate-first.md#1s9--eligibility-classifier-regime-naming-substrate-primitive))
- **BF-L per-region.** Input is **code-region features pulled from the Codebase Model** (P-26): test-coverage density, runtime-telemetry density, historical churn cadence, Caremark/RSI exposure tag, debt-cluster membership, conventional-view idiom-conformance score. Output regime is *per region*, not per cycle — a single cycle can touch multiple regions and inherit the strictest classification. Per-region classification is the load-bearing answer to BF-L's CTR-A4 lights-out / L5 mapping question. ([brownfield-legacy-ingestion-first §2.1 + §2.5](../tracks/brownfield-legacy-ingestion-first.md))
- **U-C distance-gated dispatcher (related variant).** Input is the **distance tuple** (graph distance to intent invariant, blast radius × test-coverage gap, pace-layer crossing count) produced by P-32. Regime set: lights-out / cross-model-judging / human-required, gated by `d ≤ τ_low` / `τ_low < d ≤ τ_high` / `d > τ_high`. The "classifier" is mostly a thresholded decision table on the distance tuple plus the Goodhart-monitoring Patrol check ([unified-C §F47](../tracks/unified-C.md)). U-C names this *dispatcher* rather than *classifier* because the distance tuple has already done the feature engineering. ([unified-C §3 + §6](../tracks/unified-C.md))

## Research-grade-uncertainty flag

**Carried, partial.** The registry note for P-19 reads "classifier may itself be LLM judge — open"; GF-S §8 OQ #3 sharpens this: *"is S9 itself an LLM-judge primitive — and if so, does the F51 Ashby-deficient probabilistic guard critique recurse into the substrate's own self-classification?"* ([greenfield-substrate-first §8 OQ-3](../tracks/greenfield-substrate-first.md)). The construction-path question (can the thing be built?) is not research-grade — both the rule-engine path and the LLM-judge path are buildable today. What is open is whether the substrate is allowed to rest its regime-classification on an LLM judge when F51 says probabilistic guards are Ashby-deficient at high-stakes intervals. The hybrid path (rules + LLM fallback + OPA post-check) is the lead-agent's best current answer; whether it survives the F51 recursion is a Phase-4.2 / Phase-8 question, not a Phase-3.5 buildability question.

## Buildability verdict

**`designed-system`.** Both construction paths use commodity ingredients (Drools / OPA / scikit-learn for the rule path; P-14 + Pydantic + OPA for the LLM-judge path). The designed-system content is the **feature schema per candidate's input variety**, the **regime label set + capability-profile mapping**, the **OPA-enforced hard floors** (F25 cold-start default, F57 caremark-tag floor, F43 RSI-tag floor), and the **classifier-output-distribution Patrol integration** that turns F57 drift into a typed event. Research-grade-uncertainty flag carried per above but does not block buildability.
