# Component Inventory B — behavior & dataflow decomposition of v4

**Cartographer B lens**: flows, lifecycles, control/feedback loops, responsibilities, inputs→outputs, state transitions, invariants.

**What v4 is (dataflow/lifecycle viewpoint)**: v4 is a *principle-bound runtime substrate* through which a human-authored **spec** flows into running software, while a parallel held-out **scenario/judge** stream measures satisfaction, an **observability→anomaly→diagnosis→fix** loop closes on failures, and a **self-optimization** loop tunes the runtime's own meta-performance — all built on Gas City + Claude Code, extended via packs, with a *recursive bootstrap* where the factory builds its own next components. The load-bearing transform is "specs in → satisfying software out, with every action attributed and every failure routed back as a new bead."
