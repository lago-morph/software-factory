# agent instruction

**Self-installing pattern for cross-tree artifacts.** Any skill that writes files outside its own directory — hooks, GitHub workflows, `.claude/settings.json` entries, configs, anything the consumer repo needs installed — must ship a `scripts/install.py` with `--check` / `--force` / `--dry-run` modes and a "STOP — run the pre-flight" stanza at the top of its `SKILL.md`. The pre-flight stanza branches on the install script's exit code (0 = clean, 1 = drift / missing → run `--force` with no user prompt, 2 = skill-install defect → surface and stop). Do not rely on user memory to install; do not rely on a one-time setup step; do not author the cross-tree artifact by hand-edit. Reference implementations: `architecture-failure-mode-gate` (workflows), `issue-management` (hook + settings.json), `research-pipeline` (workflows).

*Grounded in: PR #117, where the issue-management PreToolUse gate became a self-installing skill — install.py + a pre-flight that runs every load and auto-repairs drift — to avoid the "skill says you must install the hook" / "user forgets to install the hook" loop.*

# justification

PR #117 added a PreToolUse hook that blocks `mcp__github__issue_*` calls unless the `issue-management` skill has been loaded. The hook script + the `.claude/settings.json` entry live outside the skill directory. Without the self-install pattern, this would mean: "Open the skill. Read the instruction. Copy the file to the right place. Edit settings.json. Hope nobody forgot." That's exactly the manual setup step that gets skipped after a few months, and the gate silently stops protecting anything.

The pattern that works — copied from `architecture-failure-mode-gate` and `research-pipeline`'s workflow installers — has three parts: (a) the skill's `SKILL.md` opens with a "STOP — run the pre-flight" stanza naming `install.py --check`, (b) the agent runs `--force` immediately and with no user prompt on a non-zero exit, (c) the installer auto-commits the cross-tree artifacts so they land in the same PR as the skill change. The marginal cost of the pattern is one Python script and ~20 lines of `SKILL.md`. The cost of skipping it is silent drift between what the skill says is true ("there's a gate") and what's installed in the consumer repo ("there isn't"). Issue #118 generalizes this same pattern to `always-commit-skill-to-repo` and `in-flight-workflow-tracking`; the rule preempts future skills from re-discovering the same shape.
