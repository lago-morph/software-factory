## Tools you'll use

- `python3 /home/user/software-factory/scripts/mhtml_extract.py info <file.mhtml>` → JSON: title, snapshot_url, main_url, image list (with size/url/content-type), text head, text length.
- `python3 .../mhtml_extract.py text <file.mhtml>` → full plain text to stdout (pipe to `head -c 4000` for a sample).
- `python3 .../mhtml_extract.py save-image <file.mhtml> <idx> <out.png>` → extract Nth image (0-indexed within the image list) so you can `Read` it.
- `python3 .../mhtml_extract.py to-txt <file.mhtml> <out.txt>` → write plain-text version (with TITLE / URL header).

- For the `.pdf`: `Read` directly (the Read tool supports PDFs).

## Process per file

### 1. Get metadata
- `.mhtml`: run `mhtml_extract.py info` and capture title / URL / image inventory.
- `.txt`: `Read` it; pull title from filename + first lines; "URL" is N/A unless one is in the body.
- `.pdf` (Neves-Bussmann.pdf): `Read` first pages; extract title and any source DOI/URL.

### 2. Summarize (1–2 sentences)
Read first ~4000 chars of body (`mhtml_extract.py text … | head -c 4000`) and write a concise content-bearing summary. Not "this is an article about X" — instead state the core claim or content.

### 3. Image triage (mhtml only)
Skip an image if **any** of:
- Size < 30 000 bytes
- URL contains: `avatar`, `profile`, `logo`, `icon`, `favicon`, `emoji`, `sprite`, `gravatar`, `og-image`, `social`
- Content-type is `image/svg+xml` AND size < 100 KB (decorative svg)

From the remaining candidates, pick at most the **3 largest** by `size`. Save each to `/tmp/<basename>_img<idx>.png` (preserve extension by content-type) and `Read` them. Judge:

- **USEFUL**: diagrams, architecture, flowcharts, tables of data, code-on-screen with substantive content, charts, model output examples, eval graphs, dotfile graph renders.
- **NOT USEFUL**: headshots, author photos, generic stock photos, UI screenshots that just show "here's the product chrome", logos, decorative illustrations, social-share cards.

If **at least one** image is useful, the file has useful images.

### 4. Prior-processing check
The repo has 27 numbered reports (`research/00-*.md` … `research/26-*.md`) and 12 followups (`research/followup/01-*.md` … `12-*.md`). Some manual sources may already be cited there.

Run:
```bash
grep -lF "<URL>" research/*.md research/followup/*.md 2>/dev/null
```
and also grep a distinctive 5–7-word title fragment. If the URL appears in a sources table or is cited as a primary anchor, mark **previously processed**. If only mentioned in passing without being a primary source, mark **referenced but not drained**.

Skim `research/INDEX.md` to map slug → topic when reporting.

### 5. Disposition

- **Previously processed** → `rm <file>`. Action = `"deleted (already drained into report NN)"`.
- **Has useful images** AND not previously processed → keep the `.mhtml` as-is. Action = `"kept mhtml (useful images preserved)"`.
- **No useful images** AND not previously processed → run `to-txt` to write `research/manual/<basename>.txt`, then `rm` the `.mhtml`. Action = `"converted to TXT, deleted mhtml"`. NOTE: there is one filename collision risk — if the basename already exists as a `.txt`, append `-mhtml` before `.txt`.
- For `.txt` and `.pdf` files: no conversion needed; just classify previously-processed or not (and delete if so).

### 6. Theme + recommendation

Map the source to 1–3 themes (1–7).

Recommendation must be one of:
- `incorporate into report NN-<slug> as <one-line angle>` — existing report needs an extension
- `supplement to followup/NN-<slug>` — existing followup
- `new report — <slug-suggestion> — <one-line angle>` — none of the existing reports fit
- `skip — already covered in report NN` (use when previously processed)
- `low-priority — <reason>` (e.g., the LukePM blog is shallow, mainly definitional)
