# P-14 — Judge router (multi-shape typed)

**Dispatch tier.** per-primitive (designed-system).
**Claimed by.** [GF-S/S6](../tracks/greenfield-substrate-first.md#1s6--judge-routing-multi-shape-model-family-tagged-substrate-typed), [BF-M cross-family routing (Stage 6 / F46)](../tracks/brownfield-methodology-first.md), [U-A judge router](../tracks/unified-A.md), [U-B per-layer judge routing](../tracks/unified-B.md).

## Contract restatement

The judge router is a substrate primitive that exposes a single typed `judge(...)` call surface, parameterised by **(a) judge-shape tag** — `same-model-different-task` / `same-model-different-role` / `cross-model-different-task` / `cross-family`; **(b) model-family taxonomy** carried by the substrate (Anthropic / OpenAI / Google / open-weights are canonical families, not models); **(c) content-addressed prompt-template ID**; **(d) typed input shape** for the judged artifact (spec / diff / scenario verdict / contradiction-detection input); **(e) typed output shape** (Pydantic-style / JSON-Schema-typed envelope: verdict + structured rationale + confidence + handles). The router's **partition discipline**: it refuses calls whose declared shape mismatches the prompt-template's registered I/O signature, refuses cross-family calls when the registry has no live provider in a required-distinct family, and refuses to log a verdict back to a cycle without the holdout-criterion handle that resolves the judged artifact's training/holdout status. The router does not pick a shape; methodology does. The router types the choice, logs it immutably, and enforces the typing.

## Construction path

**Primary tool: LiteLLM proxy (open-source) as the provider-abstraction substrate, with Pydantic models per judge role as the typed-shape layer.** LiteLLM exposes a unified OpenAI-compatible chat-completions endpoint with `model_list` config keying provider routes and `model_group_alias` rules for family-level routing; the substrate carries a `judge_shape -> model_group` mapping (e.g., `cross-family -> [anthropic-claude, openai-gpt, google-gemini]`) and uses LiteLLM's `fallbacks` / `routing_strategy: cost-based-routing-with-tags` features to enforce *distinct-family-required* policies (the router rejects a fallback that would land back inside the originating family). Typed shapes are enforced by Pydantic `BaseModel` subclasses registered per judge role, validated against the template's declared I/O signature on every call; LiteLLM's `response_format={"type": "json_schema", "json_schema": ...}` parameter passes the typed-output contract through to provider-native structured-output features (OpenAI/Anthropic/Gemini all expose this). **Integration sentence:** LiteLLM's `Router` class plus `model_group_alias` + tag-routing realises the family-diversity policy mechanically — the substrate stores `required_families: {distinct: ["anthropic", "openai"]}` per judge-shape and LiteLLM's tag-matching refuses to route to a model whose `tags` overlap the originating call's family tag, which is exactly the F46 mechanism the contract requires.

**Alternative tool: OpenRouter unified API as a managed-SaaS substitute** for the same shape: OpenRouter's `provider.allow_fallbacks=false` plus `provider.order=[anthropic, openai, google]` and per-request `models` arrays let the substrate declare "this judge call must succeed *only* on a non-originating-family provider"; structured outputs are handled per-provider through the same JSON-Schema response-format machinery, with Pydantic validation on the substrate side. Integration sentence: OpenRouter's per-request `provider` block is the policy-enforcement surface; the substrate maps `judge_shape -> provider block`.

**Prior art reference.** Anthropic + OpenAI + Google native SDKs composed behind a typed dispatcher is the build pattern described in [report 34 §6.2](../../../research/34-lenny-howiai-personal-harnesses.md) (CJ Hess `kevin`/`carl`) and [report 23 §3.5](../../../research/23-anthropic-engineering-trilogy.md) (Anthropic Auto-Review subagent); both are corpus precedents that someone has built something in this shape.

## Corpus-why citation

The load-bearing corpus problem is **[F46 — Single-Model Review Blindspot](../failure-modes-v3.md#f46--single-model-review-blindspot)**: same-model self-review samples the same distribution as the original and correlated blind spots survive (greenfield severity **high**, brownfield severity **high**). The router is the substrate's typed control surface against the F1 / F27 / F46 / F48 correlated-error cluster ([failure-modes-v3.md §"F1 / F27 / F46 / F48 cascade"](../failure-modes-v3.md)). Secondary: the router resolves [CTR-C4](../contradictions.md) (RouterLLM unification vs Attractor "do not unify" per-provider) by typing the choice rather than picking a side — intra-family routing is a configuration of the primitive; cross-family is a mandatory policy at high-stakes intervals.

## Research-grade-uncertainty flag

**none for the primitive's core construction** (LiteLLM-class proxies + typed Pydantic envelopes are commodity engineering on a designed-system spine). One named uncertainty carried as a risk marker, not a buildability blocker: **judge-shape typing for natively-multimodal artifacts** (vision-bearing spec or trace artifacts judged across families) is not uniformly supported — Anthropic, OpenAI, and Google differ on structured-output guarantees under multimodal input, so the typed-output shape may be best-effort rather than strict for that sub-class. Substrate flag, not a research-grade gap.

## Buildability verdict

**`designed-system`.** Provider abstraction + tagged routing + typed envelopes are commodity ingredients; the designed-system content is the family-taxonomy registry, the judge-shape typing rules, the holdout-handle enforcement, and the immutable-log integration. Registry: Medium (per [primitives/index.md](index.md) row for P-14).
