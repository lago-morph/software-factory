Headline rules proposed (5):

5. **A before/after `find` diff is the canonical verification for any multi-source `git mv` reorg.**

## Part 4 — proposed ADRs

Architectural-ish decisions surfaced in this session that the user *might* want to record formally. Titles + one-line rationale only — author via the `adr` skill if any look worth investing in.

- **Subject-matter as default categorisation axis for curated citation corpora** — the orchestrator's redirect on PR #71 turned an implicit default into an explicit one; worth recording so future reorgs don't relitigate the axis choice. Borderline ADR-worthy: only one corpus has tested the default so far (8 sources).
- **Branch-name authority: plan-file > session-bootstrap** — when a fresh-agent plan file specifies a branch name and the session was bootstrapped on a different branch, the plan-file's name wins. Worth recording because the question recurs on every multi-step plan and the answer is non-obvious.
- **PR description must be rewritten after a same-branch rework, not appended to** — PR #71's body was wholly replaced when the medium→subject pivot landed. A descriptive note at the top of the body marked the rework; the rest of the body now describes only the final state. Codifying this prevents future PRs accumulating stratified "old approach / new approach" sections that confuse reviewers.
