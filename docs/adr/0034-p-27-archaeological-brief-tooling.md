# ADR 0034: P-27 archaeological-brief tooling

- **Status**: Accepted
- **Date**: 2026-05-25
- **Deciders**: lead agent (Phase 5 Wave 5.1b fanout)

## Context

P-27 is claimed by two candidates per the [Phase-4.2 overlap analysis](../../architectures/v3/primitives/overlap.md#2-primitive-overlap-counts-by-candidate-coverage): [BF-M](../../architectures/v3/tracks/brownfield-methodology-first.md) for the **Comprehension** stage that produces a per-cycle archaeological brief consumed by Intent-capture, Plan, and PR-body attribution; and [BF-L](../../architectures/v3/tracks/brownfield-legacy-ingestion-first.md) for ingestion-time context briefs over codebase regions (same construction shape, different output envelope). The [P-27 buildability sketch](../../architectures/v3/primitives/P-27-archaeological-brief-tooling.md) verdicts it `designed-system` with `partial` research-grade uncertainty: the *structural* contract is buildable today; *brief-quality calibration* (distinguishing form-correct-substance-thin from form-correct-substance-rich briefs) is an unresolved Phase-5/8 problem.

The forcing failure modes are [F21 (context-window exhaustion) + F61 (multi-agent context fragmentation)](../../architectures/v3/failure-modes-v3.md#f21--context-window-exhaustion--silent-degradation) — brownfield-critical, the brief mitigates them by *compressing* a code region into a typed artifact downstream stages read instead of raw code — and [F40 (last-mile drift)](../../architectures/v3/failure-modes-v3.md#f40--last-mile-drift), since the PR body carries a brief-version pointer as part of per-cycle attribution. A brief that misses a load-bearing invariant or under-counts blast radius silently re-introduces F21/F61 rather than mitigating them, so the construction surface must keep every claim traceable to a substrate query result rather than free-form LLM narration.

## Decision

**Build P-27 as a tool-using LLM-judge synthesis loop over two read-only fact sources — Git-blame/Git-log (introduction-cycle and intent-decay history per touched line/file) and a [Glean](https://glean.software/) fact-store (semantic facts queried out of the [P-26 Codebase Model](../../architectures/v3/primitives/P-26-codebase-model.md): symbol references, call-graph closure, type relationships, lint/test coverage) — emitting a typed `ArchaeologicalBrief` envelope with three load-bearing sections: `introduction-cycle` (when the region was introduced, by whom, in which cycle/PR, with the original change-intent if recoverable), `intent-decay-log` (subsequent edits and the drift between original intent and current behavior, scored by commit-message + diff-shape signals), and `contemporary-references` (current callers, dependents, tests, and invariants in scope).** Every field cites the substrate query that produced it (Git revision range or Glean fact-id); the envelope is append-only-versioned and the BF-M PR body / BF-L ingestion record carries a pointer to the specific brief version. The brief is generated by a tool-using loop whose tools are read-only wrappers over Git-blame, `git log -L`, `git log --follow`, and the Glean query API; synthesis is the LLM-judge's job, but every emitted claim must reference a tool-return.

The envelope is shared across BF-M and BF-L; the **section set** is uniform, the **per-section compression rule** is work-unit-class-parameterised (BF-M cycles: narrow + deep for regression-fix, broad + shallow for codebase-evolution-proposal; BF-L ingestion: broad + shallow across whole regions). Structural validation (Pydantic schema + every claim has a citation) is mandatory at envelope-emit time; substance calibration is deferred per the sketch's `partial` uncertainty flag and tracked as a Phase-5/8 work item.

## Alternatives considered

**B. Pure Git-log review (no semantic fact-store).** Generate the brief from Git history alone — blame, log, diff. *Why rejected:* Git-log surfaces *who touched what when* but not *what calls what* or *what invariants are enforced where*. The brief's `contemporary-references` and `enforced_constraints` fields require semantic-level traversal of the call graph and type graph; Git-log produces a chronology, not a structural picture. Scaling is also adverse — a region with a decade of history under pure Git-log review costs O(commits-touching-region) tool calls before synthesis, while a fact-store query for the same structural slice is O(1). The sketch's tool list (`query_symbol`, `find_callers`, `recent_commits_touching`, `runtime_trace_for_endpoint`, `lint_rules_matching`) makes the semantic surface load-bearing. See [P-27 Construction path](../../architectures/v3/primitives/P-27-archaeological-brief-tooling.md#construction-path).

**C. Commercial code-archaeology tools (CodeSee, Sourcegraph Cody-archaeology, Swimm).** Adopt a vendor tool as the brief-generation substrate. *Why rejected:* vendor lock-in on a load-bearing methodology artifact is the wrong shape — the brief envelope is consumed by BF-M's Intent-capture, Plan, and PR-body attribution stages, all of which the factory authors. A vendor output schema cannot be extended for the work-unit-class compression rules the sketch's [own open question](../../architectures/v3/primitives/P-27-archaeological-brief-tooling.md#corpus-why-citation) requires (`regression-fix` narrow-deep vs `codebase-evolution-proposal` broad-shallow). Glean is open-source; Git tooling is universal; the LLM-judge is provider-swappable. The construction-shape commodification benefit of a vendor tool does not outweigh the extensibility cost.

## Consequences

**Easier:** F21/F61 mitigation becomes substrate-grounded — every claim in the brief points at a Git revision or Glean fact, so downstream stages read a compressed-but-traceable artifact rather than re-reading the codebase. F40 attribution is mechanical (brief-version-pointer in PR body). Both BF-M and BF-L consume the same envelope, so the [BF-L scenario-derivation primitive](../../architectures/v3/tracks/brownfield-legacy-ingestion-first.md) reuses the structural validator and citation discipline without re-implementing them.

**Harder:** Glean deployment + schema authoring becomes a per-language operations requirement (out of scope for this ADR; resolved at architecture-spec time per BF-L's substrate-spec; the P-26 Codebase Model orphan ADR is deferred to [Wave 5.3 next run](../../architectures/v3/decisions/auto-005-phase-5-dispatch-shape.md#decision-round-2)). The LLM-judge cost per brief is non-trivial; per-stage budgets are enforced via [P-02 cost ceilings](./0011-p-02-cost-ceilings.md) and the loop is captured via [P-05 trajectory capture](./0012-p-05-trajectory-capture.md).

**Explicitly NOT promising:** brief-substance quality. Structural validation guarantees only that every field is populated and every claim cites a tool-return — not that the *right* facts were surfaced. Brief-quality calibration (hold-out-brief evaluation, cross-family second-pass diff, adversarial reviewer agent) is a Phase-5/8 research-grade problem per the [sketch's research-grade-uncertainty flag](../../architectures/v3/primitives/P-27-archaeological-brief-tooling.md#research-grade-uncertainty-flag). Same-vs-distinct on the BF-M vs BF-L brief *envelope* is decided SAME (shared envelope, per-class compression rule); same-vs-distinct on upstream brief *provenance* (cycle-trigger vs ingestion-region) is candidate-specific and recorded in Wave-5.3 per-candidate ADRs.
