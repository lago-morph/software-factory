## Part 1 — what happened

### Phase 1 — Research kickoff

Goal: turn a one-paragraph software-factory methodology request into structured research producing four architecture options. Approach: ask four clarifying questions via `AskUserQuestion` to lock down scope, then spawn 7 parallel research subagents (one per source group from `initial-sources.md`).

The plan held: subagents produced reports at `research/01-` through `research/07-`. The first significant surprise: **six of seven source domains returned HTTP 403 from the sandbox** (factory.strongdm.ai, every.to, simonwillison.net, news.ycombinator.com, lennysnewsletter.com, el-kaim.com). Subagents reconstructed content from secondary sources and flagged the caveat in each report header.

### Phase 2 — Synthesis + four architectures

Goal: convert seven reports into a shared synthesis and four architecture options. The synthesis captured 8 consensus points, 8 unresolved tensions, and a 20-failure-mode catalog. Four architecture specs (Specification Refinery, Compound Atelier, Phase-Gated Foundry, Evolutionary Tournament) each ran 3000–5000 words. A comparison doc added a 20×4 coverage matrix.

Unplanned: the stop hook flagged uncommitted changes on every turn, forcing per-report commits rather than batching. Result: cleaner history at the cost of interleaving commits with parallel-agent management. Workable.

### Phase 3 — V2: primary source access

Goal: when the user committed local HTML copies of the previously-blocked sources, re-run the four substantively-blocked reports (01, 03, 05, 06) against primary content and propagate corrections.

Five revision subagents ran in parallel. Sharper than expected: the v2 pass caught **five distinct fabrications** that had propagated from v1 into the architecture specs:

- `DTU = Digital Twin Universe`, **not "Users"** — the URL slug `dtu` had misled v1.
- **HN comment id 46955602 does not exist.** Its quoted text was invented. Closest real comment (bitwize HN 46955522) is substantially more nuanced.
- **Willison's "4 agents → exhausted by 11 AM" specific number was fabricated.** The verbatim Lenny editorial says only "mentally exhausted by 11 a.m.".
- "6,000–7,000 lines" StrongDM spec count was third-party speculation.
- Cal Newport attribution for the Dark Factory framing was wrong (only Dan Shapiro is cited).

Each correction propagated through synthesis, all four architecture specs, and the comparison doc.

### Phase 4 — Followup threads + first fetcher build

Goal: catalog outbound research threads into `followup.md` and build a reusable fetcher mechanism for sandbox-blocked sources.

`followup.md` shipped 12 threads in three tiers. The fetcher mechanism (workflow + Python script + SKILL.md) passed YAML validation and 7/7 auth-check fixtures and 6/6 URL-to-filename fixtures.

### Phase 5 — Reconciliation with main

Another agent had built `fetch-blocked-urls.yml` on main while my branch was in flight. User asked for reconciliation so the merge produces one mechanism. Main's design was better (separate `fetched/issue-N` branches, label-only auth gated by Triage role, `author_association` footgun documented). I deleted my redundant workflow, renamed my skill directory, and rewrote SKILL.md to match main's mechanism.

### Phase 6 — Conflict re-check after big main merge

User merged round-2 research consolidation (PR #9) to main and asked for compatibility verification. Merge-tree dry-run + file-set intersection confirmed zero overlap with main's modifications. PLAN.md §5–6 references in my SKILL.md still resolved (main added §10 but didn't renumber). Real-world usage (issue #4 → 14 .html + 13 .md files) confirmed my docs were accurate.

### Phase 7 — External skill installation

Installed three skills from `lago-morph/ai-skills`: self-retrospective, parallel-subagent-fanout, subagent-prompting (15 files total). Surprises: (a) GitHub API blocked from sandbox even for the same org; (b) GitHub MCP scoped to one repo; (c) WebFetch summarized one SKILL.md file instead of returning verbatim content — switched to `curl` + raw URLs.

### Phase 8 — ADR skill creation + agent-os alignment

Created an ADR skill with template + link checker + first real ADR (recording the fetch-blocked-urls decision so future agents inherit context). Initial form had structural issues (collapse-on-consecutive-hyphens; checker didn't skip code blocks). Fixed both. Then aligned with the `lago-morph/agent-os/adr` convention discovered by examining 41 real ADRs there: H1 form `# ADR NNNN: Title`, section order Context → Decision → **Alternatives considered** → Consequences → References, lowercase "considered", **direct subsection linking** in References (one bullet, multiple anchor links).

### Phase 9 — Self-retrospective skill upgrade

Modified the inherited `self-retrospective` skill to write to disk at `retrospective/report/YYYY-MM-DD-NN.md` with mandatory UTC-date verification via tool call, commit-hashes-by-PR collection, a sibling directory of self-contained per-skill specs, and a consolidated `AGENTS-suggestions.md` with proposed-text plus persuasion subsections. Removed the README.md convention from all four skills (consolidated into spec/SPEC.md only). Updated all references from "Claude file" / `CLAUDE.md` to "agents file" / `AGENTS.md`.

## Part 4 — proposed ADRs

Architectural decisions made in this session that you might want to record formally. **Titles only — no specs.** Author any of these via the `adr` skill if you decide they're worth recording.

- **Adopt `lago-morph/agent-os/adr` as the canonical ADR convention** — H1 form `# ADR NNNN: Title`, section order Context → Decision → Alternatives considered → Consequences → References, direct subsection linking in References. Made in Phase 8 after surveying 41 real ADRs in agent-os.
- **Skills follow `SKILL.md` + optional `spec/SPEC.md` + helper directories; no `README.md`** — consolidates motivation and reference content into one file. Applied to all 4 skills in Phase 9; 7 README files deleted.
- **Retrospectives live at `retrospective/YYYY-MM-DD-NN.md` (no `report/` subdir) with a sibling spec directory** — the canonical path for retrospective artifacts. The redundant `report/` segment was dropped per session decision.
- **Verify UTC date via tool call before producing any date-stamped artifact** — `date -u`, Python `datetime.UTC`, or Node `new Date().toISOString()`. Never trust the model's internal notion of the date. Mandatory step in the retrospective skill.
- **All agent-file references use `AGENTS.md` / "agents file", not `CLAUDE.md`** — the generic naming. Applied throughout `self-retrospective` skill in Phase 9.
- **Workflows commit to side branches (`fetched/issue-N`, `feat/X`); humans merge into main** — main stays clean by construction. Adopted from the `fetch-blocked-urls` mechanism (ADR-0001) but worth recording as a broader principle.
- **Label-only authorization (Triage-role gate) for issue-triggered workflows; never `author_association`** — webhook payload and REST API disagree on `author_association`; label-only avoids the silent-skip footgun. Documented in `research/PLAN.md` §6 and applied in `fetch-blocked-urls.yml`.
