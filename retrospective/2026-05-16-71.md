### Phase 3 — Orchestrator redirect on sizing: "If there are 200 sources, why 6 categories?"

After the retrospective landed, the user asked the sizing question. Answer: the second pass was sized for the **current** corpus of 8 sources, not the **restored** corpus of ~180–220. 6 categories × 33 sources/cat average = 2× the plan's ~5–15 ceiling. The "fine-grained (6) vs coarser (4)" framing of the previous `AskUserQuestion` was itself the bug: both options were below the size-rule target, so the user picked the better of two undersized choices.

Recovery: explicit sizing math — `ceil(estimated_total / target_per_category)` → ~13–40 categories for 180–220 sources at 5–15/cat. Proposed a 15-category subject-matter taxonomy and used `AskUserQuestion` again (this time with options at and above target). User picked "re-categorize now to ~15".

Third-pass moves were more substantial than the second pass because the new taxonomy required splitting an existing source unit: `lenny-podcast-transcripts/` (a collection-of-convenience bundling Cherny and Willison) was split along the interviewee axis — Willison → `willison-canon/`, Cherny → `anthropic-substrate/cherny-claude-code-interview/`. The collection-level README was `git rm`'d; Willison provenance folded into the top-level inventory; a fresh README written for the Cherny subdir. Net result: 15 categories of which 9 hold current sources and 6 are reserved for restoration; no on-disk dirs for empty categories — they live only in the top-level README's Categories table. Committed `7123d4c`, pushed, updated PR description.

## Part 3 — agents-file suggestions

See [./2026-05-16-71/AGENTS-suggestions.md](./2026-05-16-71/AGENTS-suggestions.md) for the full set, one section per rule, each with exact paste-ready text and a persuasion argument.

Headline rules proposed (9 after Phase 3 update):

1. **Trust the plan's branch names, not the session-bootstrap branch.**
2. **When categorising a curated citation corpus, default to subject-matter, not medium.**
3. **On a directional redirect, propose options via `AskUserQuestion` with concrete preview content — don't re-execute on a guess.**
4. **When backfilling an inventory, `ls` the actual directory; don't trust a parent README's chapter / file count.**
5. **A before/after `find` diff is the canonical verification for any multi-source `git mv` reorg.**
6. **PR description gets rewritten on same-branch reworks, not appended to.**
7. **Auto-subscribe webhook discharges the manual subscribe action — don't re-call as a no-op.**
8. **Sizing math drives category count from the start: `ceil(estimated_total / target_per_category)` before proposing any category list.**
9. **`AskUserQuestion` option sets for sizing-sensitive decisions must include at least one option at or above the size-rule's target — otherwise the user is forced to pick the best of two undersized options.**

## Part 4 — proposed ADRs

Architectural-ish decisions surfaced in this session that the user *might* want to record formally. Titles + one-line rationale only — author via the `adr` skill if any look worth investing in.

- **Subject-matter as default categorisation axis for curated citation corpora** — the orchestrator's redirect on PR #71 turned an implicit default into an explicit one; worth recording so future reorgs don't relitigate the axis choice. Borderline ADR-worthy: only one corpus has tested the default so far.
- **Branch-name authority: plan-file > session-bootstrap** — when a fresh-agent plan file specifies a branch name and the session was bootstrapped on a different branch, the plan-file's name wins. Worth recording because the question recurs on every multi-step plan and the answer is non-obvious.
- **PR description must be rewritten after a same-branch rework, not appended to** — PR #71's body was wholly rewritten *twice* (after the axis pivot, then after the sizing pivot). A pivot-note at the top preserves audit trail; the rest of the body describes only the final state. Codifying this prevents future PRs accumulating stratified "old approach / new approach" sections.
- **Sizing-driven category-count formula for taxonomy design** — `target_categories = ceil(estimated_total / target_per_category)` should be applied at the start of any sizing-anchored categorisation, with explicit allowance for empty / "reserved for restoration" categories. This was the latent rule the third pass on PR #71 made explicit; codifying it as an ADR would lock the formula into future taxonomy designs in this repo.
