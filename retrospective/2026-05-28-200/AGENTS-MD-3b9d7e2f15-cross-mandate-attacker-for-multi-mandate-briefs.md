# agent instruction

**Cross-mandate-attacker as Round-2-default for multi-mandate hypothesis briefs.** When a decision brief posits a falsifying pattern across multiple mandate/category surfaces (e.g., greenfield-vs-brownfield, both-mandates-vs-one-mandate, multi-tenant, multi-jurisdiction), the lead agent MUST include the **cross-mandate-attacker** angle in Round 2 of adversarial review (or earlier). The cross-mandate-attacker reads the brief looking specifically for cells where the discipline cannot hold across all mandates — e.g., where the file model presupposes one structure while the falsifying pattern presupposes another; where pass-criteria are mandate-blind in a way that masks single-mandate failures; where escape-hatches have mandate-asymmetric interpretation. The angle is structurally distinct from skeptic / pre-mortemer / cost-hawk / regulator / on-call and catches a class of structural defects those angles miss.

*Grounded in: Phase-8 auto-008 Round 2 — Reviewer 6 (cross-mandate attacker) found the load-bearing structural defect where the DEC-1.a falsifying pattern said "≥2 unified-attempts pass cleanly on BOTH the greenfield-mandate lean-eval AND the brownfield-mandate lean-eval" but the file model has only ONE lean-eval brief per unified-attempt. Round 1 reviewers (pre-mortemer, falsification-designer, cost-hawk) did not catch this. The Round-2 amendment chain R6 #1 + #2 + #5 (mandate-scenario-split YAML field + partitioned §1 + partitioned pass-cleanly definition + structural rider) was the load-bearing fix. Without it, all 4 unified-attempt lean-evals would have been DEC-1.a-falsification-incoherent at simulator-harness execution time.*

# justification

The cross-mandate-attacker angle has high information value for any brief whose central load-bearing claim depends on a pattern holding across multiple categorical surfaces. The standard adversarial-reviewer angles in [`adversarial-reviewer-angles.md`](../../.claude/skills/autonomous-run/resources/adversarial-reviewer-angles.md) — skeptic, pre-mortemer, cost-hawk, regulator, on-call, etc. — are domain-general but do not specifically target cross-category structural mismatches. The cross-mandate-attacker is in the catalog but listed under "cross-cutting angles for synthesis / candidate-set work"; this rule promotes it from optional-when-relevant to mandatory-when-applicable.

The structural pattern the angle catches is recurrent: a brief commits to a falsifying-pattern statement (e.g., "≥2 unified-attempts pass cleanly on BOTH X AND Y") without checking that the file/data/evidence model supports the "BOTH X AND Y" form. If X and Y are stored together in one artifact (one file per unified-attempt), the brief either needs to partition the artifact (one mandate-bloc per subsection) or rewrite the pattern to use single-artifact terms. Either fix is mechanical once surfaced. The risk is the lead agent + standard reviewers not noticing the mismatch.

Triggering: any brief that names a falsifying pattern using "BOTH X AND Y" / "across both A and B" / "in either C or D" where X/Y/A/B/C/D are categorical surfaces (mandates, regions, tenants, jurisdictions). Phase-8 auto-008's "BOTH the greenfield-mandate lean-eval AND the brownfield-mandate lean-eval" is the prototype.

The cross-mandate-attacker should fire **no later than Round 2** because by Round 2 the brief's structural commitments are visible enough for the angle to find specific cells. Firing earlier (Round 1) is acceptable but the brief may be too underspecified at R1 for the angle to find concrete defects.
