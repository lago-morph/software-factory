# agent instruction

**Use GitHub permalinks when referencing churn-prone files.** When citing a specific line range or section of a file whose section numbers or line positions drift (`research/PLAN.md`, `INDEX.md`, status docs, anything regenerated by a workflow), link to a GitHub permalink pinned at a specific commit SHA (`https://github.com/<owner>/<repo>/blob/<sha>/<path>#L<start>-L<end>`) instead of a live relative link. Keep a separate live link alongside for current-state navigation, but make the permalink the citation of record so the reference does not silently rot.

*Grounded in: PR #113 reference to `research/PLAN.md` §3.6 worked F36/F37-collision example.*

# justification

The reviewer flagged the bare-`research/PLAN.md §3.6` reference because that file changes a lot — drains add round-summary bullets, plan reorganizations renumber sections. A future reader following the link could find `§3.6` is now about something else entirely. Pinning the citation to commit `58216ff#L83-L97` costs four extra characters of typing per reference (the SHA prefix) and one `git log -1 -- <file>` lookup; the benefit is a permanent reference that survives arbitrary file reorganization. The live link alongside still gives readers the current-state version. Adopt for any reference whose target is a file that gets regenerated, regularly amended, or carries section numbers that re-flow.
