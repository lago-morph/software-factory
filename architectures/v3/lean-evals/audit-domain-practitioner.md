# Domain-practitioner audit — Phase 8 Wave 8.1 cross-candidate roll-up

**Auditor.** Phase-8 Wave-8.1.b domain-practitioner subagent (cross-candidate roll-up per auto-008 §Decision Round 2 A.2′).
**Inputs.** 10 finalized lean-eval briefs at architectures/v3/lean-evals/{gf-s,gf-m,gf-c,bf-s,bf-m,bf-l,u-a,u-b,u-c,d7-u-1}.md.

## Cross-candidate summary

Headline finding: **across 10 briefs, scenarios broadly validate the discipline rather than just exercise primitives, but the validation is uneven — 3 briefs land clear practitioner-relevant tests (BF-S, BF-L, BF-M); 3 land defensible but heavily-primitive-coupled tests (GF-S, GF-C, U-C); 4 lean toward "internal-consistency check disguised as lean-eval" (GF-M, U-A, U-B, D7-U-1) where the falsifier reads more like "did the substrate emit the envelopes we asked for" than "would a working engineer trust this verdict." None are reject-worthy, but the four unified-attempts collectively have the weakest mapping from scenario outcome to practitioner-meaningful failure.**

Top 3 practitioner-relevance candidates: **BF-S** (real perimeter-bypass count on production-shaped data is the test a senior engineer would actually run); **BF-L** (seeded-drift detection on a real 1M+LOC repo is something an SRE/maintenance lead immediately recognizes); **BF-M** (archaeological-brief invariant recall against labeled invariants on a realistic codebase reads like an actual onboarding-doc evaluation). Bottom 3 (concerning, not failing): **U-A** (zero-promotion-rate on a substrate-named envelope class is plausibly an empty-config bug, not a methodology failure); **U-B** (`LayerInferenceConfidence < 0.7` is a number the substrate itself emits — a substrate that always returns 0.71 passes); **D7-U-1** (KL > 1.0 on opposing-side-kind distribution is a metric only an in-corpus reader can interpret).

**Cross-candidate patterns.** (1) **MCC ≤0.55 falsifier is mechanically clean but practitioner-thin**: five briefs use the Larbi single-judge ceiling. A practitioner cares less about the MCC number and more about whether real contradictions get caught — the scenarios sometimes obscure this. (2) **Substrate-emitted-envelope-as-evidence is a recurring weakness in unified-attempts**: U-A, U-B, U-C, D7-U-1 all measure outcomes through fields the candidate's own substrate populates. (3) **Heavy-tier scenarios consistently understate evaluator burden** — 1-day budget on BF-M's medium codebase + invariant labeling, or BF-L's 1M+LOC scaffold + Caremark/RSI tagging, is implausible. (4) **Greenfield candidates avoid F40 by construction**, which is honest but removes the most practitioner-felt brownfield-adjacent pressure.

## Cross-cutting recommendations

Three patterns for Wave 8.2 cross-candidate evaluator-brief:

1. **Substrate-emitted-evidence vs ground-truth-labeled evidence.** The four unified-attempts (U-A/U-B/U-C/D7-U-1) and parts of GF-M, GF-S use success criteria that read substrate-emitted records (envelope content-hashes, layer-confidence fields, dispatcher regime counts, FC ledger entries) as evidence the methodology worked. A substrate misconfigured to always return passing values would pass these tests. The three briefs with the strongest practitioner-relevance (BF-S, BF-M, BF-L) avoid this by labeling ground-truth independently (perimeter bypass on actual production-shaped data; seeded load-bearing invariants on real codebase; seeded drift events). Wave 8.2 should explicitly evaluate each candidate's "ground-truth-independence" — i.e., could a misconfigured substrate that always says "yes" pass the lean-eval?

2. **Evaluator-time budgets are uniformly optimistic, especially for Heavy tier.** Every Heavy-tier brief (BF-M, BF-L, U-A, U-B, U-C, D7-U-1) claims 1-day with hour-by-hour breakdowns that compress setup, polyglot codebase ingestion, seeded-drift/invariant labeling, and 6 scenarios into 8 hours. BF-L's 1M+LOC + Caremark/RSI tagging + 6 scenarios is the clearest violator. Wave 8.2 should either re-budget Heavy-tier to 2 days OR accept that lean-evals will be partial — the current pretense risks scenario-skipping under time pressure, which the protocol invariants forbid but which evaluators will do anyway.

3. **Unified-attempts' falsifiers are mechanically rigorous but practitioner-distant.** All four unified-attempt §3 falsifiers (U-A promotion-rate, U-B LayerInferenceConfidence + degradation, U-C regime-distribution KL/divergence, D7-U-1 opposing-side-kind KL) pass the auto-008 4-item rubric cleanly but read as "the substrate's distinctive primitive did/didn't behave per spec" rather than "the methodology produced/failed to produce software a practitioner would trust." This is the structural risk auto-008 §Decision Round 2 A.2′ asks us to surface. None warrant rejection — each falsifier IS targeting the candidate's distinctive wager — but Wave 8.2 cross-candidate comparison should weight practitioner-felt scenarios (BF-S #2, BF-M #2, BF-L #2, GF-C #1) more heavily than substrate-self-test scenarios when adjudicating cross-candidate verdicts. The unified-attempt mandate-asymmetric collapse pattern is sophisticated synthesis-internal logic; a Wave 8.2 brief explaining DEC-1.a to a practitioner-evaluator would need an additional translation layer.
