# ADR 0028: P-19 eligibility / regime classifier framework

- **Status**: Accepted
- **Date**: 2026-05-25
- **Deciders**: lead agent (Phase 5 Wave 5.1b)

## Context

Four candidates claim P-19 eligibility / regime classification as a substrate primitive: [GF-S/S9](../../architectures/v3/tracks/greenfield-substrate-first.md#1s9--eligibility-classifier-regime-naming-substrate-primitive), [BF-L per-region](../../architectures/v3/tracks/brownfield-legacy-ingestion-first.md), [U-C distance-gated dispatcher](../../architectures/v3/tracks/unified-C.md), and [U-A interval-kind](../../architectures/v3/tracks/unified-A.md). The [Phase-3.5 buildability sketch](../../architectures/v3/primitives/P-19-eligibility-regime-classifier.md) verdicts the primitive `designed-system`: commodity ingredients (Drools / OPA Rego / scikit-learn / P-14) but candidate-specific feature schemas, regime label sets, and OPA-enforced hard floors are the load-bearing design content.

Per the [Phase-4.2 overlap analysis](../../architectures/v3/primitives/overlap.md#p-19-eligibility--regime-classifier--four-contested-variants), the verdict is verbatim: **"SAME primitive (P-19 classifier framework), DISTINCT feature sources + distinct output regime sets."** All four variants share the construction recipe (decision-table engine + LLM-judge fallback via P-14 + OPA hard-floor post-check); they differ at the *feature engineering* layer and the *output enum* layer, not the *decision-engine* layer. This ADR records the common framework. The discipline-layer counterpart — methodology contract binding each candidate to declare its regime set, feature source, and hard-floor table — is [ADR 0024](0024-discipline-regime-classification.md).

The forcing failure modes are [F57 (design-authority erosion / convenience reclassifies stakes)](../../architectures/v3/failure-modes-v3.md#f57--design-authority-erosion-convenience-reclassifies-stakes) — the classifier exists to make regime drift substrate-visible — and [F25 (design starvation)](../../architectures/v3/failure-modes-v3.md#f25--design-starvation) — cold-start cycles must default to `augmentation-required` regardless of classifier output. [F47 (Goodhart on visible metrics)](../../architectures/v3/failure-modes-v3.md#f47--visible-metric-drift-goodhart-on-tokens) is the Patrol-monitoring concern: the classifier-output distribution itself becomes a watchdog signal.

## Decision

**Build the P-19 framework as a feature-engineered decision-table classifier on a substrate-typed feature vector, with three composable layers:** (1) a **decision-table engine** — Drools (when the deployment already operates a JBoss/Java rules layer) or OPA Rego (preferred default, so the regime cut-points live next to other policy mediators in P-29) — evaluating versioned declarative thresholds against named features and emitting the regime label deterministically; (2) an **LLM-judge fallback** routed through [P-14](../../architectures/v3/primitives/P-14-judge-router.md) for the rule-engine's `unknown` bucket, returning a Pydantic-typed `{regime, rationale, confidence, named_drivers[]}` envelope under `same-model-different-role` or `cross-family` judge diversity; (3) an **OPA hard-floor post-check** binding both rule-engine and LLM outputs against deterministic invariants the classifier cannot violate (e.g., cold-start cycle count < N → `augmentation-required` per F25; `contradiction_flag = true` → `human-required` regardless of regime; Caremark/RSI exposure → never `automation-eligible`).

Classifier parameters (cut-points, rule packs, hard-floor predicates) are stored as **versioned configuration** alongside the OPA policies, so Patrol can diff across versions and log drift as F57-typed events. Every classification is a typed event written to the trajectory store ([P-05](0012-p-05-trajectory-capture.md)); the output distribution is watchdog-monitored ([P-06](0013-p-06-watchdog-tiers.md)) for F47-shaped drift. The hybrid (rules → LLM fallback → OPA floor) is the canonical path; deployments may degrade to rules-only when LLM availability is constrained, but the OPA floor is non-optional.

## Alternatives considered

**B. LLM judge as the sole classifier (no rule engine, no OPA floor).** *Why rejected:* this is the [F51 Ashby-deficient probabilistic guard](../../architectures/v3/failure-modes-v3.md) attractor — resting regime classification entirely on an LLM judge at high-stakes intervals violates the substrate-typed-invariant discipline that F57 requires. The [P-19 sketch's research-grade-uncertainty flag](../../architectures/v3/primitives/P-19-eligibility-regime-classifier.md#research-grade-uncertainty-flag) explicitly carries this concern: the hybrid path with OPA floors is the lead-agent's best current answer because the floors are deterministic invariants the judge cannot violate. A judge-only path also forfeits the auditability of versioned cut-points that Patrol can diff for F57 drift detection.

**C. Hardcoded per-candidate classifiers (no shared framework; each candidate ships its own decision logic).** *Why rejected:* the [overlap.md verdict](../../architectures/v3/primitives/overlap.md#p-19-eligibility--regime-classifier--four-contested-variants) established the decision-engine layer is genuinely shared across the four variants; only feature sources and output enums differ. Per-candidate reimplementation duplicates the rule-engine + LLM-fallback + OPA-floor plumbing four times, fragments the Patrol drift-monitoring signal across incompatible classifier shapes, and forfeits the Phase-8 lean-eval cross-variant correlation pressure-test ([overlap §P-19 implications](../../architectures/v3/primitives/overlap.md#p-19-eligibility--regime-classifier--four-contested-variants)) which requires a shared substrate to be meaningful.

## Consequences

**Easier:** F57 drift becomes substrate-visible at the classifier-output-distribution layer (Patrol has a defined signal). F25 cold-start protection is an OPA floor, not an agent-discipline promise. The hybrid decision-engine path lets candidate variants share Drools/OPA/P-14/Pydantic infrastructure while differing only at the feature-extractor and regime-enum layers. The Phase-8 cross-variant correlation pressure-test becomes meaningful because all four variants share the same decision engine.

**Harder:** Per-deployment ops carries OPA-Rego policy authoring + Drools rule-pack maintenance + the LLM-judge integration through P-14. Classifier-drift monitoring requires a baseline output distribution per regime, calibrated per deployment. The hybrid path's three layers each have failure modes that must be exercised in lean-evals (rule-engine staleness; LLM-judge instability; OPA-floor over-restrictiveness).

**Explicitly NOT promising — scope boundary:** This ADR covers the **framework only**: decision-table engine choice (Drools or OPA Rego), LLM-fallback discipline via P-14, and the OPA hard-floor post-check pattern. The **per-variant feature sources** — GF-S work-unit-class features (intent-block-fields-touched, scenario-set saturation); BF-L per-region features from [P-26 Codebase Model](../../architectures/v3/primitives/P-26-codebase-model.md); U-C distance-tuple from [P-32](../../architectures/v3/primitives/P-32-distance-estimator.md); U-A interval-kind from the [P-28 envelope](../../architectures/v3/primitives/P-28-typed-object-store.md) — are DEFERRED to Wave 5.3 next run as 4 candidate-specific ADRs per [auto-005 Round 2](../../architectures/v3/decisions/auto-005-phase-5-dispatch-shape.md#decision-round-2). Per-variant feature-source ADRs are Wave-5.3-next-run scope. Phase-6 candidate architecture specs reference BOTH this framework ADR + their per-variant feature-source ADR.
