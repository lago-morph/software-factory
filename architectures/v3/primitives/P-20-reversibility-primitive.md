# P-20 — Reversibility primitive (event-sourced)

**Dispatch tier:** per-primitive (designed-system).
**Claimed by:** [GF-M](../tracks/greenfield-methodology-first.md) §1.3 "Reversibility primitive."
**Registry buildability scope:** designed-system — the event-sourcing pattern is well-understood; the integration with intent / scenario / artifact event types is the design content.

## Contract restatement

The primitive provides **cheap commit-and-reverse on intent / scenario / artifact objects** by storing all mutations as an append-only ordered event log and projecting the current aggregate state on demand. What gets *logged* is a typed event per mutation: `IntentDrafted`, `IntentParaphraseEmitted`, `IntentPromoted`, `IntentReversed`, `ScenarioAuthored`, `ScenarioPromoted`, `ScenarioReversed`, `ProbeRealized`, `ProbeOutcomeRecorded`, plus the slice-level events (`SlicePromoted`, `SliceRolledBack`). What gets *reversed* is the **projected aggregate** — an intent block, a scenario object, a slice manifest — by appending a compensating event (`*Reversed`) rather than mutating or deleting prior state, and re-projecting the aggregate from the trimmed event stream. The log itself is immutable; "reversal" is a forward-only operation that produces a new projected state. The latency / cost target is **sub-millisecond per-event persist** (the OpenHands V1 prior art anchor [report 11 §6](../../../research/11-openhands-substrate-audit.md), cited by GF-M §1.3 as the warrant that this is affordable), enabling reversal to remain in the inner loop of Regime A's promote-or-reverse gate without budgeting concerns.

## Construction path

**Primary tool: EventStoreDB** (`event_store_db.AppendToStream`). Each intent / scenario aggregate maps to a stream keyed by aggregate ID (e.g., `intent-<uuid>`, `scenario-<uuid>`, `slice-<uuid>`); the cycle appends typed events via `AppendToStream(streamName, expectedVersion, events)` with optimistic concurrency on `expectedVersion`. Reversal is `AppendToStream(streamName, currentVersion, [Reversed(reason, reverter)])`, and a projection worker (EventStoreDB's `$by_category` projection or a custom catch-up subscription using `ReadStreamEvents`) materializes the current aggregate by folding events left-to-right and dropping any event whose ID appears in a subsequent `*Reversed.reverses` field.

**Fallback / lighter constructions.** (a) **axon-framework** on JVM provides the same primitives (`@EventSourcingHandler`, `EventStore.appendEvents`) with annotation-driven aggregates; chosen if GF-M's eventual deployment target is JVM-shaped. (b) **Custom event-sourcing on Postgres**: an `event_log(stream_id, version, event_type, payload jsonb, ts)` table with a `(stream_id, version)` unique constraint for optimistic concurrency, plus per-aggregate projection workers polling `event_log` and writing to a `projection_<aggregate>` table; this is the construction GF-M defaults to if EventStoreDB's operational footprint is too heavy for the factory's substrate budget. (c) **OpenHands V1's own event-log pattern** (registry cites it as prior art) — the [`11-openhands-substrate-audit`](../../../research/11-openhands-substrate-audit.md) §6 trajectory persist primitive is structurally identical to what GF-M needs, and a deployment can compose P-20 directly on top of P-05 (trajectory capture) by adding the typed-event taxonomy on top of OpenHands' raw event sink.

## Cost / latency analysis

Per-event persist is sub-ms on EventStoreDB / OpenHands V1; reversal cost is one additional append (sub-ms) plus a projection rebuild (linear in stream length, typically <100 events per intent aggregate → microseconds). The **interaction with Regime A paraphrase fan-out** is the load-bearing cost-side concern: each Regime A cycle generates `1 + N + M + 1` events (draft + N paraphrases + M probe outcomes + promote-or-reverse) where N is the paraphrase fan-out (registry's "known multiplier"). At N=5 paraphrasers and ~10 events per cycle, even 10,000 cycles/day = 10⁵ events/day = trivially within EventStoreDB's per-node throughput (~15k events/sec sustained). The primitive's cost is **dominated by paraphrase compute, not by event persistence** — the reversibility primitive itself contributes negligibly to GF-M's OQ-T2 cost-ceiling concern.

## Corpus-why citation

GF-M §1.1 step 4 ("Promote or reverse") and §1.3 ("Reversibility primitive") make this primitive *constitutive* of Regime A: without sub-ms reversal, the "commitments are reversible by design and cheap by substrate" claim (§2.2) collapses and the malleable-phase cycle becomes paralytic rather than productive. Specific failure modes the primitive is shaped against: **F9 (spec overfitting)** — reversal lets the cycle abandon an intent rather than retroactively rationalize the artifact built from it; **F41 (under-defined-intent debt)** — reversal at the promote-or-reverse gate prevents under-defined intents from compounding into durable spec; **F37 (silent contradictory-prompt collapse)** — when paraphrase divergence flags contradiction, reversal cheaply removes the contaminated intent; **F40 (last-mile drift)** — coupled with promote-only-on-slice-coherence, reversal keeps the durable spec narrow and shippable. GF-M's own [OQ-T6](../tracks/greenfield-methodology-first.md#7-open-questions-surfaced-by-this-track) is the standing falsification surface for the reversibility-as-defense argument.

## Research-grade-uncertainty flag

**None for the event-sourcing substrate itself** — EventStoreDB, axon-framework, and OpenHands V1's event log are all production-tested. The **integration with intent artifacts** (defining the right typed event taxonomy for intent / scenario / slice mutations, including the `reverses` back-reference shape and the compensating-event projection semantics) is designed-system work, not research-grade — the design space is bounded by GF-M's four-phase Regime A cycle plus the slice-promotion / rollback shape, and the corpus precedent (DDD event-storming) maps cleanly. Flag only escalates if Phase 4.2 reveals that the event taxonomy must also encode cross-aggregate causality (e.g., reversing an intent automatically reverses all scenarios that depend on it), at which point the projection logic approaches a small graph-rewrite engine; still designed-system, not research-grade.

## Buildability verdict

**designed-system.**
