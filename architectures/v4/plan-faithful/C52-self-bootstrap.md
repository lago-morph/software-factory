## 2. Dependency graph

Critical path: **C08 spec format + C51 predicate + C20 `factory_build` lifecycle → T1 → T2 → T3 → T4 (mandatory gate) → T5 (deploy)**.
- **T1 is the controller spine:** it reuses the *existing* C12/C13/C28 flow, so it does **not** wait on a new engine — only on those components' build seams existing.
- **T2** needs **C51's predicate contract** frozen (the `{pass|fail|inconclusive}` verdict + `transfusion-insufficient` signal — C51 §3.3/§3.5); C51 is the hard upstream that makes "factory builds factory" acceptance-gated.
- **T3** cannot write until **C20's** `factory_build`/`factory_build_in_progress` schema + resume fields are frozen (D-3) and C19/C41 exist.
- **T4 (the keystone gate)** is the load-bearing task: it joins C51's verdict (T2) and C53's rubric-result (T6) and runs at C56's level. C53 and C56 are **Batch-4, unbuilt** — T4 builds against **stubs** for both and freezes the *consumption seams* now.
- **T7 (resume)** keys off T3's lifecycle fields but is otherwise an independent workstream against a seeded fixture bead.
- **Must precede C52:** C08 (format), C51 (predicate), C20 (lifecycle), C19/C41 (store + attribution), and the C12/C13/C28 build flow. **Soft/stubbed:** C53 (rubric — routed seam), C56 (autonomy level), C54 (sequencing — C52 is the per-component mechanism it orders).
- **Downstream of C52 (depend on it, build after):** C53 (consumes the loop + gate), C54 (sequences the recursion), C56 (governs the gate's level). C52 must freeze its gate-input and lifecycle seams early so these three can build against stubs.

## 3. Parallelization

Three workstreams fan out once T1's controller skeleton + the upstream contracts (C51 verdict, C20 lifecycle) are frozen:
- **WS-A (recursion core):** T1 + T2 + T3 + T5 — author-spec → declare-transfusion → run-flow → write/advance `factory_build` bead → deploy. Verifiable end-to-end against a **C51 predicate stub** + a **C20 `factory_build` schema stub** + the existing build flow.
- **WS-B (the gate):** T4 + T6 — the mandatory design-review gate and its **C53 rubric-result** + **C56 autonomy-level** consumption seams. Built against **C53/C56 stubs** (both unbuilt). This is the highest-risk seam (two unbuilt consumers) and is best isolated so the gate's *mandatory-ness* (spec I2) can be asserted independently of the rubric's content.
- **WS-C (resume):** T7 — the `gc bd find` → recover → `gc converge resume` procedure, built against a **seeded `factory_build_in_progress` fixture bead** (no need to wait for WS-A to produce a real in-progress build).
- **T8** (G23 / `C52-gate` scope doc) rides alongside all three.
The join point is a real self-build flowing **author → run → transfusion-pass → mandatory gate → deploy**, with the resume path (WS-C) proven by interrupting that flow mid-build and continuing it.

## 4. Interfaces-first / contract milestones (freeze early)

1. **`factory_build` lifecycle + resume-field contract** (T3, T7) — depends on **C20's** frozen `factory_build`/`factory_build_in_progress` schema (D-3): the exact resume fields (`transfused_from`, spec pointer, scenario pointer, **workflow handle**, lifecycle `status`). Freeze the C20↔C52 seam first so WS-A can write the lifecycle and WS-C can seed a realistic resume fixture. *(This seam also touches review-log XC-2 — the cold-start-query reconciliation; coordinate with C20.)*
2. **C51 predicate-consumption contract** (T2) — the `{pass | fail | inconclusive}` verdict shape + the `transfusion-insufficient` signal C52 consumes at acceptance (C51 §3.3/§3.5). Freeze so WS-A's acceptance step builds against C51's stub.
3. **Design-review-gate input contract** (T4) — what the gate consumes: (a) C51's verdict, (b) **C53's** validation-rubric result, (c) **C56's** autonomy-level policy. Freeze the *consumption seams* now (even against stubs) so C53 and C56 — both unbuilt and both *depending on C52* — can build their producing sides against a stable C52 gate interface.
4. **Self-targeted spec emission contract** (T1) — the C08-format spec instance (`packs/*/spec.md`) C52 authors for the factory's own next component. Constrained by **C08's** format (the artifact is *in* C08's format, not a new one). Freeze the "factory authors its own spec" handoff so the build-flow dispatch (C12/C13/C28) is keyed off a real spec artifact.

## 5. Risks & de-risking order

1. **The mandatory-gate seam onto two unbuilt consumers (highest, OQ1/OQ2).** T4's gate must consume **C53's** rubric-result and run at **C56's** level, but **both C53 and C56 are Batch-4 and unbuilt**, and the inventory's `C52-gate` dependency is easy to misread as a third missing component. **First** freeze the gate-input contract (milestone 3) and document the decomposition (T8: C52 = loop + gate, C53 = bar, C56 = level, C11 = intent) so the three consumers build against a stable seam. De-risk the *mandatory-ness* invariant (spec I2/AC4) independently by testing that a deploy with the review unset is **blocked** — the keystone safety property must hold even before C53's rubric content exists.
2. **G23 — "deploy if it works" has no pass bar (OQ1).** The most consequential checkpoint in the plan is subjective (README:434). Do **not** invent a bar in C52; route it to C53 (T6) and confirm via review-log that C53 owns the rubric + ships the bootstrap component's scenario set (README:526), and that C11 supplies the structured next-component intent. Spiking a C52-local bar would be the wrong fix and would collide with C53.
3. **Resume happy-path-only (OQ4, review-log XC-2).** AI-CONTEXT §16 gives only the success procedure; the cold-start query `gc bd find --type factory_build_in_progress` is also the XC-2 reconciliation point (C20-B folds it into `state=in_progress`). Prototype WS-C against a seeded fixture bead **early**, and define the resume-failure path (unrecoverable handle/dangling pointer → restart-from-spec) — but treat resume-completeness as a **C20** invariant, not a C52 re-implementation.
4. **F54 RSI drift overstatement (OQ6).** C52 *is* the self-modifying loop; F54 is "Partial — significant residual" (F-MODE L93). The temptation is to claim the mandatory gate *closes* F54. It does not — it reduces blast radius. Spike nothing here; **document** that the dedicated multi-cycle goal-comparison audit pack (F-MODE §11 #5; G35) is a separate, elsewhere-owned discipline, so no one assumes C52's gate alone covers RSI drift.
5. **Second-engine scope creep (T1).** The temptation is to build a bespoke "bootstrap runner". The bar says reuse the existing C12/C13/C28 flow (spec I4). Prototype T1 as a *dispatcher into the existing flow* first; if any factory-self-build need cannot be met by the normal flow, surface it as a gap rather than forking a parallel engine.

## 6. Definition of done

- **Per spec ACs:** AC1 (self-build only from a committed C08-format spec), AC2 (runs through the existing convergence flow with a `factory_build_in_progress` bead — no second engine), AC3 (≥1 `transfused_from` + C51 predicate invoked; zero-exemplar self-build rejected), **AC4 (mandatory design-review gate — non-bypassable; a deploy with review skipped does not ship — the keystone)**, AC5 (gate consumes C51 verdict + C53 rubric-result, runs at C56 level; C52 defines no pass bar), AC6 (approval → build advances to completed `factory_build` state [advance form = C20:OQ-3] + component installed back; rejection → spec-iteration), AC7 (resume recovers `transfused_from` + spec + scenarios + workflow handle and continues via `gc converge resume` with no state loss), AC8 (writes only C20-declared fields + C08-format specs; new field/format = upstream change request).
- **Per-task DoD:** each task's artifact (recursion controller, lifecycle driver, gate, resume controller) is exercised by at least one run of the recursion against the **small first-factory-built-component fixture** (README:431 — a Linear-webhook `[[provider]]` extension or a daily-bead reporter pack), and the **mandatory-gate** task additionally passes a negative test (deploy blocked when review unset).
- **Component DoD:** a real self-build flows **author C08 spec → declare transfusion → run the existing flow → `factory_build_in_progress` bead → C51 predicate → mandatory human design review (at C56's level, against C53's rubric) → approve → deploy back into the factory → build advances to the completed `factory_build` state** (the advance's on-disk form is C20-owned — C20:OQ-3); the **resume** path is proven by interrupting that flow mid-build and continuing it via the §16 procedure; and the **G23 / `C52-gate` scope reconciliation** (C52 = loop + mandatory gate; C53 = bar; C56 = level; C11 = intent; `C52-gate` = C52-internal, not a separate component) is written to [`_meta/review-log.md`](../_meta/review-log.md) — closed by escalation, not silent assumption. The keystone safety invariant — **no factory-built component deploys into production without passing the mandatory design-review gate** — is asserted by an enforced negative test, not just documented.
