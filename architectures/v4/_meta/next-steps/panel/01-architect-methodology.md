# Panel review 01 — Architect / methodology angle

**Reviewer:** software architect & delivery-methodology expert.
**Target:** [the unified plan](../10-unified-plan.md), against [the grounding brief](../00-grounding-and-exemplar.md), [the build order](../../../implementation-dependencies.md), [C53](../../../spec/C53-bootstrap-validation.md), [C55](../../../spec/C55-methodology-experiment.md).

## 1. Verdict

**`accept-with-named-amendments`.**

The macro-shape — *calibrate the instrument → one trustworthy nail → production line* — is correct and well-grounded: it respects the real dependency graph (Gas City conformance is the literal first action per [the build order §"The whole product rests on the conformance check"](../../../implementation-dependencies.md#gas-city--gc-binary-mit)), it puts the eval tier (the named "hinge of the whole build", [build order §products](../../../implementation-dependencies.md#the-backbone-25-components-but-only-seven-products-to-build)) ahead of any trust claim, and it uses C55 correctly as *horizon* not *now*. But the **calibration gate (Gate 1) has a sample-provenance gap** that makes its stated exit unreachable in the order given, and two gate hand-offs need tightening. The shape ships; the seams do not yet close.

## 2. Top 3 named amendments

**A1 — Gate 1's calibration sample has no source of trajectories (the load-bearing gate is built on nothing).**
*Problem:* Gate 1 requires "a small fixed set of trajectories with human-authored ground-truth root-cause labels spanning **all five corners** (`judge/spec/scenario/system/none`)" ([§Gate 1](../10-unified-plan.md)). But Gate 1 sits *before* Gate 3, the first real build — so at Gate 1 the factory has produced exactly one trajectory (the B22 design draft from Gate 0). You cannot author trajectories that exhibit a *`system` defect* or a *`scenario` defect* without builds that produced them. *Cited fact:* the C32 acceptance tests the plan leans on (AC-C32-16..23) each presuppose a *run that scored scenarios* — e.g. [AC-C32-17 "Given a scenario fails… root_cause = system"](../../../spec/C32-judge-harness.md) requires a built, failing system. *Fix:* either (a) seed the calibration sample with **synthetic/replayed trajectories** (corpus-authored fixtures, explicitly labelled as fixtures, not live builds) and say so, or (b) split Gate 1 into **1a (design the sample + harness, pre-build)** and **1b (populate + measure, after Gate 3 yields real trajectories)**, leaving `oversight_level = full` in the interim. As written the exit ("a recorded false-green rate") is not earnable at this point in the order.

**A2 — Gate 1 and Gate 2 both depend on the same eval-tier substrate; their relative order is asserted, not argued.**
*Problem:* The plan orders calibration (Gate 1) strictly before holdout-integrity (Gate 2). *Cited fact:* per [the build order, C34 holdout integrity depends on the eval tier (C30/C32) and lands *with* it](../../../implementation-dependencies.md#the-remaining-custom-products), and "until twins exist it *detects and audits* violations rather than preventing them" ([build order §fence](../../../implementation-dependencies.md#build-order-across-products)). Holdout integrity is *logically prior* to calibration: if the agent can teach to the test, the scenarios feeding the calibration sample are themselves compromised, so a "calibrated judge" measured over leakable scenarios is calibrated against a lie. *Fix:* run the **leak probe (Gate 2) before or concurrently with Gate 1's measurement**, or state explicitly why calibration-on-possibly-leaked-scenarios is acceptable as an interim. Right now Gate 2's exit (holdout verdict) feeds nothing back into Gate 1, yet Gate 1's validity assumes it.

**A3 — Gate 3's exit asserts `tri_alignment = aligned` as a go-term, but Gate 1 may not have licensed trust in it.**
*Problem:* Gate 3 lists the "four conjunctive C53 terms" including `tri_alignment = aligned` ([§Gate 3](../10-unified-plan.md)). *Cited fact:* per [C53 §3.2 the four-term gate is correct](../../../spec/C53-bootstrap-validation.md), and `tri_alignment` is a *binding conjunctive term* — but [C53 §3.3 pins `judge_self_trust = uncalibrated` → forces `oversight_level = full`](../../../spec/C53-bootstrap-validation.md), and the 100% floor + tri-alignment *still bind even when uncalibrated*. The plan's own [§Gate 1 exit](../10-unified-plan.md) says tri_alignment is "advisory only" until the bar clears. These two statements collide: at Gate 3, is `tri_alignment` a *binding go-term* (C53) or *advisory* (the plan)? *Fix:* reconcile — state that Gate 3's `tri_alignment` term is *evaluated and recorded but its weight is governed by the Gate-1 trust level*, with the human-approve term carrying deploy authority while uncalibrated. The plan gestures at this in §3 but the Gate-3 exit text doesn't encode it.

## 3. The single thing the plan gets most wrong

**Gate 1's all-five-corners calibration sample is unbuildable at the point it is gated** (Amendment A1). This is the load-bearing gate by the plan's own framing — everything downstream trusts `root_cause` only because Gate 1 measured it — yet a `system`-corner or `scenario`-corner labelled trajectory cannot exist before a real build has run and failed, which is Gate 3. The plan inverts a true dependency: *you need builds to calibrate the judge that judges the builds.* It is fixable (synthetic fixtures, or split the gate), but as written the macro-claim "we earn the green light before we read it" ([§0](../10-unified-plan.md)) is not literally achievable in the stated order.

## 4. What the plan gets right that must be preserved

- **Treating calibration as a precondition *gate*, not a smoke-test folded into the first build.** This correctly honours that the backbone ships the judge `uncalibrated` and defers PF-2 to C46 *outside the backbone* ([C32 OQ6](../../../spec/C32-judge-harness.md)) — the plan consumes that seam minimally instead of pretending it's closed. This is the single most architecturally honest move in the document; do not let any "go faster" amendment collapse it back into Gate 3.
- **C55 used as horizon, not now.** The plan places methodology-as-config in [§4 longer horizon](../10-unified-plan.md), matching [C55 §2 "Phase 3 … post-Phase-2 work"](../../../spec/C55-methodology-experiment.md) and the brief's "GF-M first = first *experiment*, not the winner" ([brief §A4](../00-grounding-and-exemplar.md)). Correctly resisted as a week-1 distraction.
