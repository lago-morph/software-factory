# Future Enhancements Bucket

Deliberately deferred capabilities — not Phase-0/foundation scope, parked here by explicit decision so
the spec/plan stay honest about what is in vs out. Each item records why it was deferred and what would
trigger pulling it back in.

| ID | Enhancement | Deferred from | Decision / trigger to revisit |
|----|-------------|---------------|-------------------------------|
| FE-1 | **Cross-provider / cross-family judge** — judge model from a different provider-family than the coder, for independence against shared-model blind spots. | C29 model-floor, C32 judge-harness, C34 holdout-integrity | Decision D-1 (user, 2026-05-30): Phase-0 judge uses the **same provider** as the coder; holdout integrity comes from rig partitioning + role/prompt isolation. Revisit when a second-provider credential path exists (Max issues no second key today) or when same-family judge bias is measured as material. |
| FE-2 | **Substrate portability contracts** — thin typed interfaces (`RuntimeSubstrate`/`SessionProvider`/`TrajectoryStore`/`EventBus`/`AgentLoopProvider`) over Gas City / CXDB / Claude Code, so a future re-platform is a swap behind one interface rather than a rewrite. | C01/C04/C21/C23/C28 DELTA-01 (Track B / "Bet 1") | Decision (user, 2026-05-31): build directly on Gas City and accept lock-in for velocity. Skeptic flagged this as the **weakest-justified** delta cluster — the port may be too thick to be real portability (documents lock-in rather than removing it). Revisit only when a concrete second-vendor plan actually exists. Grounding: [`optimized-deltas-force-skeptic.md`](research/optimized-deltas-force-skeptic.md). |
| FE-3 | **Graduated-mandatory signing + per-actor key model** — signing flips from optional (v4 P9) to config-tiered default-on for cross-boundary/Mail actions; per-actor keypairs minted at registration, with rotation/revocation. | C41 DELTA-01/06 (Track B / "Bet 2") | Decision (user, 2026-05-31): defer. It is a greenfield bolt-on — Gas City has **no** intra-rig actor signing (the gastownhall/wasteland GPG model is *inter*-rig federation across operators, a different problem). Threat model (mail-injection, attribution forgery) is enterprise/multi-tenant; marginal for a single-operator factory. Also blocked on G37 (no secrets store; plaintext keys make signing theater). Revisit at multi-operator/multi-tenant scale or for RSI hardening, **and** only after G37 is chosen. |
| FE-4 | **Multi-seat / seat-pool automation** — a pool of N Max seats (+ optional Agent-SDK credit / metered-API) behind one scheduler with admission control, a seat ledger, back-pressure, and per-seat rate-limit state. | C28 DELTA-03 (Track B / "Bet 4") | Decision (user, 2026-05-31): this version uses **Max only**, with eyeball-managed concurrency. Spawning N concurrent sessions is already native to Gas City's `runtime.Provider`; a seat-aware *scheduler* is not (and is not in v4). Blocked on Max ToS clarity for pooled unattended automation. Revisit when concurrency outgrows manual management and the ToS question is settled. |
| FE-5 | **Enumerated per-criterion Definition-of-Done in the spec artifact** — a `DoD` with stable per-criterion IDs that satisfaction scoring (P5/P6) reads, instead of free-form prose. | C08 DELTA-03 (Track B); survivor-pass apply | Decision (survivor-pass apply, 2026-05-31): a real P5 capability, but its consumers C32 (judge harness) and C33 (satisfaction metric) are among the unbuilt 34 — defining the DoD interface now gets ahead of the consumer. Decide **where** enumerated criteria live (in the spec vs alongside) when C32/C33 are authored. Does **not** require C08's standalone-bundle split (dropped); a DoD can attach to the Reading-A collapsed spec. |

> Builders for C29/C32/C34 MUST treat cross-family judging as FE-1 (out of foundation scope) and spec the
> same-provider judge as the baseline, while leaving a clean seam (a `judge_family` policy hook) so FE-1
> can be switched on later without re-architecture.
