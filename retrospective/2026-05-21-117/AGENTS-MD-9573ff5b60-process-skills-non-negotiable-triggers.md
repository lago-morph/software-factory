# agent instruction

**Process skills — non-negotiable triggers.** Certain skills govern conventions that must fire on every interaction with a class of tool surface, regardless of the user's stated task. Load them the first time their gated tool surface comes up in a session, not after. The current process skills are: `issue-management` (gates `mcp__github__issue_*`, `add_issue_comment`, `list_issues`, `search_issues`, `sub_issue_write`, and any reference to an issue number in a commit, PR, or plan doc); `always-commit-skill-to-repo` (gates `git commit`, `git push`, and the PR-write MCP tools); `in-flight-workflow-tracking` (gates long-running dispatch — subagent fanout, PR-activity subscription, fetch-blocked-urls issue creation). Carve-outs like "I'm only reading" or "I'll load it when I actually do something" are not valid. When a prompt triggers more than one skill (e.g. "fix issue 105 — ingest a source" hits both `research-pipeline` and `issue-management`), load all of them, not the most salient one.

*Grounded in: PR #116, where "fix issue 105" loaded `research-pipeline` for the source-ingestion content but skipped `issue-management` until the user pointed it out, leaving the STARTED claim and PR-OPENED comment unposted on the issue.*

# justification

The PR #116 session opened with "Fix issue 105." The issue body was about source ingestion, so I loaded `research-pipeline` and went straight to catalog work. Every `mcp__github__issue_read` and `mcp__github__add_issue_comment` call after that happened without `issue-management` ever being loaded — the STARTED claim, the `good first issue` label, the per-event comments. The user caught this one turn before the PR opened. Backfilling cost ~5 minutes of tool calls and a "Posted retroactively" preamble on every comment. The next slip in a less-attentive review window costs the audit trail entirely.

The cause is what the user named in chat: salience collapse. When a prompt names a vivid work-content trigger (source ingestion, fetch, drain, fanout), the process skill that governs the meta-activity (issue interaction, git ops, long-running dispatch) gets drowned out. The fix is mechanical at the gate level (PR #117 ships the `issue-management` PreToolUse gate that hard-blocks this exact mistake), but the doc rule belongs in `AGENTS.md` so it lands in front of the agent at session start regardless of which skills get auto-loaded. The marginal cost of the rule is zero — readers already scan AGENTS.md. The cost of skipping it is the slip we just experienced, recurring quietly in every session that hasn't yet picked up the gate.
