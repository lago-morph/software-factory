# agent instruction

**Distinguish "I disagree" from "I see a gap in your premise."** When asked to push back, first identify whether the disagreement is substantive (different position) or framing (user's position is fine but missing a piece). Defensive pushback wastes a turn; gap-surfacing moves the conversation forward.

*Grounded in: pushback on "methodology drives" used "designed system not commodity" defensively; user immediately reframed to the actual issue (buildability).*

# justification

When the user invited pushback on the methodology-over-substrate orientation, the response was a defensive pushback: "some substrate primitives like CodebaseModel are designed systems, not commodity infrastructure." The user immediately reframed to the actual gap: the issue is that substrate-track agents handwave construction paths, not that some primitives are designed systems. The defensive framing wasted a turn. The right pushback would have been: "your principle is good; the gap is that substrate tracks aren't producing construction paths; without those, the principle can't be evaluated." That framing leads directly to the buildability rule the session ended up adopting. The cost of a defensive turn vs. a gap-surfacing turn is one conversational round-trip — small per instance, large across a session that warns about context limits.
