An artifact with zero FCs cannot compound. Verdict: `designed-system`.
- **[P-33 — Opposing-side router](../primitives/P-33-opposing-side-router.md).** Provider-property-driven router that consumes an FC + artifact handle and returns the resolved opposing-side handler. Honors Attractor's *do-not-unify* discipline via unconditional builder-family denylist. Verdict: `designed-system`. Shares substantial substrate with P-14 (LiteLLM `Router`, model-family taxonomy, tag-based routing) but with FC-shaped surface, unconditional builder-family exclusion, and broader handler universe; same-vs-distinct deferred to Phase 4.2.
- **[P-29 — Policy mediator](../primitives/P-29-policy-mediator.md), compounding-gate variant.** Refuses to expose artifact A downstream unless A's declared FC has `verdict.outcome ∈ {survived, conditionally-survived-with-window}` AND (when conditionally) the cycle is inside the declared `survival-window`. Structural replacement for voluntary review (F53) and D-4 holdout discipline at every artifact boundary. Verdict: `designed-system`.
- **[P-34 — Independence auditor](../primitives/P-34-independence-auditor.md).** Patrol-tier deterministic anomaly detector over the FC log; flags collusion (binomial test) and correlation (Fisher exact, IsolationForest) patterns. Verdict: **research-grade-uncertainty** (structural; construction itself is designed-system) — see §2.
- **[P-30 — Event registrar](../primitives/P-30-event-registrar.md), survival-window-registrar variant.** Typed event-state-machine over FC lifecycle (`FC-declared → opposing-side-running → verdict-rendered → survival-window-open → window-expired → re-falsification-required`). Wakes dependent-FC graphs when a parent's survival window expires. Verdict: `designed-system`.

## §3 Candidate-specific contracts on each primitive

D7-U-1 references three contested primitives (P-28, P-29, P-30) and two D7-U-1-named primitives (P-33, P-34). Fixed sub-section headers per the contested-primitive convention follow.

**P-28 FC store — `envelope schema:`** D7-U-1's envelope is *commitment-indexed rather than artifact-indexed* (per [P-28 sketch §"D7-U-1 FC envelope"](../primitives/P-28-typed-object-store.md)). Fields: `id`, `artifact` (content-addressed handle), `artifact-kind` ∈ {spec, plan, code-change, eval, adr, skill, classifier-decision, scaffold-edit}, `conjecture` (declared claim about the artifact), `opposing-side.{kind, identity, independence-evidence}`, `refutation-attempt.{budget, method, inputs[]}`, `verdict.{outcome ∈ {survived, refuted, inconclusive, budget-exhausted}, counter-evidence[], survival-window}`, `ledger.{immutable-log-ref, trajectory-ref}`. The typed filter is keyed on `artifact-kind × verdict.outcome`; the compounding gate (P-29 D7-U-1 variant) consumes this filter to refuse downstream exposure of any artifact lacking a `survived` FC.

**P-29 compounding gate — `policy DSL:`** Rego/Cedar policy expressing the FC-survival vocabulary (per [P-29 sketch §"D7-U-1 compounding gate"](../primitives/P-29-policy-mediator.md)): artifact A is available as input to artifact B iff A's matching FC in the P-28 FC store has `verdict.outcome ∈ {survived, conditionally-survived-with-window}` AND (when conditionally) the current cycle index is still inside the declared `survival-window`. The policy walks the FC ledger entries (loaded as `data.fc_ledger`) and returns `allow` only on a survived-FC match. Design content is the FC-survival vocabulary and the interaction between `survival-window` expiry and re-falsification triggers from the opposing-side router.

**P-30 survival-window registrar — `state-machine semantics:`** Per [P-30 sketch §"D7-U-1 (survival-window registrar)"](../primitives/P-30-event-registrar.md): `FC-declared → opposing-side-running → verdict-rendered (survived | refuted | inconclusive | budget-exhausted) → survival-window-open → window-expired → re-falsification-required`. The timer half is load-bearing in a way U-A's re-entry variant is not — the registrar must wake dependent-FC graphs when a parent's `survival-window` expires, flagging every downstream artifact that depended on the expired verdict. Subscribers: compounding gate (refuses past-window artifacts), independence auditor (monitors verdict-distribution drift), FC store (marks expired FCs for re-run).

**P-33 opposing-side router.** Contract per [P-33 sketch](../primitives/P-33-opposing-side-router.md): consumes `FC.artifact-kind × FC.refutation-attempt.method × builder.family`; queries the capability registry; for LLM-judge classes calls LiteLLM with `tags=["exclude:" + builder.family]`; for deterministic/human/vote classes returns the registered binary/identity/pool. Three-layer denylist (call-time computed denylist + LiteLLM tag-exclusion + registry family-allowlists) plus a P-29 post-hoc check enforces Attractor's *do-not-unify*. Shares substrate with P-14 (same-vs-distinct deferred to Phase 4.2).

**P-34 independence auditor.** Construction per [P-34 sketch](../primitives/P-34-independence-auditor.md): scipy `binomtest` (per opposing-side × artifact-kind collusion test) + Fisher exact (per opposing-side-pair correlation test) + IsolationForest (cycle-feature outlier sweep). A+C hybrid recommendation noted in §2 above; structural recursion concern is the load-bearing residual.

## §4 X_UNM_B articulation

Per the [X_UNM_B finding](../candidate-registry.md#u-a--escrow-graph-factory-cycle--directed-graph-of-typed-nodes), D7-U-1 addresses Codebase-Model acquisition from legacy artifacts as follows:

- **Source artifact:** for brownfield deployments, D7-U-1 inherits a *rich initial FC catalog* directly from legacy artifacts (per [D7-U-1 §1 "How the same architecture serves both mandates"](../bias-guards/phase-3/d7-blind-axis/d7-u-1-prohibit-interval-escrow.md#1-architecture-sketch)): existing test suites are FCs whose opposing side is the test runner; production telemetry is an FC opposing-side for runtime behaviour; the type system is a deterministic-checker FC; the dependency graph and live users are opposing sides on integration-level conjectures. For greenfield, the initial FC catalog is sparse with operator-as-opposing-side at day-0.
- **Extraction primitive:** no new extraction primitive is required when these existing artifacts are present — existing tests + telemetry + type-checks *become* FC catalog entries through wrapper FCs that re-classify their existing pass/fail signal as a `verdict.outcome` against an inferred `conjecture`. The wrapper itself is a P-28 envelope-population step on top of the legacy artifacts.
- **Completeness gap:** legacy systems without test coverage and without typed APIs cannot bootstrap an FC catalog from artifacts; these deployments degrade to the greenfield-like bootstrap pattern (operator-attested FC entries on intent / architecture-sketch / spec artifacts). D7-U-1 does *not* reconstruct P-26's 6 views — the FC catalog substitutes for the Codebase-Model role for falsification-gating purposes, but does not provide structural/conventional/historical/runtime/invariant/debt query surfaces a methodology needing P-26 would expect.
- **Fallback if missing:** operator-as-opposing-side bootstrap until artifact-derived FCs reach critical mass; day-0 FC defaults are strictest (every artifact-kind requires minimum two opposing sides; operator-as-opposing-side mandatory on intent / architecture-sketch FCs; survival-window defaults to single-cycle) per [D7-U-1 §5 "Cold-start"](../bias-guards/phase-3/d7-blind-axis/d7-u-1-prohibit-interval-escrow.md#5-cold-start).
