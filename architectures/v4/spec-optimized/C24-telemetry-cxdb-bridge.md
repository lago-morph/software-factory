## 1. Purpose & responsibility

C24 is **the ingestion bridge that turns raw factory telemetry into CXDB turns** — the standalone, supervised tool-node service that *reads* conversation-shaped telemetry (Claude Code's `OTEL_LOG_RAW_API_BODIES` raw request/response bodies, and — DELTA-01 — the C23 event-bus stream) and *posts* each record into C21 (CXDB) as an idempotent, parent-chained turn. It is the **seam component**: its entire reason to exist is to *define and own* the delivery, ordering, back-pressure, and parent-mapping contract between the telemetry producers (C28/C25) and the trajectory store (C21) that v4 left unspecified (G26). It is named an `interface` in the inventory precisely because the bridge *is* the contract.

Concretely C24 owns five capabilities:

1. **Source adapters (DELTA-01).** A `BodyWatcher` over the `OTEL_LOG_RAW_API_BODIES` inbox dir, and a `BusTailer` over C23's `Tail(stream)` cursor — two adapters normalising into one internal `IngestRecord`.
2. **Idempotent posting (DELTA-02).** Post each `IngestRecord` to C21 `AppendTurn` with retry; rely on C21's content+parent dedup so at-least-once delivery never duplicates a turn.
3. **Durable client-side spool + cursor (DELTA-03).** A crash-survivable watermark so a body/event is acked only after CXDB confirms its turn — the raw-bodies path's durability story, which C21/C23 explicitly delegate here.
4. **Parent-chain construction (DELTA-04).** The `session.id → head TurnRef` table that gives each posted turn its `parent_ref`, reconstructing the conversation DAG from a flat directory of bodies.
5. **Readiness/partial-file protocol (DELTA-05).** Only-ingest-complete-files, quarantine-on-parse-failure, so torn writes never corrupt a trajectory.

What C24 is **NOT**:
- **Not** the trajectory store (C21). C24 is a *client* of C21's ingest contract; it stores nothing canonical — its only durable state is the spool/cursor/head-table needed to deliver reliably. C21 owns dedup, branching, and the turn-DAG; C24 owns *getting records there exactly-effectively-once*.
- **Not** the event bus (C23). C24 *reads* C23 (DELTA-01 BusTailer) as one source; it does not produce or order the bus. C23's `seq` is authoritative ordering for the bus-sourced class.
- **Not** the telemetry exporter (C25). C25 owns the OTLP pipeline and the `OTEL_LOG_RAW_API_BODIES` env-var configuration that *produces* the inbox files; C24 only *consumes* the directory. C25↔C24 meet at the inbox dir contract (filename/atomicity).
- **Not** the type registry (C22). C24 maps each record to a `{bundle_id,type,version}` triple, but C22 owns what the triple means; the mapping table is pinned at the C24/C22 seam to D-2's namespace.
- **Not** an OTLP→CXDB translator. v4 explicitly skips the OTLP path (highest impedance, span-tree→turn-DAG mismatch, AI-CONTEXT §5.4, §11). C24 ingests *raw bodies* (conversation-shaped) and *event-bus records*, never OTel spans.
- **Not** the model-floor/router (C29) or agent loop (C28). C24 has no opinion on what produced the telemetry; it bridges whatever lands.

- **Downstream consumers (of the turns C24 lands):** **C21** readers — **C36** (numeric anomaly), **C37** (trajectory clustering), **C38** (diagnosis Healer), **C49** (counterfactual replay), **C46** (meta-metric stream, which the inventory lists as depending on C24). These never call C24; they read C21. C24's correctness is load-bearing for *their* input completeness.

It is **NOT foundational** (Batch 2, "observability ingest" alongside C25/C26/C27) — it builds against the *frozen* C21/C23/C28 contracts. ## 3. Interfaces / contracts

Named-and-described (sweep 1; concrete wire schemas, the inbox-filename grammar, the spool-cursor on-disk format, and the conformance suite in sweep 2). C24 is offered as a pack-declared supervised service (DELTA-06) exposing a control/health surface to C01 and consuming three external contracts (inbox dir, C23 cursor, C21 ingest).

**Inbound — telemetry sources (C24 reads):**
- **`BodyWatcher(inbox_dir)` (DELTA-01, DELTA-05):** watches `OTEL_LOG_RAW_API_BODIES=file:<dir>` for *complete* body files (readiness protocol DELTA-05). Each ready file → parse → `IngestRecord{ source=raw-body, session_id, ordinal, correlation_attrs, request_body, response_body }`. Pre: file is signalled-complete; Post: file is either acked-and-archived (after CXDB ack) or quarantined (parse failure).
- **`BusTailer(stream, from_cursor)` (DELTA-01):** `Tail`s C23 from C24's durable consumer cursor (C23 §3 `Cursor`/`Commit`, consumer_id=`cxdb-bridge`). Each event → `IngestRecord{ source=event-bus, event_id=(stream,seq), actor, type, payload }`. Ordering authority = C23 `seq`. At-least-once per C23 DELTA-03.

**Outbound — post to CXDB (C24 calls C21):**
- `AppendTurn(parent_ref, typed_payload, attribution) → TurnRef` (C21 §3). C24 supplies `parent_ref` from the head-table (DELTA-04 for raw bodies) or from the bus record's trajectory pointer; `typed_payload` carries the `{bundle_id,type,version}` triple (DELTA-06, D-2 namespace); `attribution.created_by` from correlation attrs / bus `actor` (NOT part of C21's dedup key — C21 DELTA-02). **Idempotency invariant (DELTA-02):** C24 may retry/replay the *same logical* `AppendTurn` freely; C21 returns the existing `TurnRef`, never a duplicate. **Back-pressure invariant (DELTA-03):** on `BUSY`/`UNAVAILABLE`, C24 does NOT advance its cursor and does NOT delete the source body — it retries with backoff; the run is never blocked because C24 is off the agent's hot path (it reads *after-the-fact* telemetry).

**Outbound — health/control (C24 → C01, DELTA-06):**
- `Health() → { inbox_depth, spool_depth, bus_lag = head−committed, last_ack_ts, post_error_rate, quarantine_count }` — surfaces the bounded-degradation signals (G33). A growing `inbox_depth`/`bus_lag` with stalled `last_ack_ts` is the "CXDB-down, bridge-backed-up" alarm.
- Lifecycle: `Start/Stop/Drain` under C01 supervision (a long-lived service, not a finite tool bead).

**Invariants:**
- **At-least-once + idempotent (DELTA-02):** every record is posted ≥1 time; duplicates are harmless because C21 dedups on content+parent. No exactly-once attempted over the wire.
- **Ack-before-release (DELTA-03):** a raw body file is archived/deleted, and the bus cursor advanced, *only after* C21 acks the corresponding turn. ⇒ no loss on C24 crash mid-post.
- **Parent-chain well-formed (DELTA-04):** every raw-body turn has a `parent_ref` equal to its session's prior head (or genesis); the per-session head advances monotonically in export order. The bus-sourced class's parent linkage comes from the bus record (already trajectory-shaped, AI-CONTEXT §5.4).
- **Complete-files-only (DELTA-05):** a torn/partial body file is never posted; parse failures are quarantined, observable, and bounded.
- **Single-canonical-path per event class (DELTA-01, resolves G27):** an event class is ingested by *exactly one* source adapter; the two adapters never both post the same logical record (no cross-path duplication that even C21 idempotency couldn't catch, since raw-body and bus records hash differently).
- **Off-the-hot-path:** C24 consumes after-the-fact telemetry; its slowness/outage degrades trajectory *freshness*, never the agent run's progress (the G33 blast-radius bound).

## 4. Data model / state

C24 owns only the *minimal durable state needed to deliver reliably* — it is a bridge, not a store. The canonical trajectory lives in C21.

- **Spool / source cursors (DELTA-03):**
  - Raw-body path: a durable record per inbox file of `{ filename, ordinal, session_id, state ∈ {ready, posting, acked, quarantined}, turn_ref?, attempts, last_error? }`. Acked files are archived (moved out of the inbox) or deleted per retention; the cursor is the set of not-yet-acked files.
  - Bus path: a single durable `committed_seq` per tailed stream (delegated to / co-owned with C23's `Cursor(consumer_id=cxdb-bridge)` per C23 OQ5 — see Open Questions).
- **Session head table (DELTA-04):** `session.id → { head_turn_ref, last_ordinal }`, durable, so a C24 restart resumes parent-chaining correctly and a session that spans a restart does not re-root at genesis. Rebuildable from C21 (query last turn per `session.id`) on cold start if lost.
- **Type-mapping table (DELTA-06, C24/C22 seam):** a static, version-pinned map from `IngestRecord` kind → `{bundle_id,type,version}` under the **D-2** root `softwarefactory.v4.trajectory` (e.g. raw request/response → `softwarefactory.v4.trajectory:RawApiTurn`; bus record → `:EventBusRecord`; tool result → `:ToolResult`). C22 owns the schemas; C24 owns the *selection* rule.
- **Quarantine (DELTA-05):** parse-failed / unmappable files retained out-of-band with their error, for operator inspection; counted in `Health()`.
- **Storage layout:** plain files on C01's mount (`inbox/`, `archive/`, `quarantine/`, `cursor.db` or a small append-only cursor log) — mirrors the "no Postgres/Redis/Kafka" posture (AI-CONTEXT §5.3). No second store introduced.
- **Consistency model:** C24 holds *no* linearization authority. Ordering is delegated: bus class ⇒ C23 `seq`; raw-body class ⇒ Claude Code export order + filename ordinal (DELTA-04). A turn is "delivered" once C21 acks `AppendTurn`; until then the source record is retained (ack-before-release).

## 5. Behavior

Key flows (sweep 1 prose; sweep 2 = Mermaid sequence/state diagrams):

- **Raw-body ingest (happy path, the v4-built path):** C28 emits a request/response → OTel exporter writes a body file → producer signals complete (atomic rename / `.done`) → `BodyWatcher` picks it up → parse + extract `session.id`/correlation attrs → look up session head → `AppendTurn(parent=head, payload=RawApiTurn, created_by)` over C21 HTTP/JSON :9010 → on ack, advance the session head to the new `TurnRef`, mark the file `acked`, archive it. p-path latency is bounded by export interval + post, not by the agent loop.
- **Event-bus ingest (DELTA-01, the lowest-impedance path):** `BusTailer` reads C23 from `committed_seq` → for each event, map type → `AppendTurn` (the bus record is already attributed + ordered) → on ack, `Commit(seq)`. Because the bus is at-least-once (C23 DELTA-03) and C21 is idempotent (C21 DELTA-02), redelivery is harmless.
- **CXDB-down / back-pressure (DELTA-03, the G33 answer for the raw-bodies class):** C21 returns `UNAVAILABLE`/`BUSY` or is unreachable → posts fail → C24 does NOT advance any cursor, does NOT delete any body, retries with capped backoff. Inbox/spool depth grows (bounded by inbox retention + a `bridge-lag` alarm). The *agent run is unaffected* (C24 is off the hot path; the body files were already written by the exporter independently). On C21 recovery, C24 drains the spool in order; idempotency makes any partially-landed posts safe. Net: CXDB outage ⇒ trajectory *staleness*, never loss, never run-stall.
- **Partial / torn body file (DELTA-05):** a file appears but is mid-write → readiness protocol holds it (not yet renamed / not size-stable) → only the complete file is parsed. If a "complete" file still fails to parse (truncated upstream) → quarantine + increment `quarantine_count` + emit health signal; never post a half-record, never spin retrying it forever.
- **C24 crash / restart:** C01 supervises and restarts the service. On restart C24 reloads the spool + session-head table + bus cursor; files in `posting` state are re-posted (idempotent, so safe if the pre-crash post had actually landed); the bus tailer resumes from `committed_seq`. No loss (ack-before-release), no duplicate turns (C21 dedup).
- **Session resume / fork (DELTA-04):** a resumed `session.id` re-roots on its recorded head (table or C21 query); a Claude Code session-id collision or fork is handled by the head pointing at the correct prior turn — the parent-chain follows `session.id` per AI-CONTEXT §5.4. (Cross-session causal links beyond `session.id` are out of scope — OQ.)

## 7. Cross-cutting

- **Security:** raw API bodies contain *untruncated* request/response JSON (AI-CONTEXT §4.3) — the highest-sensitivity telemetry in the factory (secrets, holdout content, full prompts). The inbox dir + spool + archive are a leakage/holdout-integrity surface: C24 honors C01/C43 isolation on who may read the inbox and which `created_by`/bundle a record may be posted under; quarantined files (which may contain partial secrets) inherit the same isolation. Attribution (`created_by`) is recorded on every turn (P9) from correlation attrs / bus `actor`. Tamper-evidence of the landed turn is C21's (BLAKE3); in-flight bodies in the inbox are *not* yet content-addressed — a hardening flag (OQ).
- **Cost/scale:** the bus path is the cheap path (no file parse, already ordered/attributed) — DELTA-01's partition pushes everything it can onto it. Raw-body throughput is bounded by Claude Code export intervals (metrics 60s / logs 5s, AI-CONTEXT §4.3) and CXDB :9010 ingest; sweep-2 sizes C24's post rate against C21's :9009/:9010 ceiling (C21 OQ4 perf contract is provisional, so C24's sizing inherits that provisionality). Dedup is C21's lever, not C24's.
- **Observability:** C24's own health (`inbox_depth`, `spool_depth`, `bus_lag`, `post_error_rate`, `quarantine_count`, `last_ack_ts`) surfaces to C01 `Health()` so the loop can *see* the bridge backing up — the bounded-degradation signal for G33. C36 can read bridge-lag as a cheap numeric anomaly.
- **Ops:** C24 is a pack-declared **supervised long-lived service** (DELTA-06), version-pinned binary, transfusing the `internal/sessionlog` parse pattern as a standalone binary (no Go import, AI-CONTEXT §5.4). Two runtime contracts: continuous back-pressure-safe draining (DELTA-03) and inbox/archive retention (bounded disk). Recovery contract is spool-reload + idempotent re-post on restart. The `OTEL_LOG_RAW_API_BODIES=file:<dir>` path is configured by C25/`city.toml` (AI-CONTEXT §579); C24 only consumes the dir.

## 8. Acceptance criteria & test strategy

1. **Idempotent at-least-once (DELTA-02):** force C24 to post the same logical raw body N times (crash between post and ack) → C21 holds exactly one turn, one `TurnRef`; zero duplicate turns. Joint test with C21 acceptance #2.
2. **Ack-before-release / no loss (DELTA-03):** `kill -9` C24 mid-post → on restart the in-flight body is re-posted and lands; no body is deleted/archived without a C21 ack; zero records lost across the crash.
3. **CXDB-down back-pressure (DELTA-03, G33):** stop C21 mid-run → agent run continues unaffected; C24 posts fail, spool/inbox depth grows, `last_ack_ts` stalls, `bridge-lag` alarm fires, zero loss; restart C21 → C24 drains the full backlog in order with zero duplicate turns. Joint with C21 acceptance #4.
4. **Parent-chain correctness (DELTA-04):** ingest a multi-turn session's bodies out of file-arrival order → the resulting C21 turn-DAG has each turn's `parent_ref` equal to the prior turn in *export* order (not arrival/wall-clock order); a new `session.id` roots at genesis; a resumed session re-roots on its recorded head.
5. **Dual-path partition, no double-ingest (DELTA-01, G27):** drive both adapters with overlapping-looking data of the canonically-partitioned classes → each logical record lands exactly once; no class is ingested by both adapters; the canonical-path-per-class rule is enforced (a misrouted record is rejected, not double-posted).
6. **Partial-file safety (DELTA-05):** write a body file slowly (mid-write visible in the dir) → C24 does not parse it until complete; inject a truncated "complete" file → it is quarantined (counted, not posted, not infinite-retried), and a valid file behind it still ingests.
7. **Type mapping pinned to D-2 (DELTA-06):** every posted turn carries a `{bundle_id,type,version}` under `softwarefactory.v4.trajectory` registrable in C22; an unmapped record kind is quarantined with a clear error, not posted under a guessed type.
8. **Supervised-service lifecycle (DELTA-06):** C24 starts/stops/drains under C01 supervision as a long-lived service; `Drain` flushes the spool before stop; restart resumes the spool + head table + bus cursor with no loss/dup.
9. **Off-hot-path proof:** measured agent-run progress (turn latency) is independent of C24 state (running, stalled, or down) — proving the bridge can never block the factory.
