## 2. Dependency graph

Critical path: **C08 spec format + C51 predicate contracts (D-40-aligned) + C20 `factory_build` schema (D-40 status slot) + C32 DiagnosisRecord (D-43 frozen schema) → T1 → T2 → T3 → T4 (mandatory gate) → T10 (repair router) → T5 (deploy)**.

- **T1 is the controller spine:** reuses the *existing* C12/C13/C28 flow — does **not** wait on a new engine; only on those components' seams existing.
- **T2** needs **C51's predicate contracts** frozen: both the declaration-time interface (`check_declaration`) and the acceptance-time interface (`can_transfuse → TransfusionVerdict`), including the `TransfusionInsufficient` signal (C51 §3.0/§3.0.3). C51 is the hard upstream making factory-builds-factory acceptance-gated.
- **T3** cannot advance `status` until **C20's** `factory_build` schema is frozen with the **D-40 status slot** (`in_progress → completed` enum) and the `gate_decision` field slot (C20 slot-request). Also needs C19/C41.
- **T4 (the keystone gate)** joins C51's verdict (T2), C53's rubric-result (T6), and C56's level. C53 and C56 are **Batch-4, unbuilt** — T4 builds against **stubs** and freezes the *consumption seams* now (so C53/C56 can build their producing sides against stable C52 gate interfaces).
- **T7 (resume, D-40)** keys off T3's lifecycle fields (the D-40 status slot) + C20's resume-completeness invariant. Uses the **corrected D-40 query** (`--type factory_build --status in_progress`); must NOT use the legacy `--type factory_build_in_progress`.
- **T8** (BootstrapIntent validation) is gated on T1 and the C08/C54 seams.
- **Must precede C52:** C08 (format), C51 (predicate interfaces + D-40 alignment), C20 (lifecycle + D-40 status + gate_decision slots), C19/C41 (store + attribution), C12/C13/C28 build flow.
- **Soft/stubbed:** C53 (rubric seam — T6), C56 (autonomy-level seam — T4), C54 (sequencing — C52 is the per-component mechanism C54 orders).
- **Downstream of C52 (build after):** C53 (consumes the loop + gate seam), C54 (sequences the recursion), C56 (governs the gate's level). C52 must freeze its gate-input contract (§3.4) and lifecycle seam (§3.5) early so these three can build against stubs.

## 3. Parallelization

Three workstreams fan out once T1's controller skeleton + the upstream contracts (C51 verdict, C20 lifecycle + D-40 status slot) are frozen:

- **WS-A (recursion core):** T1 + T2 + T3 + T5 + T8 — author-spec → declare-transfusion → run-flow → write/advance `factory_build` bead (status: `in_progress → closed`) → deploy. Verifiable end-to-end against a **C51 predicate stub** + a **C20 `factory_build` schema stub (D-40 status)** + the existing build flow.
- **WS-B (the gate + repair router):** T4 + T6 + T10 — the mandatory design-review gate, its **C53 rubric-result** + **C56 autonomy-level** consumption seams, and the repair router that fires on the no-go branch. Built against **C53/C56/C32 stubs** (C53/C56 unbuilt; C32 DiagnosisRecord schema frozen by D-43 — read-only seam). Highest-risk seam: two unbuilt consumers + anti-gaming invariant (INVARIANT-AG). The *mandatory-ness* invariant (spec I2) is asserted independently of the rubric's content: test that `advance_to_closed` without an `approved` GateDecision raises `E-C52-04`. The anti-gaming invariant is asserted by: given any `route_repair` result with `independent_path=True`, verify the implementing worker is never invoked (AC-C52-17).
- **WS-C (resume, D-40):** T7 — the D-40-corrected `gc bd find --type factory_build --status in_progress` → recover → `gc converge resume` procedure, plus the `E-C52-02` escalation. Built against a **seeded `factory_build` fixture bead** (no need to wait for WS-A to produce a real in-progress build). Validates D-40 corrected query before any integration.
- **T9** (scope + D-40 + D-21 documentation) rides alongside all three.

The join point is a real self-build flowing **author → run → transfusion-pass → mandatory gate → `status=completed`**, with the resume path (WS-C) proven by interrupting that flow mid-build and continuing it.

## 4. Interfaces-first / contract milestones (freeze early)

1. **`factory_build` schema + D-40 status slot + gate_decision slot** (T3, T7) — depends on **C20's** frozen `factory_build` schema (D-3, D-40): the `status` enum (`in_progress | completed`), the `gate_decision` JSON slot (C20 slot-request from C52/C53, per D-40 "C53 records the go/no-go on the same bead"), and the resume fields (`transfused_from`, spec/scenario pointers, `workflow_handle`). **Freeze first** so WS-A writes correct status transitions and WS-C seeds a realistic D-40-conformant fixture bead. *(Also resolves XC-2: the cold-start query shape.)*
2. **C51 predicate-consumption contracts** (T2) — both interfaces: `check_declaration(exemplar_refs) -> DeclarationResult` (declaration-time) and `can_transfuse(exemplar_refs, spec_ref) -> TransfusionVerdict` (acceptance-time), including the `TransfusionInsufficient` signal (C51 §3.0/§3.0.3). Freeze so WS-A's acceptance step builds against C51's stub.
3. **Design-review-gate input contract** (T4) — the `submit_for_review` signature: (a) C51's `TransfusionVerdict`, (b) **C53's** `RubricResult` type (what C53's producing side must return — even just `{pass: bool, rubric_version: str}` as a stub), (c) **C56's** `AutonomyLevel` policy type. Freeze the *consumption seams* now (even against stubs) so C53 and C56 — both unbuilt and both *depending on C52* — can build their producing sides against a stable C52 gate interface. **This is the most consequential seam to freeze early: C53 + C56 are gated on it.**
4. **Self-targeted spec emission contract** (T1) — the C08-format spec instance (`packs/<id>/agents/<slug>/prompt.template.md`) C52 authors for the factory's own next component. Constrained by **C08's** format. Freeze the "factory authors its own spec" handoff so the build-flow dispatch (C12/C13/C28) is keyed off a real spec artifact.

## 5. Risks & de-risking order

1. **D-40 status-transition correctness (highest, T3/T7).** The Sweep-2 D-40 ruling resolves XC-2 and C52:OQ3 by mandating a STATUS TRANSITION (not a type-flip). Both T3 (`advance_to_closed`) and T7 (resume query) must be built against the D-40 corrected semantics. **First** freeze the C20 schema with the `status` slot + `gate_decision` slot, then assert the D-40 transition in AC-C52-06 before any integration with C53. De-risk: a failing AC-C52-06 is a C20 schema gap, not a C52 control-logic bug.
2. **The mandatory-gate seam onto two unbuilt consumers (OQ2 RESOLVED, still high construction risk).** T4's gate must consume **C53's** `RubricResult` and run at **C56's** `AutonomyLevel`, but **both are Batch-4 and unbuilt**. Freeze gate-input contract (milestone 3) first. De-risk the *mandatory-ness* invariant independently by testing that `advance_to_completed` without `approved` raises `E-C52-04` — the keystone safety property must hold even before C53's rubric content exists (AC-C52-04 negative test).
3. **D-40 resume query correction (T7).** AI-CONTEXT §16 hard-codes `gc bd find --type factory_build_in_progress`; D-40 changes this to `--type factory_build --status in_progress`. Prototype WS-C against a seeded fixture bead using the **corrected D-40 query early** — any Gas City substrate that doesn't support `--status` filtering is a G11 gap that surfaces immediately and safely in isolation (before it breaks the full recursion loop).
4. **G23 pass-bar discipline (OQ1 RESOLVED).** Do **not** invent a bar in C52; the C53 stub returns a typed `RubricResult` (even a trivial `{pass: true}` stub) so the seam exists. Confirm C53 owns the bar (review-log receipt T9).
5. **Resume-failure escalation (OQ4 RESOLVED, T7).** The `E-C52-02` escalation (operator gate before restart-from-spec; stranded bead preserved) is the resume failure contract. Prototype T7 with a **deliberately corrupted fixture bead** (missing `workflow_handle`) to confirm the escalation path fires before it can happen in production.
6. **F54 RSI drift discipline (OQ6 RESOLVED via D-21).** C52's mandatory gate reduces blast radius; it does NOT close F54. D-21 assigns the real drift detector to C57 (registered-unbuilt). Document this clearly in T9: the gate is one layer; C57's audit pack is the required second layer; they are NOT the same thing. Prevent the temptation to claim the gate alone covers RSI drift.
7. **Second-engine scope creep (T1).** Prototype T1 as a *dispatcher into the existing C12/C13/C28 flow* first. If any factory-self-build need cannot be met by the normal flow, surface it as a gap (not a fork of the engine).
8. **INVARIANT-AG enforcement in the repair router (T10).** The anti-gaming invariant must be a hard coded check in `route_repair`, not documentation alone. Risk: a fallback path inadvertently calls the implementing worker when `E-C52-09` fires (independent path unavailable). De-risk: assert AC-C52-17 with a negative test that injects an unavailable-independent-path scenario and verifies the worker is NOT called and `E-C52-09` is raised. Build T10 with the invariant check **before** wiring the correction seam stubs.
9. **DiagnosisRecord seam correctness (T10, D-43).** C52 reads the `DiagnosisRecord` schema frozen by C32 §3.2a. Any drift between C32's produced schema and the shape C52 parses for routing is a silent mis-route. De-risk: freeze the C52↔C32 `DiagnosisRecord` read-surface as a typed stub (not raw JSON) in T10; validate AC-C52-12 through AC-C52-19 against that stub before C32 lands.

## 6. Definition of done

- **Per spec ACs (sweep-2):** AC-C52-01 through AC-C52-19 all pass (see spec §9.1).
  - Keystone gate: **AC-C52-04** (gate non-bypassable — negative test; `advance_to_closed` without `approved` → `E-C52-04`).
  - D-40 + INT-2: **AC-C52-06** (same bead, `status=closed`, no type-flip) + **AC-C52-10** (query uses `--type factory_build --status in_progress`).
  - Resume: **AC-C52-07** (happy path) + **AC-C52-08** (escalation on missing `workflow_handle` → operator gate, stranded bead preserved).
  - Transfusion: **AC-C52-03** (zero-exemplar → `E-C52-03`) + **AC-C52-11** (fail → review-not-deploy).
  - Repair router (D-42/D-43): **AC-C52-12** (judge → recalibrate), **AC-C52-13** (system → polish, worker-only), **AC-C52-14** (scenario → independent correction), **AC-C52-15** (spec-localized → independent correction), **AC-C52-16** (spec-structural → discard + reimplement).
  - Anti-gaming keystone: **AC-C52-17** (INVARIANT-AG — any `independent_path=True` route MUST NOT invoke the implementing worker; treated as security violation if it does).
  - Attempt-exhaustion: **AC-C52-18** (`E-C52-08`; deferred-Phase-3 signal; bead not closed).
  - Unknown-attribution: **AC-C52-19** (`E-C52-07`; escalate rather than silently fall through).
- **Per-task DoD:** each task's artifact (recursion controller, lifecycle driver, gate, resume controller, error handlers) is exercised by at least one run of the recursion against the **small first-factory-built-component fixture** (README:431 candidates), and the **mandatory-gate** task additionally passes a negative test (deploy blocked when review unset — AC-C52-04).
- **Component DoD:** a real self-build flows **author C08 spec → declare transfusion (C51) → run the existing flow → `factory_build` bead (`status=in_progress`) → C51 predicate → mandatory human design review (at C56's level, against C53's rubric, gate owned by C52) → C32 `diagnose()` produces DiagnosisRecord → repair router fires on no-go / misaligned → appropriate route executed → (on eventual go + aligned) → `status=closed` (D-40 + INT-2 status transition on same bead) → component installed back into the factory**. The resume path is proven by interrupting that flow mid-build and continuing it via the D-40-corrected `gc bd find --type factory_build --status in_progress` → `gc converge resume <id>` procedure. The **OQ1/OQ2/OQ3/OQ4/OQ6 resolutions** are documented in `_meta/review-log.md` (T9); OQ7/OQ8 remain open. The two keystone safety invariants are both asserted by enforced negative tests: (a) **no factory-built component deploys without passing the mandatory design-review gate (`E-C52-04` blocks)** — AC-C52-04; (b) **no spec/scenario correction is executed by the implementing worker** (INVARIANT-AG — AC-C52-17).
- **Seams frozen for downstream:** the `submit_for_review` gate-input contract (§3.4), `advance_to_closed` status-advance contract (§3.5), and `route_repair` / `CorrectionRequest` seam stubs (§5.0.2/§5.0.5) are published for C53 + C56 + C08 + C30 to build against. The C52↔C20 D-40 status-transition seam is validated per AC-C52-06. The C52↔C32 DiagnosisRecord read-seam is validated per AC-C52-12 through AC-C52-16 against a C32 stub.
