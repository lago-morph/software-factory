## Part 4 — proposed ADRs

Architectural decisions made (or implicitly ratified) in this session that the user may want to record as ADRs. Titles only — use the `adr` skill to author any of these.

- **Modular skill layout: SKILL.md always loaded, `resources/*.md` loaded only when degraded paths are entered** — codifies the pattern this skill uses (and that `research-pipeline` uses for `scripts/`). Justified by: prompt-size pressure on the main file; recovery procedures are large and irrelevant 99% of the time.
- **`git format-patch` + tarball + `SendUserFile` as the canonical agent-session escape hatch when remote push is unavailable** — preserves commit metadata (vs. flattened diff), bundles atomically, and the harness file-surface mechanism is the only post-disconnect channel back to the user.
- **GitHub MCP auth health is a pre-condition, not a runtime concern, for any multi-step session work** — promotes auth checking from "deal with errors as they happen" to "verify at every boundary." This is the architectural shift the new skill institutionalizes.
- **Recovery commits stay in history; never rebase or amend them out** — they are the audit trail of session resilience events and must remain greppable for future retro-coverage audits.
