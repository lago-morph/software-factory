### Suggestion 1: Verify cross-artifact citations against source — `AGENTS-MD-d6fb69a1c8`

- **Per-rule file**: [./2026-05-25-151/AGENTS-MD-d6fb69a1c8-verify-cross-artifact-citations.md](./2026-05-25-151/AGENTS-MD-d6fb69a1c8-verify-cross-artifact-citations.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **Verify cross-artifact citations against source.** When a brief, decision document, plan, or any other authored artifact cites another artifact's conclusion or content, re-read the source artifact's actual text to verify the citation is accurate before treating the claim as load-bearing. Memory-driven or paraphrased citations are not acceptable for load-bearing claims; if a brief's argument hinges on what another document says, the citation must reflect what that document literally says.
>
> *Grounded in: auto-002 Round-1 misreading of the P-31 sketch.*

**Justification** (verbatim from the per-rule file's `# justification` section):

In the 2026-05-25 session, decision brief `auto-002` (U-B path at Phase 4 entry) Round 1 claimed that the corpus fragments GtWR / EARS / AILCCP "point at cross-layer invariants" — the implication being U-B could plausibly author the invariant catalog from corpus material in a bounded sub-track. The cited source, the P-31 cross-layer drift detector sketch, says exactly the opposite: those fragments are explicitly intra-layer, and the sketch was explicit that no source in the corpus authors per-layer-pair invariants. The brief's "plausible but bounded work" claim was load-bearing for the option-1 recommendation. Both real adversarial subagents in Round 1 caught the misreading — the cost-hawk reviewer demonstrated it by reading the source docs directly and finding only one trivial L2↔L3 referential-integrity invariant and zero non-trivial invariants for the other four layer-pairs. The misreading cost a full round of adversarial review (~80K tokens of subagent work) and triggered a complete decision reversal (from "full sub-track" to "smoke-test variant first"). The marginal cost of the rule is one extra Read call per load-bearing citation in a brief — a few hundred tokens at most. The asymmetry is overwhelming: pay a few hundred tokens at write time, or pay a full revision round at review time plus the risk that the misreading slips past review entirely if the user is unattended.

### Suggestion 2: PR descriptions are the user's review surface — `AGENTS-MD-4244c1aeda`

- **Per-rule file**: [./2026-05-25-151/AGENTS-MD-4244c1aeda-pr-descriptions-review-surface.md](./2026-05-25-151/AGENTS-MD-4244c1aeda-pr-descriptions-review-surface.md)

**Proposed agent instruction** (verbatim from the per-rule file's `# agent instruction` section):

> **PR descriptions are the user's review surface; write them substantively.** Reviewers (especially when the user is reviewing during morning hand-off of an unattended run) read PR descriptions, not code diffs. Every PR description must include: (a) Summary — 2-4 sentences naming what changed and why; (b) Key findings or decisions — specific bulleted list, not generic platitudes; (c) Rewind point — at least one named commit SHA to revert plus what each reversal undoes; (d) Test plan or acceptance criteria — a checkboxed list of what verification would look like; (e) Stacked-PR base notice when applicable, naming the parent PR and the auto-rebase behavior. Thin one-paragraph PR descriptions are forbidden.
>
> *Grounded in: user statement during 2026-05-25 review of the overnight chain (PRs #136-#145).*

**Justification** (verbatim from the per-rule file's `# justification` section):

The user reviewed the 10-PR overnight chain in PRs #136–#145 by reading PR descriptions in sequence and merging in order; they did not open file diffs. Their stated review style: "I do not review code in general. I review the PR descriptions." Under this review style, the PR description is functionally the entire change — anything missing from the description is invisible during review. Every chain merge proceeded based on the description's claims. This is also the failure mode behind unauthorized scope creep on long-running runs: if the description is bland, the reviewer can't detect that the PR did more or less than authorized. The marginal cost of the rule is a few minutes per PR (already paid in this session's chain — PRs #136–#145 all had this structure). The cost of omitting it is silent acceptance of unintended changes. The rule formalizes what worked in this session and prevents regression.
