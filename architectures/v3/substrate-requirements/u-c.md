**Candidate.** [U-C — Anchor-Distance Factory](../tracks/unified-C.md). Mandate: unified-attempt. Axis: distance-from-frozen-anchor — every work unit is parameterised by graph-distance to a load-bearing immutable anchor; the mandate is parameterised by the anchor's `kind`.

## §1 Primitive list (buildability-confirmed)

U-C requires five substrate primitives per [unified-C §1](../tracks/unified-C.md):

- **[P-28 — Typed-object store (content-addressed, append-only)](../primitives/P-28-typed-object-store.md).** U-C variant: the **AnchorObject** envelope (`kind` ∈ {intent-invariant, architecture-rule, standards-rule, live-test, runtime-trace}; `content`; `frozen-since`; `owning-mandate`; `mutation-protocol`). Load-bearing as the durable anchor catalog the distance estimator reads against. The same store carries the `anchor-edit` write surface (separate queue semantics described in §3). Verdict: `designed-system` (construction substrate is commodity; envelope schema is the design content).
- **[P-32 — Distance estimator (multi-component, typed)](../primitives/P-32-distance-estimator.md).** Computes `distance(work-unit, anchor-set) → DistanceTuple{graph_distance, pace_layer_crossings, intent_field_touches, contradiction_flag}`. Composes P-22 + P-23 for the structural leg, a deterministic decision table for the pace-layer leg, and a P-14-routed LLM judge for the implicit semantic-touch leg. Verdict: `designed-system` for construction; **partial RG on calibration + Goodhart-resistance** (see §2).
- **[P-19 — Eligibility / regime classifier (distance-gated dispatcher variant)](../primitives/P-19-eligibility-regime-classifier.md).** U-C names this the *distance-gated dispatcher*; the substrate is the same. Reads the P-32 DistanceTuple, applies thresholds `τ_low` / `τ_high`, and emits one of {near-anchor lights-out, mid-distance Augmentation, far-anchor / anchor-edit human-required}. Verdict: `designed-system`.
- **[P-28 — write surface for anchor mutation queue](../primitives/P-28-typed-object-store.md).** The anchor mutation queue is not a separate primitive — it is a typed-filter view over P-28 with `kind=anchor-edit` envelopes and a P-29-mediated approval policy enforcing the named-human L4 protocol. Covered by the P-28 AnchorObject envelope schema (§3).
- **[P-05 — Trajectory capture (distance-keyed variant)](../primitives/cluster-C2.md).** U-C's per-event trajectory log additionally appends the P-32 DistanceTuple at write time so Patrol-tier P-06 can monitor the empirical distance distribution for F47 Goodhart-gaming. Verdict: `commodity` (the distance-keyed variant adds one field at write; the storage substrate is unchanged).

The P-06 watchdog tier is named in U-C §1.5 but is consumed rather than owned (Patrol monitors the empirical distance distribution per [unified-C §1 primitive #5](../tracks/unified-C.md)); P-06 itself is commodity per [cluster-C2 § P-06](../primitives/cluster-C2.md) and is not double-counted here.

## §2 RG primitives

Per the [Phase-3.5.5 RG-primitive rule](../candidate-registry.md#phase-355-rule-on-load-bearing-rg-primitives-binding-user-approved-2026-05-25), U-C carries **partial RG flags on P-32 distance-estimator calibration + Goodhart-resistance** (not a full load-bearing RG primitive — calibration-style, not full unbuildability).

U-C does NOT appear in the [Phase-3.5.5 application table](../candidate-registry.md#phase-355-rule-on-load-bearing-rg-primitives-binding-user-approved-2026-05-25): that table catalogues full load-bearing RG primitives (P-31 for U-B, P-26 conventional/invariant views for BF-L, P-34 for D7-U-1). U-C's partial-RG is on sub-components of an otherwise `designed-system` primitive, matching the same shape as GF-S contradiction-detector reliability, GF-C 2-field substance-check, and BF-M brief-quality calibration (per [registry close §candidates with partial-RG flags](../candidate-registry.md#phase-355-close)).

- **Calibration partial-RG.** Per [P-32 § Calibration uncertainty](../primitives/P-32-distance-estimator.md): no corpus recipe maps `(graph_distance, pace_layer_crossings, intent_field_touches)` weights `(w_g, w_p, w_i)` and thresholds `(τ_low, τ_high)` to operator-meaningful risk. Plausible paths (historical-incident → distance-tuple regression; operator-rated calibration sample) need empirical study.
- **Goodhart-resistance partial-RG.** Per [P-32 § Goodhart resistance](../primitives/P-32-distance-estimator.md): 2 of 3 legs are structurally Goodhart-resistant (gaming `graph_distance` requires limiting actual symbol reach — a real cost; gaming `pace_layer_crossings` requires mis-typing the anchor, which is an `anchor-edit` always routed L4). The third leg, `intent_field_touches` LLM-judged, is **F33/F51-vulnerable** with a Patrol-tier residual detector only — does **not** close F47.

**Choice:** (b) accept-as-RG on the calibration + Goodhart-residue, routed to Phase 5/8. U-C does not commit to a bounded authoring sub-track at Phase 4. Phase-5 ADRs land with `accepted-with-RG-flag` status on the P-32 calibration recipe and on the F33/F51 residual Patrol-detector specification; Phase-6 architecture spec carries the accept-as-RG note in its YAML header; Phase-8 lean-eval includes a pressure-test of the degradation pattern (calibration sweep + Goodhart-gaming red-team). The substrate exposes `(w_g, w_p, w_i, τ_low, τ_high)` as first-class versioned parameters so Phase-8 sweeps are tractable, matching the GF-M / P-21 calibration-parameter exposure pattern.

## §3 Candidate-specific contracts on each primitive

U-C names two contested primitives (P-28, P-19) plus one designed-system primitive (P-32) and one commodity primitive (P-05, distance-keyed variant). Fixed-header contracts on the contested primitives follow.

**envelope schema:** (P-28 — U-C AnchorObject variant). Per [P-28 § U-C anchor envelope](../primitives/P-28-typed-object-store.md): the typed envelope carries `kind` ∈ {intent-invariant, architecture-rule, standards-rule, live-test, runtime-trace}, `content` (immutable bytes), `frozen-since` (timestamp), `owning-mandate` ∈ {greenfield, brownfield, both}, and `mutation-protocol` (named-human L4 policy reference). The typed filter is keyed on `kind` × `owning-mandate`; the P-32 distance estimator reads the anchor set produced by this filter to compute distance for any proposed change. U-C's envelope is **immutability-metadata-first** — `frozen-since` and `mutation-protocol` are first-class envelope fields, not policy attached out-of-band. The anchor mutation queue is a typed-filter view over the same store where `kind=anchor-edit` envelopes carry `proposed-content` + `target-anchor-hash`; the P-29 mediator (if U-C adopts one — U-C §1 does not name P-29 directly, the protocol-enforcement could equally sit at the P-19 dispatcher layer) gates approval against the target anchor's `mutation-protocol` field.

**feature source:** (P-19 — U-C distance-gated dispatcher variant). Per [P-19 § U-C distance-gated dispatcher](../primitives/P-19-eligibility-regime-classifier.md): U-C's feature source is the **P-32 DistanceTuple** — not work-unit-class features (as in GF-S) and not Codebase-Model-region features (as in BF-L). The dispatcher consumes `(graph_distance, pace_layer_crossings, intent_field_touches, contradiction_flag)` and emits regime in {lights-out, cross-model-judging, human-required} via threshold logic on the composite `w_g · graph_distance + w_p · pace_layer_crossings + w_i · intent_field_touches` plus a hard floor: `contradiction_flag = true` ⇒ regime = human-required regardless of composite (the F37 catch). U-C calls this *dispatcher* rather than *classifier* because P-32 has already done the feature engineering; the P-19 surface is mostly a thresholded decision table plus the Patrol-monitoring distribution check.

**P-32 distance estimator (not contested-fixed-header; named here for completeness).** Per [P-32 sketch](../primitives/P-32-distance-estimator.md): the substrate commits to the tuple as canonical (not the composite); per-dispatcher weight schemes are stored as versioned configuration. The estimator's `intent_field_touches` leg uses a stored `symbol → intent-field` map maintained as a P-13 reconciliation artifact for the deterministic half, falling back to a P-14-routed judge for unmapped symbols.

**P-05 distance-keyed trajectory (not contested-fixed-header).** Per [cluster-C2 § P-05](../primitives/cluster-C2.md): the U-C variant appends the P-32 DistanceTuple at write time. Patrol (P-06 tier-3) reads the cross-cycle distance distribution to detect F47 distributional gaming (too many work units landing just under `τ_low`).

## §4 X_UNM_B articulation

Per the [X_UNM_B finding](../candidate-registry.md#u-a--escrow-graph-factory-cycle--directed-graph-of-typed-nodes), U-C addresses Codebase-Model acquisition from legacy artifacts as follows:

- **Source artifact:** For brownfield, U-C needs the **dependency graph** (BF-L's P-26 *structural view*: P-22 polyglot codebase index + P-23 dependency-impact graph) to compute `graph_distance`, plus a **pace-layer mapping** (which files / directories / artifacts live at which Brier pace-layer) to compute `pace_layer_crossings`. The anchor set itself is operator-authored at deployment time (production traces become `kind=runtime-trace` anchors; the existing test suite becomes `kind=live-test` anchors; ARCHITECTURE.md becomes `kind=architecture-rule` anchors per [unified-C §1 primitive #1](../tracks/unified-C.md)).
- **Extraction primitive:** [P-22 polyglot codebase index](../primitives/P-22-polyglot-codebase-index.md) + [P-23 dependency-and-impact graph](../primitives/P-23-dependency-impact-graph.md). Both are `designed-system` (registry: High) and are the structural view of BF-L's P-26. U-C depends only on the **structural view portion** of BF-L's Codebase Model — the 4-of-6 `designed-system` views (structural / historical / runtime / debt) cover what U-C needs; the 2 RG views (conventional / invariant) are not required for distance computation. U-C therefore does NOT inherit the RG flag on P-26; the structural view it depends on is non-RG per [P-26 § Buildability verdict — decomposed per view](../primitives/P-26-codebase-model.md). The pace-layer mapping is a deployment-authored decision table over file globs / directory rules — `designed-system` engineering on top of the structural view.
- **Completeness gap:** `intent_field_touches` is the load-bearing gap. The El-Kaim 9-field intent block is a greenfield artifact; legacy brownfield codebases do not carry intent fields explicitly. The deterministic half of the leg (explicit `intent-field:<field-id>` markers in diffs) is unavailable for legacy code. The implicit-semantic half (P-14-routed LLM judge reading the diff against an intent block) presupposes an intent block exists. For pure-brownfield U-C deployment with no intent block authored, this third leg cannot be computed without operator-authored mapping from legacy spec artifacts (requirement docs, READMEs, change-management tickets) to a synthesised intent block. This is the F33/F51-vulnerable leg from §2 *plus* an additional brownfield acquisition cost.
- **Fallback if missing:** If `intent_field_touches` cannot be computed (no intent block; no synthesised mapping), U-C's third distance leg **degrades to "operator-attested"** — the work-unit author declares a Boolean estimate of intent-field touches per anchor, recorded as a typed event in P-05 with role provenance. The dispatcher then treats `intent_field_touches` as missing-and-attested and **falls back to L3 dispatch for that leg** (mid-distance Augmentation by default; the composite still applies the other two legs deterministically). Patrol monitors the attestation distribution for drift. This is graceful degradation, not failure: graph_distance + pace_layer_crossings still drive the dispatcher; the operator-attested leg is honestly flagged in the trajectory.
