## Part 4 — proposed ADRs

Architectural decisions made or implied by this session that the user may want
to record formally. Titles only — author any via the `adr` skill if you want
them.

- **Drain pipeline owns title-cleanliness, not just title-extraction.**
  `drain.py` should decode MIME quoted-printable headers and other transport
  encodings as part of stage-2-url-extract, not leave them for a manual cleanup
  pass. Grounded in: 5 raw `=?utf-8?Q?...?=` titles surfaced post-drain.
- **Drain pipeline auto-applies canonical-category tags.** The URL-pattern
  heuristic in `category-taxonomy.md` is mechanical and complete enough to run
  during stage 3. Grounded in: every new record failed the `has-category-tag`
  audit, forcing a manual 23-record retagging pass after the drain.
- **Drain pipeline auto-populates `references_from`.** The `--fix` flag is
  documented in `edit.md` but doesn't exist in `check-source-refs.py`. Either
  implement `--fix` or fold the back-population into `drain.py`. Grounded in:
  hand-wrote a Python script to close 8 gaps the linter flagged.
- **`render-sources-md.sh` writes to the canonical path by default.** Today
  it prints to stdout; every operator has to remember to redirect. Grounded
  in: caught the bug only because the markdown landed in the chat transcript
  instead of a file diff.
- **Drain's inventory list is data-driven, not hard-coded.** Adding `.mmd`
  (or any new extension) requires editing `drain.py`. A small allowlist in
  the pipeline config (the YAML block in SKILL.md) would let users add
  formats without code changes. Grounded in: had to manually set up the `.mmd`
  record because drain didn't see it.
