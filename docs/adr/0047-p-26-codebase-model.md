# ADR 0047: BF-L P-26 Codebase Model

- **Status**: Accepted
- **Date**: 2026-05-25
- **Deciders**: lead agent (Phase 5 Wave 5.3b subagent)

## Context

[BF-L](../../architectures/v3/tracks/brownfield-legacy-ingestion-first.md) is "three loops over one Codebase Model" — the [P-26 sketch](../../architectures/v3/primitives/P-26-codebase-model.md) integrates six views (structural, conventional, historical, runtime, invariant, debt) of a brownfield codebase into a single durable, versioned, queryable artifact keyed to a common symbol-ID space. Without integration discipline, BF-L collapses to BF-S (six co-located stores) and forfeits the load-bearing claim that *one artifact* parameterises methodology, regime classification, and scenario derivation. This is "the most ambitious primitive in the catalog" ([primitives/index.md](../../architectures/v3/primitives/index.md)) and the [BF-L substrate-requirements summary](../../architectures/v3/substrate-requirements/bf-l.md#1-primitive-list-buildability-confirmed) makes it the only load-bearing primitive for the track.

Four named substrate primitives compose into P-26 with existing ADRs: P-22 polyglot index ([ADR 0017](0017-p-22-polyglot-codebase-index.md)), P-23 dependency-impact graph ([ADR 0031](0031-p-23-dependency-impact-graph.md)), P-07 telemetry ([ADR 0014](0014-p-07-telemetry-ingestor.md)), P-24 attribution ([ADR 0035](0035-p-24-attribution-store.md)). The forcing failure modes ([BF-L §2](../../architectures/v3/tracks/brownfield-legacy-ingestion-first.md)) are F20 (maintenance-vs-greenfield asymmetry — the model *is* the answer to "what do you know"), F21 (context-exhaustion — persisted versioned artifact defeats reload), F34 (cross-layer drift — Loop-3 reconciliation), F54 (RSI-goal subversion), F58 (runtime/design-time compliance split).

Two of P-26's six views carry research-grade-uncertainty (conventional, invariant). Per [auto-003 Round 2](../../architectures/v3/decisions/auto-003-bfl-rg-view-choice.md#decision-round-2), each got an independent smoke-test gate. Both [conventional](../../architectures/v3/sub-tracks/bfl-conventional-smoke-test.md#4-honest-verdict-smoke-test-close) and [invariant](../../architectures/v3/sub-tracks/bfl-invariant-smoke-test.md) smoke-tests **passed 3/3 languages** (Python / TypeScript / Java) with non-trivial, corpus-cited artifacts — authorizing the full Wave-4.5b sub-track scope but leaving the structural RG flag in place pending Wave-4.5b scaling to ≥10-per-language.

## Decision

**Build P-26 as a layered composition over the four existing substrate ADRs, with integration discipline at three named layers and a per-RG-view binding deferred to the consumer.**

**Layer 1 — fact substrate.** P-22 ([ADR 0017](0017-p-22-polyglot-codebase-index.md))'s Glean typed-fact database is the canonical fact store for all six views. Tree-sitter parsers + SCIP records define the symbol-ID space (`{language, qname, source-revision}` + stable hash); every other view foreign-keys to it. A symbol that does not exist structurally cannot carry facts in other views — this mechanically enforces "one model" rather than "six co-located stores."

**Layer 2 — dependency closure + composition.** P-23 ([ADR 0031](0031-p-23-dependency-impact-graph.md))'s blast-radius is a Datalog/Angle query over Glean's `xref` predicate joined with module-membership facts. P-07 ([ADR 0014](0014-p-07-telemetry-ingestor.md)) spans are tagged with source-symbol qnames (line-number → Tree-sitter range → qname) at ingest. P-24 ([ADR 0035](0035-p-24-attribution-store.md)) cosigned `{symbol, revision, author, timestamp, signed-by}` records intersect Tree-sitter ranges with `git blame -p` output. Conventional / invariant / debt views write `Convention` / `Invariant` / `Debt` Glean predicates with `source` provenance.

**Layer 3 — typed envelopes + join API.** A per-region typed envelope per view (`file`, `module`, `feature-flag`, `test-suite`, `region`) is composed via Glean Angle queries. The consumer-facing call shape is `model.join(symbol, version, [views]) → { structural, conventional, historical, runtime, invariant, debt }` — not the per-view APIs. **Snapshot consistency at version boundaries**: a `version` token (git-commit + ingestion-pass ID) resolves a coherent view across all six; within a version, queries are repeatable. Maintenance-loop (P-13) produces Merkle-DAG incremental delta-versions; per-cycle queries pin a version at dispatch (F34 defence at the model level).

**Per-RG-view consumer binding (per [auto-003 Round 2](../../architectures/v3/decisions/auto-003-bfl-rg-view-choice.md#decision-round-2)).** The conventional / invariant view bindings happen at the **consumer layer** (regime classifier, scenario-derivation primitive), not in the substrate. Both Wave-4.5 smoke-tests passed 3/3 languages, authorizing Wave-4.5b scaling; the per-view ADRs (separate from this one) record the verdict-conditional bindings.

**Methodology-degradation clause (load-bearing for fallback resilience; mandated by [auto-003 Round 2 §Methodology-degradation clause](../../architectures/v3/decisions/auto-003-bfl-rg-view-choice.md#methodology-degradation-clause-new-per-reviewer-2-a2)).** If conventional view falls back to (b) accept-as-RG at Wave-4.5b close, the eligibility function loses convention-density as a feature; cycles touching regions with no convention coverage default to L3 (not L4 lights-out), pending operator approval. If invariant view falls back, the scenario-derivation primitive (P-27, [ADR 0034](0034-p-27-archaeological-brief-tooling.md)) cannot pre-condition derived scenarios on invariant-satisfaction; derived scenarios are flagged "invariant-unconditioned" and routed to cross-family review rather than to L4 acceptance. **BF-L's Phase-6 architecture spec MUST carry both clauses regardless of Wave-4.5b verdict** — they are the structural defense that makes (b) fallback operationally viable rather than a fig leaf.

## Alternatives considered

**B. Standalone graph database (Neo4j / TigerGraph / Memgraph).** Build P-26 as a typed property-graph in a dedicated graph DB; all six views become node/edge types on one graph. *Why rejected:* duplicates Glean's machinery (typed-fact schema, incremental ingest, query planner) at the cost of losing SCIP-native interop and the dependency-closure idioms already engineered in P-23. Property-graph query languages (Cypher, GSQL) are weaker than Glean's Angle for the per-region cross-view joins BF-L's regime classifier needs. See [P-22 ADR alternatives](0017-p-22-polyglot-codebase-index.md) and [BF-L invariant prior-art §6](../../architectures/v3/research-notes/bfl-invariant-view-prior-art.md).

**C. Per-region SQL warehouse (Snowflake / BigQuery / Postgres + dbt).** Materialise each view as a relational table keyed by `(region, version)`; joins are SQL. *Why rejected:* no semantic-graph query — transitive closure (blast-radius), MRO resolution (conventional view's class-hierarchy rules per [Django Manager smoke-test convention](../../architectures/v3/sub-tracks/bfl-conventional-smoke-test.md)), and import-graph walking (TypeScript layering invariants) are awkward or O(n²) in SQL. The forcing failure mode F34 (cross-layer drift detection) requires *typed*-graph traversal, which SQL warehouses approximate poorly.

## Consequences

**Easier.** All four composed substrate ADRs are already accepted; this ADR is composition, not new substrate engineering. The integration discipline (common ID space, join API, snapshot consistency, Merkle-DAG versioning) is the *call-shape* the eligibility function ([ADR 0028](0028-p-19-eligibility-regime-classifier.md)) and scenario-derivation primitive ([ADR 0034](0034-p-27-archaeological-brief-tooling.md)) consume — they do not see the layered substrate. F21 (context-exhaustion) is defeated by the persisted versioned artifact; F34 (cross-layer drift) by snapshot-consistent versioning.

**Harder.** Six-view composition at 1M+LOC with 10+ years of history is unmeasured (soft RG on scale per [P-26 sketch §RG-flag](../../architectures/v3/primitives/P-26-codebase-model.md)); Glean and SCIP publish scale numbers for structural alone. Wave-4.5b sub-track outcomes (≥30 conventions / ≥30 invariants per language) gate the per-view ADRs. Realistic effort: **9–18 engineer-months for a credible v1** ([P-26 §Construction effort](../../architectures/v3/primitives/P-26-codebase-model.md)).

**Explicitly NOT promising.** Same-vs-distinct verdicts on whether BF-L's integrated P-26 "should be" the same as BF-S's separate primitives — Phase-4.2 work, not here. The conventional / invariant view feature contributions to the regime classifier are conditional on Wave-4.5b verdicts; the methodology-degradation clause is the structural defense if they fall back. Phase-8 lean-eval (per [BF-L §5](../../architectures/v3/substrate-requirements/bf-l.md#5-open-carries)) pressure-tests integration discipline at scale and per-region classifier drift under degradation regime.
