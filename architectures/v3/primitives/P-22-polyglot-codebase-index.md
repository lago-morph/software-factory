# P-22 — Polyglot codebase index

**Dispatch tier.** per-primitive (designed-system).
**Claimed by.** [BF-S/S-1 (Codebase Index, incremental)](../tracks/brownfield-substrate-first.md), [BF-M Stage-2 Comprehension (code-traversal capability)](../tracks/brownfield-methodology-first.md), [BF-L Codebase Model (structural view component)](../tracks/brownfield-legacy-ingestion-first.md).

## Contract restatement

A queryable, **incrementally-maintained per-language index** of the existing codebase exposing: symbols (functions, classes, methods, constants), definitions and references, the call graph, module boundaries, and per-language **type information where available**. The index is **polyglot**: a single index API spans multiple languages in one repository (or fleet of repositories) so callers issue uniform queries — *find definition*, *find references*, *list symbols in file*, *resolve type of expression*, *list callers of `Foo.bar`* — and the index routes per-language under the surface. Partition discipline: the index is updated on every push (incremental, not full rebuild), it is queryable by agent tools as a substrate-side service (callers do not re-grep the repo), and it returns *slices* sized to the caller's context budget rather than full file dumps (the F21 mitigation only works if the contract is "give me only what's relevant").

## Construction path

**Primary option: tree-sitter as the universal AST layer + per-language LSP servers for type information, federated behind a single index API.** tree-sitter ships incremental parsers for ~40+ languages (Python, JavaScript / TypeScript, Go, Rust, Java, C / C++, Ruby, etc.); `Parser.parse(source, old_tree)` produces an updated AST in time proportional to the *edit*, not the file — this is what makes the index incremental on every push rather than a full re-walk. The substrate runs tree-sitter once per touched file in the post-receive hook, extracts symbols + definitions + references into a per-language fact table (one row per definition, one row per reference, file + byte-range coordinates), and stores the tables in a queryable backend (SQLite-FTS or DuckDB is sufficient for single-repo scale; Postgres + per-language partitions for fleet scale). For *type* queries — which AST alone cannot answer — the index delegates to a per-language LSP server (`pyright` for Python, `gopls` for Go, `rust-analyzer` for Rust, `typescript-language-server` for TS) over the LSP JSON-RPC protocol. **Integration sentence:** a "find all callers of `Foo.bar`" query resolves as `index.references(symbol_id="Foo.bar")` — the substrate looks up `Foo.bar`'s definition row, joins to the reference table by symbol-id, and returns `(file, line, surrounding-context)` tuples ranked by the call-graph distance; for the symbol-id resolution itself the substrate may call `textDocument/definition` against the file's LSP server to disambiguate same-named symbols across modules, then cache the resolved id back into the reference table for future queries.

**Alternative option: Sourcegraph + SCIP indexers.** Sourcegraph publishes the SCIP (Source Code Intelligence Protocol) format and ships per-language SCIP indexers (`scip-python`, `scip-typescript`, `scip-java`, `scip-go`, etc.) that produce a uniform protobuf-shaped index file per language; Sourcegraph's API consumes these and exposes a polyglot REST/GraphQL surface (`/definitions`, `/references`, `/symbols`). Integration sentence: "find all callers of `Foo.bar`" issues `POST /api/graphql {repository(name:...) { commit(rev:...) { blob(path:...) { lsif { references { nodes { resource { path } range }}}}}}` — Sourcegraph's resolver dispatches to the language-appropriate SCIP index and returns the cross-language reference set behind one API call.

**Alternative option: Glean (Meta).** Glean is a Datalog-backed code-knowledge store with per-language indexers (Hack, C++, Python, Java, Rust, etc.) that emit facts conforming to per-language Glean schemas; queries are written in a typed Angle / Datalog language and `glean derive` runs derivation rules across language schemas so a cross-language query ("all callers of an exported symbol regardless of caller language") is one derived predicate. Integration sentence: "find all callers of `Foo.bar`" is the Angle query `python.DirectXRefsByTarget { target = python.Name "Foo.bar" } | java.CallSite { target = java.Method ... }` unioned in a derivation rule — `glean derive` materialises the union, which the substrate exposes through Glean's `glean shell` or thrift API. Glean is the strongest fit for *fleet-scale* polyglot but ships with high operational complexity.

**Prior art reference.** GitHub's Stack Graphs (a name-resolution-only layer atop tree-sitter targeting *cross-language* symbol resolution) is the closest published prior art for an explicit polyglot index. Sourcegraph's deployment across multi-language enterprise monorepos (Stripe, Uber, Lyft) is the closest production evidence at brownfield-fleet scale. Meta's Glean is the production case for Datalog-backed multi-language stores.

## Polyglot fidelity gap

The index's polyglot promise is *real for AST / symbol / reference queries* (tree-sitter covers ~40 languages uniformly; SCIP and Glean both publish multi-language schemas) but **uneven for type queries**. Statically-typed languages with mature LSP servers (Rust, Go, Java, TypeScript with strict mode) return reliable type information; dynamically-typed languages return *best-effort* types (Python under `pyright --strict` is good but degrades sharply on untyped third-party code; Ruby and JavaScript without TypeScript are weakest). Cross-language *type* resolution (a Python service that RPCs into a Go service — what is the resolved type at the boundary?) is essentially **not supported** by any single tool: each language stops at its own boundary, and the bridge is contract-typed at best (protobuf, OpenAPI) and untyped at worst. The realistic fidelity ceiling on a polyglot index is therefore: **uniform high fidelity for symbols and references; per-language variable fidelity for types; near-zero fidelity for cross-language type resolution at boundaries.** BF-S's OQ-T2 (S-2 dependency-graph maintenance for polyglot codebases) and the BF-S text "the architecture has to accept S-2 fidelity will vary" both name this honestly; the same applies to S-1.

## Corpus-why citation

The load-bearing corpus problems are **[F21 — Context-window exhaustion](../failure-modes-v3.md#f21--context-window-exhaustion--silent-degradation) (brownfield severity *critical*)** and **[F61 — Context fragmentation across agents](../failure-modes-v3.md#f61--context-fragmentation-across-agents) (brownfield severity *high*)**. Brownfield ingestion saturates context fastest (F21); multi-agent swarms split context so no agent has a complete picture (F61). The index is the substrate's structural answer: per-cycle agents *query a persisted, indexed artifact* and receive scoped slices, instead of re-loading the codebase. Secondary motivation: legacy-archaeology / comprehension is the brownfield analogue of cold-start (BF-S §5, BF-L §1 Loop-1 ingestion) — the index is the durable artifact that makes the bootstrap pay off across cycles.

## Research-grade-uncertainty flag

**Not research-grade for the index's core construction** — tree-sitter, LSP, SCIP, Sourcegraph, and Glean are all production-deployed at multi-language scale. **Explicit named risk:** the **polyglot type-fidelity ceiling** (see "Polyglot fidelity gap" above) is uneven across languages and near-zero across boundaries; methodology layers that assume uniform type-fidelity will fail silently in dynamic-language regions and at cross-language RPC boundaries. This is a *fidelity calibration* gap, not a buildability blocker — the index can be built; downstream consumers must be told what they're getting per language.

## Buildability verdict

**`designed-system`.** Multiple mature tools (tree-sitter + LSP federation; Sourcegraph + SCIP; Glean) construct the primitive; the *design content* is (i) which substrate to pick at what scale (per-language LSP-federation for single-repo, Sourcegraph for fleet, Glean for Meta-scale), (ii) the per-language fidelity calibration the caller must respect, and (iii) the slice-sized query contract that makes F21 mitigation real rather than nominal.
