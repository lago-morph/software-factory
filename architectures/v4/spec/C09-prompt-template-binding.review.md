## Findings

### RC09-01 — major — §6 F37 row presents INV-1-determinism-as-F37-mitigation and the GF-M pack guard as if both are v4-stated; the determinism framing is a fill, and the "runnable as a pack" gloss slightly overstates v4
**Claim.** §6 F37 row says v4's guard is "multi-model paraphrase divergence (gene-transfusion from GF-M, **runnable as a pack**)" and adds "C09's contribution is INV-1 determinism so the contradiction is at least *reproducible* and diagnosable."
**Evidence.** F-MODE line 23 states the F37 mechanism as "Multi-model paraphrase divergence (gene transfusion from GF-M pattern, runnable as pack on v4)" with status "Partial — multi-model has its own ceiling." So "runnable as a pack" IS in v4 — that part is faithful. What is **not** in v4 is the second sentence: the idea that C09's INV-1 determinism contributes to F37 handling by making a contradictory prompt "reproducible and diagnosable." That is a plausible inference but it is the spec's own reasoning, not a v4 statement, and it is presented in the handling column as if it were part of v4's F37 story. INV-1 itself is already (correctly) flagged as a [FAITHFUL-FILL] in §3.3; using it as an F37 mitigant inherits that fill status and should say so.
**Fix (applied).** Re-tagged the determinism-as-F37-aid sentence as the faithful inference it is (explicitly "faithful inference, not a v4-stated F37 mechanism"), leaving the v4-sourced "GF-M pattern, runnable as a pack / Partial" claim intact.

### RC09-02 — minor — header Source line lists F18/F36/F37/F38 flatly as C09 sources, but §6 correctly scopes F18/F38 as upstream-of-C09 (C10/C07), risking a read that C09 owns them
**Claim.** The `> Source:` header ends "...F-MODE-COVERAGE F18, F36, F37, F38" with no scope qualifier; §6 then (correctly) says F38 is "**Addressed** upstream of C09" (C10 linter / C07 glossary) and F18 "C09 is a faithful conduit, not a disambiguator" (resolved at C10/P6, not C09).
**Evidence.** This is not a miscitation — all four F-modes genuinely touch the rendered-instruction surface, so listing them as relevant is defensible. But a reader skimming the header could infer C09 *owns/mitigates* F18 and F38, when the spec body is careful that C09 only *conducts* them and the mitigation lives upstream (C10, C07, P6). The header is the one place that flattens this nuance.
**Fix (applied).** Annotated the header F-mode list to mark which are C09-relevant-but-handled-upstream (F18, F38) vs. inherent/conduit at C09 (F36, F37) — one parenthetical, no content change.
