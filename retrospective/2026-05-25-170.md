### Proposed AGENTS-MD rule: structure-not-conclusions test for top-of-doc TL;DRs

**Source observation:** PR A5 verification finding. Lead-agent-authored registry TL;DR contained "GF → BF continuity matrix is withdrawn per DEC-1.b" — a policy verdict, not a structural element. Fresh-context reviewer correctly applied the heuristic: would this line need updating if the policy flipped? Yes ⇒ restates content.

**Proposed rule:** "Every line of a top-of-doc TL;DR (≤200 words) section MUST pass the 'would this line need updating if the doc's conclusion changed?' test. If yes, rewrite to name structural element rather than conclusion. Conclusion-restatement TL;DRs drift silently and fail in the regeneration loop."

**Justification:** TL;DR-first discipline (from the [context-slimming plan](../CONTEXT-SLIMMING-PLAN.md)) relies on the regeneration pattern being cheap — body changes → TL;DR regenerates from the body. If TL;DR captures conclusions, body changes that flip conclusions require manual TL;DR edit; the regen sub-step (codified in PR A3) can't catch the drift because the regen-subagent doesn't know what was conclusion vs. structure.

### Proposed AGENTS-MD rule: forward-ref scope-boundary statement in variant-bearing framework ADRs

**Source observation:** Wave 5.1b briefs explicitly required Consequences sections of P-19 / P-28 / P-29 / P-30 framework ADRs to carry forward-reference scope-boundary statements (per-variant ADRs deferred to Wave 5.3 next run). All four subagents complied; ADR 0036 (P-30) carried the verbatim DISTINCT-primitives scope warning per auto-005 Round 2.

**Proposed rule:** "Common ADRs for primitives with deferred per-variant ADRs MUST carry an explicit scope-boundary statement in their Consequences section, naming (a) the variant landscape, (b) the deferral target (next run / wave / phase), (c) the cross-reference requirement for downstream consumers (e.g., 'Phase-6 architecture specs MUST reference BOTH this framework ADR AND the candidate's per-variant ADR'). Omitting this invites silent under-reference where consumers cite only the framework ADR for variant-bearing decisions."

**Justification:** ADR 0036's verbatim scope-warning was authored under explicit subagent guidance because the cost-hawk and pre-mortemer surfaced the risk in adversarial review. Codifying the rule means future Phase-5-style variant-bearing ADRs apply the discipline without per-subagent reminders.

### Proposed SKILL-SPEC: ADR-ID-to-file mapping table at run-close handoff

**Source observation:** auto-005 Round-2 Reviewer-2 (ADR-quality auditor) explicitly called for a Wave-5.3 cross-reference mapping table. PR B4 (Phase-5a-close handoff) carries the table for this run's 27 ADRs. The successor run uses it to publish cross-references in per-variant ADRs without re-deriving ADR numbers.

**Proposed skill:** Codify this as part of the [`autonomous-run` skill's handoff-discipline](../.claude/skills/autonomous-run/SKILL.md). When a run produces ADRs that will be cross-referenced by future runs, the run-close handoff MUST carry the ADR-ID-to-file mapping table.

**Justification:** PR-deferred ADR work is normal (PR-cap + context-budget force splits). Without an ADR-ID-to-file mapping table at the handoff, the successor run either re-discovers IDs (cost) or speculatively cross-references with placeholders (drift risk).

### Proposed ADR: deferred-work binding-artifact pattern

**Source observation:** All three Round-2 reviewers raised the Wave-5.3 binding concern. Without an explicit binding artifact, deferred work risks dissolving at run boundary (pre-mortemer's most-likely failure path). The Phase-5a-close handoff was promoted to "binding artifact with Phase-6 gate."

**Proposed ADR:** Establish "deferred-work binding artifact" as a recurring pattern: when an autonomous run defers in-scope work to a successor run, the deferral MUST be carried as a binding constraint in (a) the session handoff doc, (b) the next-run dispatch prompt, AND (c) the morning summary's "what I deliberately did NOT do" section. All three must agree; divergence is a process bug.

**Justification:** The 2026-05-25 cost-hawk's PR-cap argument was sound but the deferral mechanism was unspecified until Round 2. Codifying the mechanism reduces ad-hoc reinvention across runs.
