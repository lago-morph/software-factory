## Part 4 — proposed ADRs

Architectural decisions that surfaced or were made in this session. **Titles only — no specs.** Use the `adr` skill to author any of these if you decide they're worth recording.

- **ADR: Adopt arXiv `/e-print/` LaTeX-tarball route as canonical arXiv-paper recovery** — when `arxiv.org/html/<id>v<v>` returns 404 and `arxiv.org/pdf/<id>` is binary, the `/e-print/` route returns a gzipped LaTeX tarball that is the most authoritative source. The CaMeL paper body unlock in this session validated this; the round-7 R7.2 decision ("accept the gap") would have been overturned by this rule.
- **ADR: Workflow drop-branches (`fetched/issue-N`) are never merged directly** — cherry-pick only namespace contents. The fetched/issue-41 and fetched/issue-42 branches both forked from an older main commit; a naive merge would have re-deleted `user-next-steps.md` and `research/next-fetch-batch.md`. Establishes the contract between the fetch-action and the orchestrator.
- **ADR: Drain subagents commit no code; the orchestrator batches all subagent outputs into one commit per drain round** — used effectively in PR #44 (4 parallel subagents, one consolidated commit). Avoids partial-state commits and gives the orchestrator the authority to reconcile cross-report bookkeeping (INDEX, PLAN, blocked-urls-round-N).
- **ADR: HTTP 200 alone does NOT indicate a successful fetch** — body inspection (Cloudflare JS challenge, 404 pages, JS-SPA shells, gzip mis-extraction) is part of the fetch-action's success criteria. Currently a runtime discipline; could be promoted to an enforced gate in the workflow YAML.
