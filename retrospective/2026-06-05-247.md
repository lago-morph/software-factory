## Part 1 — what happened

### Phase 1 — Ground the question (and discover the real target)
The ask was open: "what's next for the factory; how do I exercise it, what methodology, what formulas,
how do we evolve it" — with an explicit request for a panel of experts. Early reads established the v4
factory's shape and that the "first 25 components" is the **safe self-build backbone**, so "what's
next" is the bootstrap-validation milestone. Mid-stream the operator added the load-bearing fact:
`lago-morph/agent-os` is the *real* product. The GitHub MCP is hard-scoped to this repo, so agent-os
was reached by `git clone` into `/tmp` (the documented out-of-scope fallback). agent-os turned out to
be a ~65-component spec/plan corpus — i.e. exactly what a "specs-in → software-out" factory consumes —
which became the grounding for "real work, not baby tests."

### Phase 2 — Competing plans → synthesis → adversarial panel
Rather than write one plan, the lead authored a grounding brief + exemplar and dispatched three
subagents to write *competing* full plans under distinct lenses (velocity / de-risk / yield),
synthesized them, then ran a **six-expert adversarial panel** (architect, safety, eval scientist,
delivery/SRE, bootstrap-skeptic, operator) plus a methodology fact-check. All six returned
`accept-with-named-amendments`; eight amendments were de-duplicated and folded in. The panel earned its
keep: it caught that "parallel rigs" buy no compute on one seat, that the "clusterless slice" wasn't
clusterless (B16/B6/B9 depend on A1), and that agent-os specs' deliberate `[PROPOSED]` holes would
drive spec-corner no-go loops unless a human-led spec-completion pass precedes a build.

### Phase 3 — The methodology companion and its fact-check
The operator flagged two misses: I under-served the *concrete methodology* (the Gas City **formulas** —
workflow recipes) and had framed the work as a march to a finished factory rather than a
co-implementation. A methodology companion was written with an illustrative formula; a dedicated
fact-check subagent then caught real over-claims — a same-family Phase-0 judge labelled a "different
model family" as fact, and invented `$slot`/`[loop]` keys not flagged as illustrative — all fixed.

### Phase 4 — The brainstorm pivot: trust map + play menu + fun-first
A multi-turn brainstorm reframed the whole approach: trust is a *gradient* not a binary; the operator
wants a *board of cards* shopped by mood (a personal project — fun is a hard constraint), agent-os is
one of many projects, and the factory is a *prototype for discovery*, not a destination. I defined a
precise vocabulary, played it back, and refined it (trust ladder, board/cards, invented projects,
gentle coverage nudge).

### Phase 5 — Capture the essence + rewrite + merge + handoff
Per the operator's instruction, I recorded the essence as a **charter** (declared to win on framing
where older docs disagree), pointed AGENT-ENTRY at it, rewrote the next-steps report around the
trust-map + board model, wrote a session handoff naming the next three steps (build the cards → plan
the 25 → execute), merged PR #247, and verified the files landed in `main`.

### Suggestion 1: Reframe-correcting artifacts must declare precedence — `AGENTS-MD-ecb1775057`

- **Per-rule file**: [./2026-06-05-247/AGENTS-MD-ecb1775057-reframe-correcting-artifacts-must-declare-precedence.md](./2026-06-05-247/AGENTS-MD-ecb1775057-reframe-correcting-artifacts-must-declare-precedence.md)

**Proposed agent instruction:**

> **Reframe-correcting artifacts must declare precedence.** When a later artifact corrects the framing
> of an earlier one, state the precedence explicitly in the new artifact (for example, "this charter
> wins on framing where older docs disagree") and add a superseding pointer; never leave a corrected
> framing to coexist silently with the stale one.
>
> *Grounded in: this session's charter explicitly superseding the earlier mis-framed next-steps report.*

**Justification:** Mid-session the operator corrected a foundational framing (co-implemented
prototype-for-discovery across a portfolio, not a march to a finished factory). Already-written
artifacts still carried the old framing. Without an explicit precedence declaration, a future reader
hits two artifacts that disagree and cannot tell which is current — wasting a session re-deriving "what
do we believe now?" The fix is one sentence plus a pointer; the cost of omitting it is a future agent
silently building on superseded framing.

### Suggestion 2: Verify relative-link depth from deep sibling directories before commit — `AGENTS-MD-cf563cd4ec`

- **Per-rule file**: [./2026-06-05-247/AGENTS-MD-cf563cd4ec-verify-relative-link-depth-from-deep-sibling-directories.md](./2026-06-05-247/AGENTS-MD-cf563cd4ec-verify-relative-link-depth-from-deep-sibling-directories.md)

**Proposed agent instruction:**

> **Verify relative-link depth from deep sibling directories before commit.** Before committing a
> markdown file authored several directories deep (e.g. under `_meta/.../panel/`), verify every relative
> link's `../` depth by running the repo's internal-reference checker (or counting levels to the repo
> root) — off-by-one `../` depth is the dominant link bug for deep artifacts, and a subagent writing
> into a deep directory will reliably get it wrong.
>
> *Grounded in: VERDICT.md and the methodology fact-check both shipped with off-by-one ../ depth from the panel/ dir.*

**Justification:** Twice in one session a file four levels deep shipped with links one `../` too
shallow, each caught only by `scripts/check-internal-refs.py` after the fact and each needing a
follow-up fix commit. The pattern is mechanical and predictable. The marginal cost of prevention is one
checker run before committing a deep file; the cost of skipping it is broken navigation and a separate
cleanup commit.

### Suggestion 3: Flag unverified external-format examples as illustrative — `AGENTS-MD-5357568132`

- **Per-rule file**: [./2026-06-05-247/AGENTS-MD-5357568132-flag-unverified-external-format-examples-as-illustrative.md](./2026-06-05-247/AGENTS-MD-5357568132-flag-unverified-external-format-examples-as-illustrative.md)

**Proposed agent instruction:**

> **Flag unverified external-format examples as illustrative.** When documenting the syntax or behavior
> of an external substrate that has not been run/verified, present every example as explicitly
> illustrative ("shape, not verified syntax") and never assert a format detail, a borrowed example's
> field, or an unbuilt safety property as present fact; cite the source spec's own hedge.
>
> *Grounded in: the methodology companion asserting a same-family Phase-0 judge as a "different model family" and inventing $slot/loop formula keys.*

**Justification:** The methodology companion described a Gas City formula format nobody has run. A
fact-check subagent caught a comment stating the judge was a "different model family" as fact (the spec
relaxes that to advisory at that phase), plus `$slot`/`[loop]` keys that were borrowed/invented but not
flagged. Such errors propagate silently — a reader takes the illustration for verified fact. The
marginal cost is a one-line banner plus a spec citation; the cost of omitting it is a fabricated-as-real
detail indistinguishable from truth until it breaks.

### Suggestion 4: Competing plans before the adversarial panel on open strategic questions — `AGENTS-MD-89ee1ad859`

- **Per-rule file**: [./2026-06-05-247/AGENTS-MD-89ee1ad859-competing-plans-before-the-adversarial-panel.md](./2026-06-05-247/AGENTS-MD-89ee1ad859-competing-plans-before-the-adversarial-panel.md)

**Proposed agent instruction:**

> **Competing plans before the adversarial panel on open strategic questions.** For an open strategic
> question with several defensible directions, dispatch 2-3 real subagents to author competing full
> plans under distinct lenses and synthesize them before running the adversarial panel — a panel fed a
> single lead-authored plan inherits the lead's anchoring, while a synthesis of competitors does not.
>
> *Grounded in: three competing plans (velocity/de-risk/yield) synthesized before the six-expert panel in PR #247.*

**Justification:** The question had ≥3 defensible lenses. Three subagents authored competing plans; the
synthesis absorbed the strongest move from each, and several panel amendments landed precisely on the
seams between lenses. A panel reviewing only the lead's exemplar would have inherited its blind spots.
The marginal cost is 2-3 extra dispatches; the payoff is a plan that survives adversarial review because
it was never anchored to one view.

### Suggestion 5: Charter-first navigation on a project framing pivot — `AGENTS-MD-e94a9aaa75`

- **Per-rule file**: [./2026-06-05-247/AGENTS-MD-e94a9aaa75-charter-first-navigation-on-a-project-framing-pivot.md](./2026-06-05-247/AGENTS-MD-e94a9aaa75-charter-first-navigation-on-a-project-framing-pivot.md)

**Proposed agent instruction:**

> **Charter-first navigation on a project framing pivot.** When a session pivots the project's framing
> or working model, capture the corrected model in a charter document and point the entry/navigation doc
> at it as "read this first for the feel" — so a future agent absorbs the current framing before the
> older design docs that predate the pivot.
>
> *Grounded in: adding factory-discovery-charter.md and pointing AGENT-ENTRY section 2 at it as read-first.*

**Justification:** This session's new mental model (trust map, board, co-implementation, fun-first)
lives nowhere in the older design corpus, which a fresh agent would read first and absorb the superseded
framing from. A charter plus one navigation line gives every future session the current model in one
hop. Marginal cost: one doc and one edited bullet; cost of omitting: every future agent re-deriving the
framing, or inheriting the pre-pivot one.
