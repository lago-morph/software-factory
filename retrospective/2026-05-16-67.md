### Phase 1 — Cluster-by-cluster drain via subagents (13 active clusters, 2 skipped)

The user explicitly framed subagent use as **context-preservation, not parallelism** — so one subagent at a time, serial, with the orchestrator committing + updating PLAN.md between each return. The pattern was:

1. Write a per-cluster brief: list source files, target reports, what to add, what NOT to touch, image-extraction instructions, deliverable expectations.
2. Spawn one subagent (`general-purpose`) with the brief.
3. Wait for completion.
4. Verify with `git status` / `git diff --stat`.
5. Update `research/PLAN.md`'s Round-10 in-progress block — flip the cluster checkbox ⬜ → ✅ and inline 3–8 surprises from the subagent's change report.
6. Commit (one commit per cluster, descriptive subject + multi-line body capturing the change report).
7. Push.

Clusters D (Codex core docs) and G (Replit docs) had already been fully drained in earlier sessions (rounds 7–8); the index marked all of their sources as deleted-duplicates, so they were skipped without a subagent run.

The 13 active clusters produced **11 new numbered reports** (27 dotfile-pipelines, 28 Schillace, 29 prompt-engineering survey, 30 cognitive escrow, 31 Caremark RSI, 32 Shapiro Claw, 33 language-as-harness, 34 personal harnesses, 35 spec-driven team ops, 36 Sendbird quests, 37 LLM agent collusion) plus targeted upgrades to **8 existing reports/followups** (01 footnote, 02 Caremark cross-ref, 07 ecosystem update, 09 diagrams, 18 .rules+ops+author-attribution, 20 App Monitoring + Mastra, 22 SWE-bench Verified + Princeton PLI, 25 AFIS strategy-3 update, followups 01/06/07/08/10).

## Part 4 — proposed ADRs

Architectural decisions made in this session that may warrant ADRs:

- **Failure-mode numbering policy** — F-numbers are strictly globally sequential across reports; never let two reports claim the same F-number. The F36/F37 collision between reports 25 and 26 has been outstanding since the Round-9 drain and is still unresolved. A binding policy that allocates F-numbers via a shared counter would prevent recurrence.
- **Per-report figure directory convention** — `research/figures/NN-<slug>/` is the canonical home for per-report visual assets; embed via relative paths; never copy duplicate the same image into two figure directories (the Cluster I work used `research/figures/28-schillace-sunday-letters/` referenced from BOTH report 28 and report 09 §10 — the by-reference pattern worked well and should be the rule).
- **Cluster-orchestration commit cadence** — One commit + one PLAN.md update per subagent return. Never batch multiple cluster outputs into a single commit. The PR's commit log then becomes a reviewable cluster-by-cluster audit trail.
- **`mhtml_extract.py` contract** — single source of truth path is `.claude/skills/research-pipeline/scripts/mhtml_extract.py`; the `info`/`save-image` index-base inconsistency is a real defect, not a feature, and should be fixed (1-based info → 0-based save is the documented current behavior; pick one and align).
- **Forward-allocate report numbers in orchestrator decisions** — when a multi-cluster drain creates more than one new report, pre-allocate report numbers (27, 28, …) in an orchestrator-decisions document before dispatching the first subagent. This drain did so and it worked perfectly.
