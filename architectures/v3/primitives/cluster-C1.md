# Cluster C1 — Execution & resource control (buildability sketches)

Per [`auto-001` Round-2 dispatch shape](../decisions/auto-001-phase-3.5-dispatch-shape.md#amendments-to-the-dispatch-brief-that-will-be-sent-to-subagents), this file holds the per-primitive buildability sketches for cluster C1: P-01 Sandbox runtime, P-02 Cost ceilings, P-03 Worktree isolation, P-04 PR creator. Each section satisfies the [two-part rule](../phase-3.4-decisions-resolved.md#refined-two-part-rule-for-accepting-a-substrate-primitive) on its own (no shared-citation reuse). Per the same brief, this subagent renders **no same-vs-distinct verdicts** across primitives.

## P-01 Sandbox runtime

**Contract restatement.** P-01 is the isolated per-cycle execution environment that every other substrate primitive composes against. Its contract: a deny-by-default closure over filesystem, network, and tool/syscall surface; capability grants are declared in the cycle manifest at boot and cannot be widened mid-cycle; production-credentialled scissors are substrate-disabled unless an explicit declaration triggers escalation to a separate, more-restricted profile. API surface: a `launch(cycle-manifest) → handle` call returning a handle on which all subsequent agent tool calls are mediated; a `revoke(handle)` call that tears down the closure. Partition enforced: kernel-level process / mount / network-namespace isolation between cycles, plus an allow-list policy boundary inside the closure.

**Construction path.** Bubblewrap (`bwrap --unshare-all --ro-bind / / --bind ./work /work --setenv PATH ...`) provides kernel-namespace closure with deny-all default and per-mount allow-listing in a single CLI invocation — the bind/setenv flags map one-to-one onto the cycle manifest's filesystem and env-var grants. For stronger isolation when the cycle's allow-list includes shell exec or unrestricted network, Firecracker microVMs (`firecracker --config-file cycle.json` with a per-cycle tap-device for network policy) provide hypervisor-grade closure without container-escape exposure. Network closure is enforced inside the closure with an nftables deny-all default + per-host allow rules generated from the manifest.

**Corpus-why citation.** [GF-S §1.S1](../tracks/greenfield-substrate-first.md#1s1--sandbox-closure-first-substrate-default-off-for-production-scissors) names this primitive as the closure-first foundation for the F12 / F33 / F44 Lethal-Trifecta cascade and the [Shapiro R1–R5 production-scissors rules from report 32 §8.2](../../../research/32-shapiro-completion-chat-agent-claw.md). [BF-M's stage-5 mitigation row for F12/F33/F44](../tracks/brownfield-methodology-first.md#25-failure-mode-coverage-severity-by-stage) requires the same closure: "production-scissors default-off; CaMeL boundary at stage 5 when production-adjacent." Without P-01 the deny-default invariant is operator-voluntary, which F53 (voluntary-discipline fragility) marks as a known failure mode.

**Research-grade-uncertainty flag.** `none` for the single-tenant, semi-trusted-agent model that all 10 candidates assume. (Adversarial multi-tenant — agents from mutually untrusted parties on shared substrate — would require primitive-level escape isolation that is research-grade, but no candidate currently posits that threat model.)

**Buildability verdict.** `commodity`.

## P-02 Cost ceilings

**Contract restatement.** P-02 is a substrate-resident enforcer of hard per-cycle and per-cycle-class budget caps in multiple axes simultaneously: token spend (per model family), wall-clock elapsed, tool-call count, and dollar spend. The contract: caps are declared in the cycle manifest at boot and the substrate **kills** the cycle when any axis reaches its ceiling — no graceful degradation, no operator override mid-cycle. API surface: `register(handle, ceilings)` at cycle boot; an inline mediator wrapping every model call and tool call that increments counters and tears down the cycle when any threshold is crossed; a `report(handle) → axes` query for trajectory capture. Partition enforced: a per-cycle counter store that no agent inside the cycle can read or write.

**Construction path.** A reverse-proxy mediator in front of the model-provider API (LiteLLM proxy, or a small bespoke FastAPI service) accumulates token-count and dollar-spend from each upstream response's `usage` field and returns HTTP 429 when the per-cycle counter exceeds the manifest's cap — the proxy's middleware hook is where the kill decision lands. Wall-clock and tool-call ceilings are enforced by a watchdog process spawned alongside the cycle (`timeout(1)` for the trivial wall-clock case; a small Python supervisor counting tool-call events from the trajectory log for the per-call case) which sends SIGTERM/SIGKILL to the cycle's process group via the P-01 handle when its counter trips.

**Corpus-why citation.** [GF-S §1.S4](../tracks/greenfield-substrate-first.md#1s4--cost-ceilings-hard-multi-axis-substrate-enforced) declares this primitive non-optional and explicitly refuses graceful-degradation per [CTR-E6](../contradictions.md) (CaMeL utility-tax-style hidden cost). [BF-M D-5](../tracks/brownfield-methodology-first.md#4-defaults-accepted-vs-challenged) accepts hard cost ceilings with justification, citing [CTR-E1](../contradictions.md)'s observed 10× cost variance (Cherny $100K+/mo vs. independents $500–$5000/day) as input to ceiling calibration. F31 (minimum-adapter principle) and [BF-M §2.5 row D-5](../tracks/brownfield-methodology-first.md#25-failure-mode-coverage-severity-by-stage) tie P-02 directly to the substrate-not-operator-voluntary discipline that defends against F53.

**Research-grade-uncertainty flag.** `none`. The "kill-not-degrade" semantics are uncontroversial commodity once the mediator wraps the model-call surface; the only design content is which axes to count, and that is a manifest-schema concern, not a buildability concern.

**Buildability verdict.** `commodity`.

## P-03 Worktree isolation

**Contract restatement.** P-03 is the per-cycle filesystem-level isolation primitive that prevents concurrent cycles operating on the same source repository from silently overwriting each other. Contract: each cycle receives its own working copy of the repository, rooted at a path the cycle's P-01 closure binds in as `/work`; merges back to the canonical branch happen only through P-04 (PR creator), not through direct filesystem coordination. API surface: `create(repo-url, base-ref) → worktree-path`; `destroy(worktree-path)`. Partition enforced: cycles cannot read or write each other's worktrees (mount-namespace + filesystem-permission boundary, enforced by P-01).

**Construction path.** `git worktree add ../cycle-<id> <base-ref>` creates an isolated checkout sharing the repository's object database (cheap; no full clone per cycle) but with an independent working tree and `HEAD` — the `git worktree` command's `--detach` flag plus a per-cycle ref namespace (`refs/cycle/<id>/...`) gives each cycle a stable starting point that survives parallel sibling cycles. The worktree path is bound into the P-01 closure as `/work` (`bwrap --bind /var/lib/factory/worktrees/<id> /work`), so the agent inside the cycle sees only its own copy. Destruction is `git worktree remove --force ../cycle-<id>` after the cycle commits or aborts.

**Corpus-why citation.** [F17 (parallel agents on shared dirs lose data)](../failure-modes-v3.md#f17--parallel-agents-on-shared-dirs-lose-data) is the named failure mode with greenfield-severity **high** and brownfield-severity **high**: "filesystem is the coordination medium; no built-in concurrency control." [BF-M §2.5](../tracks/brownfield-methodology-first.md#25-failure-mode-coverage-severity-by-stage) assigns the mitigation to stage 5 as "per-cycle isolated worktree." High-parallelism architectures (Compound, Symphony per [archive synthesis §4](../../archive/synthesis-v1-v2/00-synthesis.md)) rely on this primitive existing for their composition story to hold.

**Research-grade-uncertainty flag.** `none`. `git worktree` is a 2017-vintage core-git feature with widely-deployed production use.

**Buildability verdict.** `commodity`.

## P-04 PR creator

**Contract restatement.** P-04 is the authenticated egress primitive that publishes a cycle's output: a branch push to the forge plus an opened pull request whose body bundles the cycle's structured metadata (per [BF-M stage 8](../tracks/brownfield-methodology-first.md): change-intent block + archaeological brief + trajectory pointer + acceptance verdict). Contract: idempotent on the cycle-id (re-runs do not create duplicate PRs); structured-metadata block in the PR body is machine-readable for re-entry per the cognitive-escrow methodology layer (DEC-2); F14 attribution data (per-agent / per-model authorship) is required in commit messages. API surface: `open(worktree-path, cycle-manifest) → pr-url`; the implementation handles authentication, branch naming, and metadata templating.

**Construction path.** The GitHub CLI (`gh pr create --base main --head cycle-<id> --title ... --body-file pr-body.md`) authenticates via a short-lived per-cycle GitHub App installation token (issued by `actions/create-github-app-token` or equivalent) and creates the PR in one call — the `--body-file` flag lets the cycle generate the structured-metadata block separately from the title, and `gh` returns the PR URL on stdout for trajectory capture. The branch push that precedes it is `git push origin refs/cycle/<id>:refs/heads/cycle-<id>`. Idempotency is enforced by checking `gh pr list --head cycle-<id> --json url` before opening; on collision the existing PR is updated via `gh pr edit --body-file pr-body.md`. For non-GitHub forges, `glab` (GitLab) or `tea` (Gitea) follow the same shape; the abstraction is one `forge.open_pr(...)` function call.

**Corpus-why citation.** [BF-M stage 8 ("Ship-or-escalate")](../tracks/brownfield-methodology-first.md) names the PR creator as the cycle's terminal substrate primitive and ties it to [F14 (attribution)](../failure-modes-v3.md) per the Phase-1 bias-guard widening (CANDIDATE-10): "Without per-agent / per-model attribution, downstream reliability cannot be diagnosed back to a cause." Stage-8's PR-body bundle is [BF-M's F42 (cognitive escrow) mitigation surface](../tracks/brownfield-methodology-first.md#25-failure-mode-coverage-severity-by-stage): "Re-entry surface designed (PR body bundles change-intent + brief + trajectory pointer + failed line)." Without P-04 as a typed primitive, structured metadata becomes an operator-formatting convention, which F53 (voluntary-discipline fragility) marks as a known failure mode.

**Research-grade-uncertainty flag.** `none`. `gh pr create` + GitHub App tokens is well-trodden CI/CD practice.

**Buildability verdict.** `commodity`.

## Cluster coda

All four C1 primitives share a single deployment substrate (a containerized CI runner or equivalent cloud-VM host with kernel-namespace support) and a single binding discipline: **deny-by-default at the boundary, substrate-enforced not operator-voluntary** (F53 mitigation as a cross-primitive invariant). P-01 enforces this for execution, P-02 for resource consumption, P-03 for filesystem state, P-04 for egress. The cluster's commodity verdict reflects that all four primitives have widely-deployed off-the-shelf realizations whose APIs map directly onto the contracts above.
