# agent instruction

**Seam adversary verifies producer-against-consumer field-by-field, not only consumer-against-contract.** A field-level seam review MUST compare the producer's emitted payload against each consumer's declared inbound schema directly, field name by field name — not merely check each side against the frozen contract. Producer and consumer payloads authored by separate parallel subagents drift on field names, traceability keys, and enum sets even when each side is internally correct and cites the same contract.

*Grounded in: the correction-request seam — C52 (producer), C08 + C30 (consumers) each internally correct but three divergent schemas; the frozen records they all cited were clean.*

# justification

The seam adversary this session was briefed to verify the two frozen records (`ScoreRecord`, `DiagnosisRecord`) against their consumers — and they were clean, because they were lead-frozen. But the adversary's one real finding was a contract that had *no single owner*: the correction request flows C52 (producer) → C08 + C30 (consumers), and each component authored its own end of it. All three were internally coherent and all three cited the same triangle decisions, yet the producer emitted `{diagnosis_ref, defect_summary, …}`, C08 expected `{factory_build_ref, defect_detail, requested_by, …}`, and C30 expected `{factory_build_ref, rationale, correction_mode, …}` — three names for the rationale field, two different traceability keys, and a `requested_by` field the producer never populated despite both consumers needing it for the worker-origin rejection. A consumer-against-contract check would have passed each side; only a producer-against-consumer field-by-field diff surfaced it. This is the exact class of the prior run's `satisfaction_score`-vs-`score_value` blocker. The marginal cost is one extra column in the adversary's verification table (producer field → consumer field); the cost of skipping it is a build-time integration break discovered only when the payloads are wired together.
