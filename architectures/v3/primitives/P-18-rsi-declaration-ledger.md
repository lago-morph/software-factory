# P-18 — RSI-Declaration Ledger

**Claimed by:** [GF-C](../tracks/greenfield-cold-start-first.md) §1.1 (fifth day-0 primitive).
**Dispatch tier:** per-primitive.
**Buildability verdict:** **designed-system** (storage substrate is commodity; the typed declaration schema and the immutable-append + board-report-derivation contract are the load-bearing design content).
**Research-grade-uncertainty flag:** none.

## Contract restatement

RSI = **Recursive Self-Improvement**, per Kahana's three-part test ([`31-caremark-rsi-board-exposure`](../../../research/31-caremark-rsi-board-exposure.md) §1): a deployment counts as RSI if it exhibits (1) durable self-modification, (2) compounding capability across cycles, and (3) limited human gating. The RSI-Declaration Ledger is the day-0 typed, append-only, signed log in which the factory commits in writing to whether it intends to satisfy that test at steady-state and, if so, records every artifact a Caremark-prong-1 board report would later need to demonstrate the three AILCCP controls (Human Approval Gate / sandboxing / immutable logging) are *actually running* rather than *merely scaffolded*. Records logged: the initial RSI declaration with operator signature; per-cycle AILCCP-control attestations (control name, status, evidence pointer); Human-Approval-Gate exercise events; board-report renderings and acknowledgements; SB-53-reportability classifications; declaration amendments (each a new append, never an overwrite). Queries answered: current RSI status, last-attestation time per control, per-cycle running-controls audit, board-report payload for a period, and full declaration revision history.

## Construction path

**Named tool: SQLite in WAL mode with a `BEFORE UPDATE`/`BEFORE DELETE` trigger that raises `RAISE(ABORT, ...)`, fronted by a small typed-record API that serialises each entry as a content-addressed JSON blob whose hash is chained Merkle-style to the prior entry's hash.** Integration sentence: SQLite's WAL mode gives crash-safe single-writer append throughput sufficient for board-reporting cadence (entries per cycle, not per token); the abort-on-mutation triggers realise the substrate-enforced append-only contract (per F53 voluntary-discipline-fragility: the discipline must be in the storage layer, not in the calling agent's good behaviour); and the chained content-hash field on each row turns the table into a tamper-evident log whose root hash can be co-signed at board-report rendering time, satisfying BCG's "complete, versioned audit trail" property ([`followup/10-governance`](../../../research/followup/10-governance.md) §1.1) without standing up an EventStoreDB-class component. The board-report rendering is a deterministic read query over rows filtered by `kind in {declaration, attestation, gate-exercise, report-emit}` within a time window, projected through a fixed template — no LLM in the path. Co-existing prior art: Git's object store (content-addressed append-only); Certificate Transparency logs (RFC 6962, Merkle-chained append-only with public auditability) — both are the same pattern at different scales.

## Corpus-why citation

GF-C §1.1 primitive 5 anchors the ledger directly on Kahana ([`31-caremark-rsi-board-exposure`](../../../research/31-caremark-rsi-board-exposure.md) §1 three-part RSI test) and BCG's "auditability by design" ([`followup/10-governance`](../../../research/followup/10-governance.md) §1.1 verbatim: "the factory produces a complete, versioned audit trail… For regulated industries, the Dark Software Factory does not make compliance harder, it makes it structurally easier"). The corpus-specific problem the ledger solves is the regulator's critique GF-C §1.1 names explicitly: the AILCCP three controls commonly *exist as scaffolding* but cannot be shown to be *actually running* on the cycle being audited, so the Caremark prong-1 board-reporting question cannot be honestly answered. The ledger closes that gap by making per-cycle control attestation a structurally required append, not a retrospective reconstruction. Mitigates **F43** (RSI Board-Visibility Gap — direct, day-0 structural closure); contributes to **F54** (goal subversion across cycles, via immutable record of declared objective) and **F55** (behavioural drift, via durable human-grounded declaration the agent cannot rewrite); spans the F58 runtime/design-time split because both attestation kinds chain into the same log.
