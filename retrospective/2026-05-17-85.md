## Part 1 — what happened

### Phase 1 — Tail of the dedup work (PRs #75-#78)

The session opened with the user asking me to consolidate two dedup files (PR #75) that I'd created in a confused branch sequence prior. PR #76 added the auto-✅ marking for referenced singletons + deleted the arxiv v1 duplicate. PR #77 built a single-page HTML UI for the user to triage remaining undecided rows — the user's feedback ("structure your output as bash I can paste back") turned the output from a human-readable description into a runnable script in PR #77 itself. PR #78 was the 404 analysis: 8 rows were clear duplicates of working content elsewhere, deleted. Significant finding: 2 of the rows the user wanted deleted whole had legitimate primary files I needed to *keep* and only delete the JS-shell HTML companion. Almost lost 1.8MB of substantive content; caught at execution time by reading the file metadata before the delete.

### Phase 2 — The big catalog design conversation

The user's pivot: "we are going to do this in the other direction. Let's come up with a canonical way to keep track of our sources." What followed was an extended design conversation that produced the schema, the scripts list, the workflow structure, the SKILL.md decision tree, the test plan — all before any code was written. Key design choices established: sha256(canonical_url)[:10] as ID, `pointer_to` for redirects, single sources.json with sort-by-id discipline, jq-driven edits with mandatory normalize-and-sort, filesystem placement IS source identity, config embedded in SKILL.md (no two-file drift), self-syncing workflow installer pattern.

### Phase 3 — Build PR #79 (the infrastructure)

15 scripts, 124 tests, 18 resource docs, 3 workflow templates, schema, SKILL.md rewrite. Five checkpoints, ~26 files. Tests caught real bugs as I wrote them: substack tracking params not lowercased correctly (one-line fix), validate-config returning exit 2 for warnings broke lint-sources.sh (warnings should be 0). Both fixed before merge. Used parallel subagent fanout for the 18 resource docs (each one written by me sequentially though — used parallel for the indexing pass in PRs #79's predecessors only).

## Part 4 — proposed ADRs

These are binding architectural choices made during the session. Titles only — author with the `adr` skill if you decide to record them.

- **Catalog ID derivation: sha256(canonical_url)[:10]** — single, derived, never invented. Drives every record's identity and prevents the filename↔content drift that produced the Frankenstein files in earlier sessions.
- **Catalog is intentional, not exhaustive** — auto-extracting every URL from research reports as "wanted" records is anti-pattern. Catalog reflects deliberate decisions to track; rejected sources go to `MIGRATION-EXCEPTIONS.md` + match a config pattern.
- **Single source of truth for category taxonomy** — `reference-only/categories.json` is canonical; scripts read it at runtime; schema doesn't constrain `tags` enum.
- **Filesystem placement IS source identity** — files in `reference-only/<id>/` don't need URL extraction; the directory location substitutes for content-based identity.
- **Reports link to source directories, not files** — durable across file changes (partial → full); exception is markdown-embedded images.
- **Skill self-bootstrapping** — every file a skill depends on is either in the skill directory OR auto-generated by the skill on first run; user copies the skill and setup is automatic.
- **Tickle-file pattern for manual workflow triggers** — for any GitHub Action that needs both auto + manual triggers, path-filtered workflow_dispatch + a tickle file whose existence triggers the workflow + workflow deletes the tickle in its commit.
- **PRs branch off the feature branch when work depends on unmerged work** — stacked-PR pattern via cross-branch targeting + GitHub's auto-base-update on parent merge.
- **AGENTS.md + CLAUDE.md pattern for cross-tool agent directives** — AGENTS.md is the OpenAI-Codex-compatible canonical; CLAUDE.md is the 2-line Claude Code loader that points at it; harness-level overrides live in AGENTS.md so they survive sessions.
- **Mechanical recovery is autonomous, judgment recovery is prompted** — for deterministic recoverable operations (regenerate-from-template), do them without asking. Reserve user prompts for irreversible or judgment calls.
