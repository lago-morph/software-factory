## §1 Primitive list (buildability-confirmed)

U-A requires 5 substrate primitives, all anchored to the typed-node-graph methodology. Per the [primitive index post-sketch annotations](../primitives/index.md#u-a), four of the five (P-28, P-29, P-19, P-30) are *contested* in the sense that other unified-attempt candidates name variants of them; the construction substrate is shared and each variant ships its own envelope / DSL / state-machine schema. Same-vs-distinct verdicts are deferred to Wave 4.2 per the [scoping principle](../phase-3.4-decisions-resolved.md#scoping-principle-immutable-overrides-any-conflicting-framing-in-the-integration-brief).

- **[P-28 — Typed-object store (content-addressed, append-only)](../primitives/P-28-typed-object-store.md).** The interval object store: every cycle node is a durable, content-addressed `EscrowInterval` record. Trajectory capture (D-7) is the inside-the-interval event stream; the envelope is its substrate handle. Verdict: `designed-system` (per-variant envelope schema is the design content).
- **[P-29 — Policy mediator (declarative gates)](../primitives/P-29-policy-mediator.md).** Reads the `policies` block from each interval at open / close time, fires gate / log / sandbox / approval-gate / reflection-trigger / judge-diversity rules in order, refuses to close the interval unless every declared policy slot has a satisfying upstream record. Substrate, not methodology. Verdict: `designed-system`.
- **[P-19 — Eligibility / regime classifier](../primitives/P-19-eligibility-regime-classifier.md).** Decides `automation-eligibility` ∈ {lights-out, sample-audit, escalate, human-required} and `work-unit-class` per interval at open time. Substrate-typed; the classifier's decision is itself a logged typed event. Verdict: `designed-system`.
- **[P-14 — Judge router (multi-shape typed)](../primitives/P-14-judge-router.md).** Routes interval-fired judge calls to same-model / different-role / different-family per the interval's `policies.judge-diversity` field. Default: cross-family judge mandatory at any interval with stakes ≥ "modifies state outside sandbox" (F46 mitigation). Verdict: `designed-system`.
- **[P-30 — Re-entry / event registrar](../primitives/P-30-event-registrar.md).** Holds the typed event-state-machine for `EscrowInterval{kind: re-entry}` nodes: open / freeze / acknowledge / resume / redirect / close transitions, plus subscription surface for the AILCCP immutable log, the classifier, and the trajectory store. Substrate-typed; the registrar fires deterministically once policy thresholds (watchdog escalation per P-06; cost-ceiling per D-5; severity-class trigger) are met. Verdict: `designed-system`.

## §2 RG primitives

**U-A has no load-bearing RG primitive per the Phase-3.5.5 application table; all primitives are designed-system with viable construction paths.** U-A does not appear in the [Phase-3.5.5 RG-primitive application table](../candidate-registry.md#phase-355-rule-on-load-bearing-rg-primitives-binding-user-approved-2026-05-25) — no row exists for U-A because none of its five primitives lands a research-grade-uncertainty flag at Phase 3.5 close (per [P-28](../primitives/P-28-typed-object-store.md), [P-29](../primitives/P-29-policy-mediator.md), [P-19](../primitives/P-19-eligibility-regime-classifier.md), [P-14](../primitives/P-14-judge-router.md), [P-30](../primitives/P-30-event-registrar.md), each carries `none` on the RG-flag).

What U-A does carry, **accepted-open and not an RG primitive**: the **DPU-1 interval-granularity concern** (per [registry §U-A material findings](../candidate-registry.md#u-a--escrow-graph-factory)) — the process-state-node-per-cycle granularity produces many `EscrowInterval` objects per cycle and is the architecture's highest substrate cost at year-2 scale. This is buildability-orthogonal (the store, mediator, registrar are all buildable at any granularity); it is a cost-and-cognitive-load question the track itself surfaces in [§7 open question 1](../tracks/unified-A.md#7-open-questions-surfaced-by-this-track). Carries to Phase 8 as a lean-eval candidate (combined cost of immutable logging + cross-family judge + STIR reflection at high-parallelism interval graphs; [§7 OQ 6](../tracks/unified-A.md#7-open-questions-surfaced-by-this-track)), not as an RG-primitive flag and not as a Wave-4.5 authoring sub-track.

## §3 Candidate-specific contracts on each primitive

Per the [auto-004 Round 2 fixed sub-section headers](../decisions/auto-004-phase-4-dispatch-shape.md#wave-41-brief-shape-revised-per-reviewer-1-amendments), U-A's contested primitive references use the fixed schema below. Wave 4.2 reads these subsections diff-style against the other candidates' variants.

**envelope schema:** U-A's [P-28 typed-object store](../primitives/P-28-typed-object-store.md) variant is the **typed-node-graph envelope** (`EscrowInterval` schema per [unified-A.md §1 lines 47–68](../tracks/unified-A.md#1-architecture-sketch)). Fields: `id`, `kind` ∈ {bootstrap, refactor, regression-fix, spec-author, review, merge, deploy, dream, re-entry, archaeology, methodology-delta, …}, `pace-layer` ∈ {code, plans, specs, architecture, standards}, `priors.{out-of-tree[], in-tree[]}`, `policies.{gate, log, sandbox, approval-gate, reflection-trigger, judge-diversity}`, `classifier.{work-unit-class, automation-eligibility}`, `artefacts.{inputs[], outputs[], trajectory}`. Typed-filter primary axis: `kind` × `pace-layer` × `classifier.work-unit-class`. Differentiator from U-B's layer-typed envelope and U-C's anchor envelope is intentional and noted in the sketch; same-vs-distinct deferred to Wave 4.2.

**policy DSL:** U-A's [P-29 policy mediator](../primitives/P-29-policy-mediator.md) variant expresses each `EscrowInterval`'s declared `policies` block as a set of **closure conditions** in OPA Rego (Cedar is an alternate path). The Rego rules consume the interval envelope (read from P-28-U-A), the upstream judge-router verdict (from P-14), the sandbox-runtime attestation, and the reflection-trigger confirmation; the mediator refuses to close the interval unless every declared policy slot has a satisfying record. The policy-DSL design content is the **interval-policy schema** the Rego rules read (what counts as a satisfying record per slot; how `judge-diversity: different-family` is verified against P-14's recorded provider-family tag; how `approval-gate: required | sample | none` interacts with re-entry-registrar transitions). F28 (holdout leakage) is mitigated by binding the holdout/builder separation into the closure rule per [unified-A §4 D-4](../tracks/unified-A.md#4-4-defaults-accepted-vs-challenged).

**feature source:** U-A's [P-19 classifier](../primitives/P-19-eligibility-regime-classifier.md) variant's input feature vector is drawn from the **interval envelope's `kind`, `pace-layer`, and `priors` fields** at interval-open time, plus the substrate-current cross-family judge agreement on the interval-kind's recent history and the cost-ceiling current-state. Distinct from GF-S/S9 (work-unit class features), BF-L (Codebase-Model-typed code-region features), and U-C (distance tuple). The classifier emits `automation-eligibility` ∈ {lights-out, sample-audit, escalate, human-required} which the policy mediator (P-29) and re-entry registrar (P-30) both consume. Per [unified-A §5.4](../tracks/unified-A.md#54-day-0--day-n-trajectory), the classifier's day-0 default is `escalate` for every interval-kind until declared threshold-bars are measured; this is enforced as a substrate floor in the OPA post-check (not a methodology choice).

**state-machine semantics:** U-A's [P-30 re-entry registrar](../primitives/P-30-event-registrar.md) variant is the **re-entry interval state machine**: `in-flight → frozen → re-entry-open → operator-acknowledged → resumed | redirected | closed`. Transitions are driven by typed events from the policy mediator (P-29) when watchdog escalation (P-06 Daemon/Triage/Patrol), cost-ceiling breach (D-5), or severity-class trigger promotes an in-flight interval to `escalate`. The frozen-state snapshot captures the interval graph's in-flight position; the re-entry summary is derived from the trajectory store + AILCCP immutable log. Subscribers: the audit ledger, the classifier (re-classifies on resume), and the trajectory store. Differs from D7-U-1's survival-window registrar by being event-driven (operator decision) rather than timer-driven (window expiry); same-vs-distinct deferred to Wave 4.2.

P-14 (judge router) is not in the contested-fixed-header set per [auto-004 Round 2](../decisions/auto-004-phase-4-dispatch-shape.md#wave-41-brief-shape-revised-per-reviewer-1-amendments). U-A consumes P-14's default contract: the interval's `policies.judge-diversity` field is the router's shape parameter; cross-family is mandatory at high-stakes intervals; intra-family routing is a configuration option.

## §4 X_UNM_B articulation

Per the [X_UNM_B finding](../candidate-registry.md#u-a--escrow-graph-factory), this candidate addresses Codebase-Model acquisition from legacy artifacts as follows:

- **Source artifact:** the legacy codebase plus its prior-cycle artifacts (history, tests, runtime telemetry, AILCCP immutable-log entries if any exist). Per [unified-A §1 "Brownfield ingestion"](../tracks/unified-A.md#1-architecture-sketch), the brownfield entry-point is an `EscrowInterval{kind: archaeology, priors.in-tree: [codebase, history, traces, tests]}` whose job is to produce the populated downstream interval-graph. U-A reads these in-tree priors as the analogue of [P-26 CodebaseModel](../primitives/P-26-codebase-model.md)'s 6 views.
- **Extraction primitive:** **no dedicated extraction primitive named in the U-A track.** U-A's `kind: archaeology` interval is a *methodology-layer construct* — an interval-kind whose policies prescribe deep ingestion — but it does not name a substrate primitive that performs the structural / semantic / dependency / test-coverage / runtime / convention extractions P-26 enumerates. The track relies on the interval's `policies.gate` and `judge-diversity: different-family` to enforce extraction quality, not on a typed Codebase-Model store. Honest assessment: extraction is **methodology-layer-only** in U-A as authored; the substrate sees only the typed envelope produced *by* the archaeology interval, not the extraction process.
- **Completeness gap:** of [P-26's 6 views](../primitives/P-26-codebase-model.md), U-A as authored cannot reliably reconstruct the **conventional view** and the **invariant view** (the two views BF-L itself carries as research-grade-uncertainty per [registry §BF-L](../candidate-registry.md#bf-l--brownfield-legacy-ingestion-first-1)) — U-A inherits whatever ceiling BF-L's authoring sub-track produces, with no candidate-specific mitigation. Additionally, U-A's typed-node-graph envelope lacks first-class code-region typing (BF-L's per-region regime classification surface), so the **structural / semantic / dependency views** are reconstructable only at interval-grain, not at code-region-grain — a coarser resolution than BF-L's contract requires. Honestly: U-A's brownfield-fit claim per [§1 "How the same architecture serves both mandates"](../tracks/unified-A.md#1-architecture-sketch) does not deeply articulate this X_UNM_B obligation; the track frames brownfield-ingestion as "the archaeology interval feeds a populated change-request interval graph" without specifying how the population is rendered structural enough to drive subsequent intervals.
- **Fallback if missing:** U-A's methodology defaults the post-archaeology interval-graph's `classifier.automation-eligibility` to `escalate` (substrate floor; see §3 above) and requires `policies.judge-diversity: different-family` on every interval until the archaeology interval has been audited at a re-entry interval per [§5.4 day-N transition condition 2](../tracks/unified-A.md#54-day-0--day-n-trajectory). In effect: when extraction is incomplete, U-A degrades to operator-augmented mode (no lights-out) until the operator has confirmed the interval-class taxonomy. This is a *graceful-degradation pattern*, not a substrate-typed extraction repair; the track's X_UNM_B articulation depth is honestly shallow and is flagged in §5 as a Phase 5/6 methodology-spec carry.
