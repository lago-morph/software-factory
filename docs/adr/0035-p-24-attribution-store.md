# ADR 0035: P-24 attribution store

- **Status**: Accepted
- **Date**: 2026-05-25
- **Deciders**: lead agent (Phase 5 Wave 5.1b common-ADR fanout)

## Context

P-24 is the durable, append-only, signed change-history store that records *who* (human / agent / model) touched *which named symbol* in *which cycle* and produced *which diff*. Two candidates claim P-24: [BF-S/S-4 directly](../../architectures/v3/tracks/brownfield-substrate-first.md) (where it is a constitutive substrate primitive), and [BF-L via P-26](../../architectures/v3/tracks/brownfield-legacy-ingestion-first.md) (which composes P-24 as the *historical view* — one of the six views in the Codebase Model). Per the [Phase-4.2 overlap analysis](../../architectures/v3/primitives/overlap.md#coverage-tier-summary-phase-5-adr-priority-signal), P-24 is a 2-candidate primitive folded as a **common ADR** per [auto-005 Round 2](../../architectures/v3/decisions/auto-005-phase-5-dispatch-shape.md) — BF-L's historical view is "P-24 plus a query API" and does not add storage-layer design content separable from BF-S's substrate.

The forcing failure modes are clustered: [F14 (attribution collapse, brownfield-high)](../../architectures/v3/failure-modes-v3.md#f14--attribution-collapse) widened to forensic-reconstruction debt; [F32 (unsigned coordination)](../../architectures/v3/failure-modes-v3.md#f32--mail-injection--unsigned-coordination-messages); [F43 (RSI Board-Visibility Gap, brownfield-high)](../../architectures/v3/failure-modes-v3.md#f43--rsi-board-visibility-gap); [F54 (goal subversion across cycles, brownfield-critical)](../../architectures/v3/failure-modes-v3.md#f54--goal-subversion-rsi-prompt-injection-over-cycles); with secondary contributions to F35 and F58. Each requires per-cycle / per-agent / per-model attribution to be *structurally required* at the substrate layer, not best-effort at the calling-agent layer (which would be F53-fragile). The [P-24 buildability sketch](../../architectures/v3/primitives/P-24-attribution-store.md) verdicts the primitive `designed-system`: git plumbing is commodity, but the per-symbol-granularity uplift via P-22 and the dual-signing model for human vs. agent events is the load-bearing design content.

## Decision

**Build P-24 as a typed-object store on the P-08 content-addressed blob substrate, where each entry is an attribution envelope `(artifact_hash, agent_id, model_snapshot, cycle_id, signer_class, parent_artifact_hashes[], diff_slice, ts, signature_blob)` keyed by content-addressed `artifact_hash` and indexed by reverse-indexes on `agent_id`, `cycle_id`, and `model_snapshot`.** The envelope schema is versioned (`envelope_schema_version` field; rolling migrations forbidden, additive only). Three signer classes attest disjoint facts: (1) `human_git` — `git commit -S` verified by `git verify-commit` at ingest; (2) `factory_agent` — Sigstore `cosign sign-blob --identity-token` against the agent's OIDC run-token (one identity per `(cycle_id, agent_role, model_snapshot)` triple); (3) `factory_root` — a long-lived factory key signs the chained hash over the projection table at board-report cadence per [F43](../../architectures/v3/failure-modes-v3.md#f43--rsi-board-visibility-gap). The append-only invariant is enforced at the substrate layer (writes are content-addressed; the projection is a write-once Postgres table with a trigger forbidding `UPDATE`/`DELETE`).

Per-symbol granularity (the contract restatement of the [P-24 sketch](../../architectures/v3/primitives/P-24-attribution-store.md#per-symbol-granularity-gap-the-design-content)) is achieved by an ingest worker that joins `git blame --line-porcelain` output against [P-22's symbol-range index](0017-p-22-polyglot-codebase-index.md) per commit, producing `attribution_events(symbol_id, artifact_hash, ...)` rows. Symbol renames cross-link via P-22's rename edges stored as `parent_artifact_hashes`. Queries served: `artifact_hash → envelope`; `(agent_id, time_window) → diffs`; `symbol_id → ordered history`; `verification_status → failing-signature set`. BF-L's [Codebase Model historical view](../../architectures/v3/primitives/P-26-codebase-model.md) consumes these queries; it does not own storage.

## Alternatives considered

**B. Git-blame as substitute (no separate attribution store).** Use the existing `git log` / `git blame` / `git verify-commit` surface directly; expose a query layer over the bare repository. *Why rejected:* git's per-commit author trailer captures only the `(human_name, email)` tuple — it has no schema slot for `agent_id`, `model_snapshot`, or `cycle_id`, and no notion of the `factory_agent` signer class with its OIDC-bound identity. Retrofitting these into git trailers is possible but produces a per-commit-message-parsed schema rather than a typed-object store with a versioned envelope; queries by `(agent_id, model_snapshot)` degrade to grep over commit messages. Critically, git's granularity is per-line / per-file, not per-symbol — closing the [F14 widening to forensic reconstruction](../../architectures/v3/failure-modes-v3.md#f14--attribution-collapse) requires the P-22 symbol-join the sketch describes, which is not a git-native operation. Git is retained *underneath* P-24 as the signed substrate for `human_git` events, not as a substitute for it.

**C. Per-artifact frontmatter (in-file attribution headers).** Each generated artifact carries a `<!-- attribution: agent=... model=... cycle=... -->` block; queries grep over the working tree. *Why rejected:* invasive (every artifact type — code, markdown, YAML, binary — needs its own frontmatter convention; binary artifacts cannot carry one at all), non-tamper-evident (anyone who can write the file can rewrite the header — [F53](../../architectures/v3/failure-modes-v3.md) voluntary-discipline failure), and orthogonal to the append-only invariant (deleting a file deletes its attribution). Frontmatter also has no query story for `(agent_id, time_window) → diffs` without a separate index — which is what P-24 already is, making frontmatter strictly redundant.

## Consequences

**Easier:** F14, F32, F43, and F54 mitigation become substrate-enforced rather than agent-discipline-dependent. The per-symbol granularity contract is uniform across BF-S and BF-L without either candidate inventing its own attribution storage. BF-L's historical view in [P-26 Codebase Model](../../architectures/v3/primitives/P-26-codebase-model.md) reduces to a query API over P-24 + churn-aggregation, keeping P-26's design content focused on the multi-view *integration* rather than storage.

**Harder:** P-24 has a hard dependency on [P-22's symbol-range index](0017-p-22-polyglot-codebase-index.md) and rename-edge emission; degrading P-22 to per-file degrades P-24 to per-file. Sigstore / cosign OIDC issuance for factory agents requires an identity-issuance discipline (one identity per `(cycle, agent-role, model-id)` triple) which is itself a per-deployment ops requirement. The factory-root chained-hash signing cadence (board-report frequency) needs key-rotation tooling.

**Explicitly NOT promising:** the upstream *semantics* of `cycle_id` and `agent_role` are not standardised here — BF-S's cycle is a knowledge-promotion cycle; BF-L's may be a maintenance-loop cycle. Both populate the same envelope field; the field is opaque to P-24. Phase-6 candidate-specific architecture-specs record per-candidate semantics.
